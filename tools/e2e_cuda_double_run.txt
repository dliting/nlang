# tools/e2e_cuda_double_run.txt — explicit list for the device
# double-run legs (spec D7, review I4). Consumed by run_e2e_tests.py's
# optional filter argument and driven by tools/gate_cuda_tree.sh.
#
# Two layers, per the D7 two-layer strategy:
#   1. the tensor-related subset — every op_tensor_*, stdlib_tensor_*
#      and op_device_* entry of manifest.txt — in FULL under
#      backend=cuda (same exit codes as the pinned-cpu suite);
#   2. a full-set SAMPLE of the control surface (file/io/net byte
#      buffers, strings, classes, enums, structs, exceptions,
#      containers, the debugger, concurrency) — the families whose
#      arrays must stay host-resident under an active device backend.
# The full 2100-entry suite is not double-run on the device: the
# subscript-heavy cases ride the per-element transfer cost and would
# push against the 3-minute per-test cap; the full-suite regression
# net stays with the cpu mode of the gate.
#
# One name per line; '#' comments. A name that keys no manifest entry
# fails the run (the runner validates the list), so a rename or
# removal in manifest.txt cannot silently shrink this net.
