# gate_tiers.txt -- tier definitions for the tiered gates
# (docs/dev/gate_tiering_design.md). One source of truth: consumed by
# tools/tier_coverage_check.py (coverage invariant) and referenced by
# tools/gate_tier.sh when it assembles each tier's e2e legs.
#
#   tier <leg-name> selector <regex over manifest test names>
#   claim <resource-name> <ctest entry>...
#
# The coverage invariant: every manifest row must be selected by at
# least one tier selector; a selector matching zero rows fails the
# guard. The full-manifest selectors (".") make today's tiers trivially
# complete — the guard exists so a future tier edit cannot silently
# orphan a test family.
#
# A claim line names a resource and the ctest entries that hold it
# (gate timing design D-11). tools/gate_tier.sh passes it as the ctest
# leg's --claim argument (gate.sh serializes whole legs against it), and
# emit-cmake turns it into RESOURCE_LOCK variables so the entries also
# serialize inside one parallel ctest process. The window-launching
# families (QApplication with a real GUI event loop) cannot run
# concurrently on one session, hence the nide-gui claim over the eight
# windowed QTest executables plus the deployment probe that launches a
# window per resolution class.
