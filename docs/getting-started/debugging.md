# 在 nide 中调试

nide 内置调试器：设断点、单步执行、查看调用栈与局部变量都可以在 IDE
里完成。调试会话由 `ndb --machine` 在后台驱动，语义与命令行 ndb 一致，
引擎侧的分层见 [VM 架构/调试支持](../vm-architecture/debugging.md)。

用下面的程序走一遍调试流程：

```nlang
import io;

int add(int a, int b) {
    return a + b;
}

int main() {
    int sum = 0;
    for (int i = 1; i <= 5; i = i + 1) {
        sum = add(sum, i);
    }
    io.print(sum);              // 15
    return 0;
}
```

输出 `15`，退出码 0。

### 启动与停止

1. 单击编辑器左侧装订线（或按 F9）在 `for` 所在行设断点，装订线出现
   红点。红点默认空心，调试会话确认该行与编译产物对应后变为实心。
2. 菜单 运行 → 启动调试（F5）：先构建，再启动会话；程序运行到第一个
   断点处暂停，输出窗口自动切到「调试」页，暂停行在编辑器中高亮，
   装订线出现红色箭头。
3. 再次按 F5 继续运行。`for` 的头部行是循环锚点——断点在每一轮迭代
   都会命中，这一点与 gdb 一致。头部行上的初始化、条件、步进三段
   锚点都计在同一个断点下，任一锚点到达都会暂停；条件在每次求值时
   命中，包括循环结束前的最后一次判断。
4. 菜单 运行 → 停止调试（Shift+F5）随时终止会话。停止是硬终止：
   死循环或停在原生调用中也能立即结束；关闭 nide 时同样会结束被调试
   进程。会话进行期间，构建与运行（Ctrl+F5）被禁用。

### 快捷键

| 动作 | 快捷键 |
|------|--------|
| 启动调试 / 继续 | F5 |
| 运行（不调试） | Ctrl+F5 |
| 停止调试 | Shift+F5 |
| 切换断点 | F9（装订线单击等效） |
| 单步跳过 | F10 |
| 单步进入 | F11 |
| 单步跳出 | Shift+F11 |

### 调试页

输出窗口的「调试」页集中显示会话信息：

- 会话状态（未在调试、已暂停、已退出……）；
- 「抛异常时中断」开关：勾选后，任何异常的抛出点都会暂停会话
  （对应 ndb 的 `catch on|off`）——抛出时栈尚未展开，调用栈与局部
  变量仍然完整；
- 调用栈树（# / 函数 / 位置）：单击某一帧即选中该帧，编辑器跳转到
  对应行并刷新局部变量；
- 局部变量树（名称 / 类型 / 值）：显示选中帧的全部局部变量。

程序输出与出错时的调用栈回溯显示在「运行输出」页。断点按文件路径
记忆，跨 nide 重启保留，文件重命名后自动跟随。

### 单步

- 单步跳过（F10）：执行完当前语句，停在下一语句——不进入被调函数；
- 单步进入（F11）：停在当前被调函数的第一条语句；
- 单步跳出（Shift+F11）：执行到当前函数返回，停在调用者的下一语句。

`while`/`for`/`do-while` 的锚点行在每一轮迭代都会命中断点与单步，
空循环体也能逐轮观察。

### v1 已知限制

- 调试会话没有标准输入：`io.readLine` 会抛出 `IOException`（可以用
  try/catch 捕获），不会静默挂起；
- 会话内不跟踪行号漂移：一次会话对应一份行号快照，会话中编辑或重新
  构建不受支持；下次启动调试会重新按最新源码解析；
- 停止调试是硬终止：进程直接结束，没有优雅展开（`finally` 不执行）；
- 原生代码内部不可中断，但进程始终可以被终止；
- 暂不支持条件断点、监视点、编辑并继续以及附加到已运行进程。

详见 → [VM 架构/调试支持](../vm-architecture/debugging.md)。
