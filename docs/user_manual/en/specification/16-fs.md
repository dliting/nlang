# 16. The fs Package

The `fs` package inspects and arranges filesystem names: type
predicates, file size, directory listing, directory creation,
removal and path composition. It never reads or writes
content — content belongs to the `io` package (chapter 15).
§16.1 fixes the package form; §16.2 defines path values and
`join`; §16.3 defines the operations; §16.4 fixes the error
model.

## 16.1 Package Form

`fs` is a standard library package (§12.4): `import fs;` brings
it into scope and every function is called through the package
qualifier (`fs.exists(p)`). The package name is single-segment
(§3.3). Its declarations are the standard library's `.n`
source; every function is a `native` function (§7.5).
Argument admission is the package rule of §15.1: every formal
is a `string`, so every argument must be a `string` expression.

Every `fs` function except `join` is a blocking native
function: it declares a blocking section (§11.1), so the
calling context parks and the carrier lock is released while
the call waits. `join` composes strings and does not block.

## 16.2 Names and Paths

A path argument is a host path in the platform's native form;
the `fs` package defines no path syntax of its own. Path
values are plain `string`s.

`fs.join(a, b)` appends the segment `b` to the path `a` and
returns the result in generic form: the separators are forward
slashes on every platform, and the result is a valid path
argument. A right segment that names an absolute path replaces
the left segment entirely; an empty right segment leaves a
trailing separator; an empty left segment yields the right
segment alone.

## 16.3 Directories and Metadata

- `fs.exists(p)`, `fs.isFile(p)` and `fs.isDirectory(p)` report
  whether `p` exists, is a regular file or is a directory. They
  never raise: a path that cannot be inspected — missing or
  inaccessible — answers `false`.
- `fs.size(p)` returns the byte size of the regular file at
  `p`. It raises `IOException` (§9.3) when `p` is not a regular
  file, when its size cannot be determined, or when the size
  exceeds the range of `int`.
- `fs.listFiles(dir)` returns the names of the regular files
  directly in the directory `dir` as a `List<string>`: the
  names carry no directory prefix, the listing is
  non-recursive, directories and other entries are excluded,
  and the names are sorted lexicographically. It raises
  `IOException` when `dir` cannot be opened or read.
- `fs.makeDirs(p)` creates every missing directory component of
  `p`; an existing directory is success. It raises
  `IOException` when a component cannot be created.
- `fs.remove(p)` removes the file or the empty directory at
  `p`. A missing path is a silent no-op. It raises
  `IOException` when the entry exists but cannot be removed.

## 16.4 Error Behavior

Every `fs` failure that raises raises `IOException` (§9.3):
the raised sites are the size, listing, creation and removal
failures of §16.3. The three predicates never raise, and
`remove` treats a missing path as success rather than a
failure.

> Implementation note. On Windows the shipped command-line
> tools declare Unicode Transformation Format (UTF-8) as the
> process active code page in their embedded manifest, so
> non-American Standard Code for Information Interchange (ASCII)
> paths round-trip; a host that runs the VM under the system
> code page is bound by that code page.
