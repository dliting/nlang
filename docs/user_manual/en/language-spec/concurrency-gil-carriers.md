# The GIL and Multiple Carriers

## What this means for your program

Multiple carriers pay off in several situations: the program spends time inside **blocking native calls** (file and network input/output, where one task's wait overlaps another task's work); in **pure-compute segments** — code that only reads and writes local variables (arithmetic, comparisons, branches, local assignments) executes concurrently across carriers; or in **object-dense** code — object construction and field reads and writes take no lock, while containers, strings, streams, and synchronization primitives each hold their own domain lock, so only same-domain operations exclude each other and different domains overlap. Once an object is shared across carriers (through `spawn` arguments or a channel), concurrent reads and writes of its fields are a data race: a transitional value may be read, but memory is never corrupted; coordinate shared mutable state with a `Mutex`. The defaults therefore stay conservative: the embedding library runs a single carrier, and `nvm` uses at most four. Leave the carrier count alone unless measurement shows a benefit.

## How it works

Storage protection is split by **domain**: heap and string **allocation** draws from per-carrier free lists with no lock; object **field reads and writes** take no lock; **containers** (List/Dict), **synchronization primitives** (the mutex/channel side tables), **streams**, and **string maintenance** (concatenation flattening, constant-cache fills) each hold one domain lock — same-domain operations serialize, different domains run in parallel. Instruction segments that touch only frame-local state (constant loads, local assignment, arithmetic, comparison, branching) are equally lock-free, so several carriers can each run a virtual thread at the same time. The domain locks guarantee that the internal structure of a container or string is never torn by concurrency; concurrent field reads and writes of a shared object are a data race — a transitional value may be read, but memory is never corrupted; coordinate shared mutable state with a `Mutex`. Context switches happen only at safepoints (function entry and loop back edges), bounded by a scheduler budget of about 1000 back edges per turn.

Garbage collection also stops the world at these safepoints: every executing thread reaches one, the last to arrive runs the collection, and execution then resumes. Programs cannot observe the pause.

A **carrier** is an operating system thread that runs virtual threads. The library defaults to a single carrier; embedding hosts opt in with `VmExecutor::SetCarrierThreadCount`, and `nvm` defaults to at most four (`--carriers=N`, 1..64). Multi-carrier parallelism comes from several kinds of window: a native call that declared a blocking section under version 5 of the native application binary interface (ABI) — the carrier parks and drops its locks for the duration, so other carriers run other virtual threads; a direct native call that touches no shared storage (under the ABI such natives must not wait); and the pure-compute and lock-free store segments themselves (described above). Host-registered callbacks always run through the blocking protocol, so their waits occupy no carrier.

Determinism in tiers: under a single carrier, the same program with the same input produces the same interleaving (FIFO queue plus a fixed back-edge budget). With multiple carriers, dequeuing applies **wake affinity** — a carrier scans a constant window at the head of the queue and prefers the context it last ran itself (a never-dispatched context counts as matching any carrier); if the window holds no match, the head dispatches. Affinity reorders which entry dispatches, for execution locality only, so the scheduling order is unspecified and changing the carrier count changes the interleaving; program correctness never rests on the interleaving — only on the `join`, channel, and mutex happens-before edges. Multi-carrier tests assert results after synchronization, never interleaving or durations. `sleep` is a scheduling hint with a lower bound: once every carrier is parked, a sleeper wakes within the operating system's timer granularity (about 15.6 ms on Windows). A paused debugger no longer holds the GIL: a freeze gate blocks new dispatches while the stop lasts, and each in-flight segment stops once it finishes (see [Known limitations](known-limitations.md)).
