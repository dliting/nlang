# 在nide中调试

nide内置调试器：设断点、单步执行、查看上下文列表、调用栈与局部变量都可以在集成开发环境（IDE，integrated development environment）里完成。调试会话由`ndb --machine`在后台驱动，语义与[命令行ndb](../cli-tools/ndb.md)一致，引擎侧的分层见[VM架构/调试支持](../vm-architecture/debugging.md)。

用下面的程序走一遍调试流程：

```nlang
import io;

int add(int a, int b) {
    return a + b;
}

int main() {
    int sum = 0;
    for (int i = 1; i <= 5; i = i + 1) {
        sum = add(sum, i);
    }
    io.print(sum);              // 15
    return 0;
}
```

输出`15`，退出码0。

### 启动与停止

1. 单击编辑器左侧装订线（或按F9）在`for`所在行设断点，装订线出现红点。红点默认空心，调试会话确认该行与编译产物对应后变为实心。
2. 菜单运行 → 启动调试（F5）：先构建，再启动会话；程序运行到第一个断点处暂停，输出窗口自动切到「调试」页，暂停行在编辑器中高亮，装订线出现红色箭头。
3. 再次按F5继续运行。`for`的头部行是循环锚点——断点在每一轮迭代都会命中，这一点与gdb一致。头部行上的初始化、条件、步进三段锚点都计在同一个断点下，任一锚点到达都会暂停；条件在每次求值时命中，包括循环结束前的最后一次判断。
4. 菜单运行 → 停止调试（Shift+F5）随时终止会话。停止是硬终止：死循环或停在native调用中也能立即结束；关闭nide时同样会结束被调试进程。会话进行期间，构建与运行（Ctrl+F5）被禁用。

### 快捷键

| 动作 | 快捷键 |
|------|--------|
| 启动调试（继续） | F5 |
| 运行 → 开始运行（不调试） | Ctrl+F5 |
| 停止调试 | Shift+F5 |
| 切换断点 | F9（装订线单击等效） |
| 单步跳过 | F10 |
| 单步进入 | F11 |
| 单步跳出 | Shift+F11 |

### 调试页

输出窗口的「调试」页集中显示会话信息：

- 会话状态（未在调试、已暂停、已退出……）；
- 「抛异常时中断」开关：勾选后，任何异常的抛出点都会暂停会话（对应ndb的`catch on|off`）——抛出时栈尚未展开，调用栈与局部变量仍然完整；
- 上下文树（上下文 / 状态 / 位置）：调试中的每个并发上下文各占一行——编号、调度状态（被某个载体的执行窗口持有时带`@载体`后缀）、最内层帧位置；单击行即选中该上下文，语义见[多上下文调试](#多上下文调试)；
- 调用栈树（# / 函数 / 位置）：单击某一帧即选中该帧，编辑器跳转到对应行并刷新局部变量；
- 局部变量树（名称 / 类型 / 值）：显示当前检查的上下文中所选帧的局部变量，只列出声明位置已被执行经过的——停驻语句到达某变量的声明行（含该行本身）后它才进入显示（恰停在声明行上时显示默认零值，直到初始化器运行），声明在更后面行的变量保持隐藏；方法帧中接收者以`this`显示，展开一层（即其字段）。

程序输出与出错时的调用栈回溯显示在「终端」页——回溯帧形如`at <函数> (<源文件>:<行>)`，行号来自语句锚点；导入单元的帧显示其编译机的绝对路径。断点按文件路径记忆，跨nide重启保留，文件重命名后自动跟随。

程序的标准输入同样在「终端」页里完成：调试期间终端切换为本地行编辑——待输入行的行首显示`> `提示符（IDE本地绘制），输入一行并回车后，整行连同提示符回显到终端历史，再交给被调试进程；回显与行编辑是IDE本地合成的，不是系统控制台语义（Ctrl+C不会被注入为中断信号，有选区时仍是复制）；上/下方向键调出会话内最近输入过的行（至多50条）。中文经输入法（IME，input method）输入，预编辑串跟随终端光标。

### 单步

- 单步跳过（F10）：执行完当前语句，停在下一语句——不进入被调函数；
- 单步进入（F11）：停在当前被调函数的第一条语句；
- 单步跳出（Shift+F11）：执行到当前函数返回，停在调用者的下一语句。

单步作用于上下文树中选中的上下文（未做过选择时即停机上下文），详见[多上下文调试](#多上下文调试)。

`while`/`for`/`do-while`的锚点行在每一轮迭代都会命中断点与单步，空循环体也能逐轮观察。

### 多上下文调试

`thread.spawn`派生的并发上下文与main并列在上下文树里，任何上下文命中断点或抛异常都会全停。单击上下文行＝同时选择查看对象与单步目标（与主流IDE一致的语义）：

- 调用栈与局部变量立即切换为该上下文的内容，编辑器跳转到其最内层帧位置——停泊中的上下文（如等待通道接收）照常可查；
- 随后的单步跳过/进入/跳出都作用于该上下文：选中正在排队的上下文，单步停在它的下一语句锚点；选中停泊中的上下文，单步放行其他上下文推进，被选上下文等到数据唤醒后停在它的下一语句；
- 选中永不唤醒的停泊上下文再单步，死锁检测照常报错——单步不是绕过死锁的手段；
- 每次新的停机把选择自动重定向到停机上下文，避免树中标记与实际停机错位。

单上下文程序里上下文树只有main一行，单击它与不单击没有区别；未做过选择时，单步一直以停机上下文为目标。

### 剥离调试信息（`--no-debug-info`）

`ncc`默认在每条语句前发射调试锚点（携带源码行号）——回溯行号、断点绑定与语句级单步都建立在锚点之上。`ncc build --no-debug-info`产出不含锚点的模块：产物更小，但回溯失去行号（帧显示`(文件:?)`）、断点无法绑定、也没有语句级单步；`ndb`装载这类模块时打警告。`sourceFile`等其余元数据保留——函数名与源文件路径仍出现在回溯里。

### 已知限制

- 会话内不跟踪行号漂移：一次会话对应一份行号快照，会话中编辑或重新构建不受支持；下次启动调试会重新按最新源码解析；
- 停止调试是硬终止：进程直接结束，没有优雅展开（`finally`不执行）；
- native代码内部不可中断，但进程始终可以被终止；
- 暂不支持条件断点、监视点、编辑并继续以及附加到已运行进程。
