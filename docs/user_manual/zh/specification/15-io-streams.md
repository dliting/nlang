# 15. io包与流

`io`包提供控制台输出、控制台输入与整文件内容搬运。流类`ByteStream`与`FileStream`提供值、结构体与类图的二进制序列化。§15.1固定包形态以及管辖每一次包调用的实参准入规则；§15.2–§15.4定义io函数；§15.5定义流类；§15.6固定流值的字节级编码。

## 15.1 包形态

`io`是标准库包（§12.4）：`import io;`把它带入作用域，每个函数都经包限定符调用（`io.print(s)`）。包名是单段的（§3.3）。它的声明是标准库的`.n`源码；输出三函数、输入函数与文件函数是`native`函数（§7.5），而带类型的读取器是建立在`readToken`与字符串转换方法（§13.3）之上的NLang源码包装。

**实参准入。** 对包函数的调用把每个实参对照声明的形参类型绑定（§7.3）；§4.12到`string`的隐式转换不适用于包实参。包函数的`string`形参只接受`string`实参；任何其他类型都是编译期错误。对用户声明的函数的调用保持§4.12的关系：在`emit`声明一个`string`参数处，`emit(42)`能编译，但`io.writeFile(42, "x")`不能。

例外是输出三函数`io.print`、`io.write`与`io.eprint`（§15.2）。这三者额外接受渲染为文本的实参（§5.3）：标量基本类型、数组与函数值。类、接口或枚举值被拒绝——类或接口值要先调用`.toString()`（§13.2），枚举变量同样如此；枚举成员常量被接受，打印其成员名（§5.3）。结构体值被直接拒绝：结构体没有`toString`（§13.2）。`null`实参被拒绝：它会打印成`0`。该例外以`io`包路径下的这三个名字为键；遮蔽`io`的用户包恰在这些名字上继承它。

## 15.2 控制台输出

- `io.print(s)`把`s`的文本写入标准输出，随后跟一个换行。
- `io.write(s)`把`s`的文本写入标准输出，不带尾随换行。
- `io.eprint(s)`把`s`的文本写入标准错误，随后跟一个换行。

每个函数按§15.1的三函数准入接受一个实参；非字符串实参在写入之前按§5.3与§13.2渲染为文本。目的地是宿主的输出通道；宿主写入失败的效果是*未指明*的。

## 15.3 控制台输入

输入函数经一个共享游标读取程序的标准输入：行读取、记号读取与码点读取在同一位置上交错，游标恰好按一次调用所消耗的内容前进。每个输入函数都是阻塞的原生函数：它声明阻塞段（§11.1），所以在调用等待期间调用上下文停泊、载体锁被释放。

- `io.hasInput()`在仍有输入可读时返回`true`，在输入结束时返回`false`。它从不抛出。没有输入通道时，它返回`true`，直到某次读取抛出`IOException`。
- `io.readLine()`返回不含行终止符的下一行；尾随的回车被剥去。在输入结束时它返回`""`：空行与输入结束无法由返回值区分，`hasInput()`把两者分开。没有输入通道时它抛出`IOException`（§9.3）。
- `io.readToken()`返回下一个以空白分隔的记号。在输入结束时它抛出`IOException`；没有输入通道时同样。
- `io.readChar()`返回下一个非空白码点，从输入的Unicode转换格式（UTF-8）字节解码而来；前导空白被跳过，与`readToken`相同。在输入结束时它抛出`IOException`；没有输入通道时同样。不是有效UTF-8的字节序列抛出`Exception`（§9.3），而非`IOException`。
- `io.readInt()`、`io.readLong()`、`io.readFloat()`、`io.readDouble()`与`io.readBool()`读取下一个记号，并用对应的字符串方法转换它（§13.3）：输入结束抛出`IOException`（来自`readToken`），格式不当的记号以与该字符串方法完全相同的方式失败。

> 实现注记。当程序为输入而阻塞、且标准输入与标准输出都是控制台时，宿主在等待之前打印一个`"> "`提示符；该提示符不是语言的一部分。

## 15.4 文件内容IO

- `io.readFile(path)`把`path`处文件的完整内容以字节的`string`返回（§4.4）。当文件无法打开、其大小无法确定、大小超过16 MiB，或读取中途失败时，它抛出`IOException`（§9.3）。
- `io.writeFile(path, content)`创建文件，或截断已存在的文件，并写入`content`；`io.appendFile(path, content)`在需要时创建文件并追加`content`。两者在文件无法打开或无法写入时抛出`IOException`。

`path`是平台原生形态的宿主路径；io包不定义自己的路径语法（第16章的`fs`包定义）。内容是字节：io函数不对其读写的内容强加任何文本编码。

## 15.5 ByteStream与FileStream

`ByteStream`与`FileStream`是内建句柄类（§13.1）：`ByteStream`读写内存缓冲，`FileStream`读写磁盘文件。`ByteStream()`构造一个空缓冲。`FileStream(path, mode)`打开文件：模式`"w"`创建或截断，`"a"`创建或追加，`"r"`只以读方式打开。未赋值的流句柄为null；经由null句柄的方法调用抛出`NullPointerException`（§9.3）。其他一切流失败都是*宿主级*执行期错误（§9.1）：没有`catch`子句处理它，程序结束。失败位点有：无效模式、打开失败（包括对缺失文件用`"r"`）、经由已关闭或无效句柄的访问、对只读流的写入或对只写流的读取、越过流末的读取、命名了程序未声明的类型的结构体或对象读取，以及由`writeStruct`或`writeObject`写出的、带数组或函数类型字段的结构体或类值。

方法面除注明处外完全相同：

| 方法 | 效果 |
| --- | --- |
| `writeInt(x)` / `readInt() → int` | 4字节整数 |
| `writeFloat(x)` / `readFloat() → float` | 4字节浮点数 |
| `writeLong(x)` / `readLong() → long` | 8字节整数 |
| `writeDouble(x)` / `readDouble() → double` | 8字节浮点数 |
| `writeString(s)` / `readString() → string` | 4字节长度，随后是各字节 |
| `writeStruct(v)` / `readStruct(name)` | 结构体各字段的递归写出；读取以字符串命名类型，产出该类型的值 |
| `writeObject(c)` / `readObject(name)` | 类图的递归写出；读取以字符串命名类型，产出该类型的值 |
| `length() → int` | 流的总字节数 |
| `position() → int` | 当前游标 |
| `reset()` | 把游标回到0并清除对象身份状态；缓冲保留（仅`ByteStream`） |
| `close()` | 释放缓冲或文件句柄；句柄变为无效 |

标量写方法按宽度准入实参。8字节写入器接受§4.12能隐式赋值到其槽类型的任何值：`int`进入`writeLong`，`float`或整数进入`writeDouble`，转换在调用点施加。4字节写入器要求精确：`writeInt`接受至多32位的整数，`writeFloat`恰好接受一个`float`。被拒绝的实参是编译期错误，给数值方法传`char`或`string`实参也是编译期错误。

读取按写出顺序消耗流；越过流末的读取抛出宿主级错误而非产出值。由`writeObject`写出的`null`类引用读回为`null`。在同一张`writeObject`图内，共享引用被保持：指代同一实例的两个字段读回为一个实例。对`FileStream`调用`close()`释放操作系统句柄并使流句柄失效；对同一引用的后续调用报告无效句柄错误。值的字节级编码——字节序以及结构体与对象的形式——由§15.6固定。

## 15.6 流编码

本节固定§15.5的写方法与读方法交换的字节级编码。`ByteStream`与`FileStream`的编码相同。流不携带头部：每个方法在游标处追加它的记录，由逐次调用写出的流是这些记录的串接。

**字节序。** 每个多字节值都按小端序写出，最低有效字节在前。整数按其类型的宽度以二进制补码形式写出，`float`与`double`写作该值的IEEE 754 binary32与binary64编码（§4.2）。

**标量方法。** `writeInt`与`writeFloat`追加4字节，`writeLong`与`writeDouble`追加8字节：即值在该方法槽类型下的编码。§15.5的隐式加宽在调用点施加，所以字节总是携带槽类型的宽度——`writeLong(42)`追加`long`值42的8个字节。

**字符串。** `writeString(s)`追加一个4字节的有符号长度——`s`的字节数——随后恰好是那些字节。字节就是字符串所持有的一切（§4.4）；编码不对它们强加文本形式。`readString`对负长度、超过16 MiB的长度、以及越过流末的长度一视同仁：每一种都是宿主级执行期错误（§9.1）。

**结构体。** `writeStruct(v)`不追加头部也不追加类型名：按声明顺序写出`v`的类型的各字段，每个字段按其自身类型编码——

| 字段类型 | 编码 |
|---|---|
| 标量基本类型（§4.2） | 以其自身宽度的值：`byte`与`ubyte`为1字节，`short`与`ushort`为2字节，`int`、`uint`、`float`、`bool`与`char`为4字节，`long`、`ulong`与`double`为8字节；`bool`为`0`或`1`，`char`为其码点 |
| `string` | `writeString`的形式 |
| 结构体 | 同样的结构体编码，内联且递归 |
| 类 | 下面的类记录 |

`readStruct(name)`对照被命名的类型恰好消耗那段字节序列：流与程序必须在类型的形状上一致。数组与函数类型的字段在写侧被拒绝（§15.5）。

**类记录。** `writeObject(c)`为每个类类型的值追加一条记录，以其首字节作标记：

| 标记 | 值 | 编码 |
|---|---|---|
| `0` | `null` | 仅标记字节 |
| `1` | 首次写出的实例 | 标记字节、4字节无符号长度、该类的限定名（§3.6），然后是实例的各字段——继承的字段在前，从基类到派生类——每个字段按结构体表中的方式编码 |
| `2` | 已在此流上写出的实例 | 标记字节与4字节对象编号 |

对象编号按写出顺序分配，从0起算，每条标记`1`的记录一个编号。`readObject(name)`重建该图：标记`1`记录的名字必须命名一个程序声明的类，且该类必须是被命名的类型或它的子类（§8.1）；实例在其字段被读取之前注册到下一个编号之下，因此环解析为同一实例。`0`、`1`、`2`之外的标记、尚未读到的对象编号、程序未声明的名字，以及既非被命名类型也非其子类的类，都是宿主级执行期错误（§9.1）。

**身份状态。** 编号的分配属于流而非属于调用：同一流上逐次的`writeObject`调用延续编号，逐次的`readObject`调用重建一个共享配对，因此较早调用写出的实例可以被较晚的调用引用。`reset()`与`close()`清除两侧的该状态（§15.5）。

**深度。** 嵌套超过64层的值——结构体内嵌结构体、类内嵌类，或两者互嵌——抛出宿主级执行期错误（§9.1），写侧与读侧皆然。
