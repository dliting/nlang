# 8. 面向对象

## 8.1 类与继承

类声明的语法见§2.4。类是引用类型（§4.7）。没有显式基类的类隐式扩展`Object`（§4.9）；类的基类由`: Base`给出，且继承是单继承：一个基类，没有多类继承。一个类可以实现任意多个接口，`implements I1, I2`（§8.3）。

成员是字段与方法。不写访问修饰符的成员是`private`：类成员默认private，接口成员默认public（§8.3）。访问修饰符管辖类的成员：

- `public`——在类自身可见的任何地方都可到达；
- `private`——只在声明类的方法内部可到达；
- `protected`——在声明类内部、以及其子类体内部可到达，按裸名或经基类类型名到达；其他任何地方不可到达。

同样的规则跨模块边界成立：导入的类只有其`public`成员可到达，例外是子类体内的`protected`成员。不是`public`的构造器不能在类外调用。

字段可以携带初始化器（§2.4）。初始化器必须是常量表达式：任意类型的字面量，允许一元取负；它不能引用字段或`this`。默认值在体运行之前注入类的每个构造器，基类在前：调用`super(...)`的构造器在该调用之后紧接着接受注入，没有`super(...)`的则在体首注入；存在字段默认值时，`super(...)`必须是构造器的第一条语句。没有声明构造器的类获得一个合成的`public`零参构造器，携带这些默认值。`native`或无体的构造器不能携带字段默认值。

构造器是不带返回类型声明的成员（§2.4），以类的名字命名。构造器是可选的，可以重载（§7.3）。构造器调用`C(args)`分配对象并运行选中的构造器（§5.8）；对没有声明构造器的类，`C()`分配对象并把字段零初始化。祖先的构造器不会自动调用：没有显式`super(...)`时，继承的字段保持其默认值（§4）。构造器内的`super(args);`在同一对象上调用直接父类的构造器；它只在有父类的类的构造器中有效，只接受按位置的实参（§7.2），且其实参表必须匹配某个父构造器。对没有构造器的父类使用`super()`是合法的空操作；这种情况下带实参是编译期错误。

在方法或构造器内部，指代所在类——包括继承的字段——的字段的裸标识符，是一次隐式的`this.field`访问；同名的局部或参数遮蔽该字段（§3.7）。`static`方法属于类而非实例：它经类型名调用，没有`this`，类内对它的裸调用直接指代它。当参数表不同时，静态方法与实例成员可以同名；签名完全相同的相撞是编译期错误。静态成员不参与虚分派（§8.2）；子类继承其父类的静态成员。

## 8.2 虚分派

`virtual`标志标记一个方法做动态分派。经由类引用的调用，从对象的运行时类向上遍历类层次来选择实现：名字的最派生实现胜出。对非虚方法的调用绑定到静态声明的类型，从不做动态分派：与某个非虚祖先方法同名的子类方法，在经由子类类型的调用中遮蔽它，而经由祖先类型的调用仍运行祖先的实现。

与某个祖先虚方法同名的子类方法必须与其签名完全一致：相同的参数类型与个数、相同的返回类型、相同的`out`修饰。不一致是编译期错误。一旦一个名字绑定了虚约定——继承的虚方法或实现的接口方法（§8.3）——该名字就不得在类或其任何子类中重载：同名的各方法必须与约定一一对应。在一个类内，带`virtual`成员的名字完全不能重载；要让整个家族非虚才能重载它。`Object`协议方法是虚的，遵循同一条规则（§4.9）：`int equals(Object other);`、`int getHashCode();`与`string toString();`。默认的`equals`与`getHashCode`比较对象身份；`equals`产出`int`0或1，而非`bool`。

重写不需要关键字：子类中同名同签名的方法取代继承来的实现。子类只在构造器中可以用`super(...)`调用父实现；没有`super.method(...)`形式。

## 8.3 接口

接口声明的语法见§2.4。接口声明实例方法签名，不携带实例字段与实例实现。接口类型是引用类型（§4.8）。

接口的实例成员是public抽象签名：访问修饰符默认`public`，写出`public`是冗余但合法的；`private`、`protected`、`const`、`native`与`virtual`在实例成员上是编译期错误，带体的实例成员也是编译期错误。接口可以声明`public static`成员：静态方法带体、经接口名调用；静态常量的形式是`static const T Name = e;`，其中`e`是编译期常量；两者都属于接口类型而非任何实现类，且不参与实现约定。当参数表不同时，接口的静态方法与实例方法可以同名；完全相撞是编译期错误，且常量不能与方法同名。

类用`implements I`声明遵从（§2.4）；其后可以跟一个接口列表，而`:`基类形式不命名接口。编译器在类声明处校验约定：接口的每个实例方法都必须由在类的继承链上分派将选中的同名方法实现，且签名完全一致（§8.2）。任何访问级别都可以实现方法，非虚方法或父类的方法也算作实现。实现缺失或不匹配是编译期错误。

接口类型的值指代一个实现对象；从类到接口类型的转换是隐式的（§4.8、§4.12）。接口引用可以为`null`；经由`null`接口引用的调用是可在执行期捕获的错误（§4.7，第9章）。经由接口引用的调用按对象的运行时类做动态分派，机制与类虚分派相同（§8.2）。

## 8.4 枚举

枚举的类型面——它的值、转换与默认值——见§4.5。成员面见本节。

枚举声明的语法见§2.4。方法跟在成员表之后，以`;`与成员表分隔；只有`;`而没有方法也被接受。每个方法都必须有体。

在枚举方法内部，`this`是接收者的底层`int32`值：它直接参与算术与`switch`（§5.2、§6.3）。方法经接收者表达式调用——一个变量、一个成员常量或任意枚举值的表达式；不带接收者的调用是编译期错误。方法做静态分派：枚举没有继承，也没有虚分派。枚举方法不带默认实参、不带`out`参数（§7.2）。内建`toString`是保留的：用户方法不能遮蔽它（§4.5）。在方法内部，对成员`M`写`this.M`指代`M`的常量值，而不是与接收者的比较。成员名与方法名不能相撞。方法默认`public`；`private`与`protected`遵循§8.1的可见性规则。

## 8.5 结构体

结构体的值面——深拷贝语义、默认值与聚合——见§4.6。成员面见本节。

结构体声明的语法见§2.4。结构体持有字段与构造器，没有方法。结构体成员总是public：字段与构造器默认`public`，在结构体成员上写`private`或`protected`是编译期错误。

结构体字段可以携带常量初始化器，遵循与类字段相同的表达式规则（§8.1）。与类不同，默认值在每次分配时应用，而非注入构造器：裸声明、数组元素、嵌套结构体字段与不完整的初始化器列表都会把默认值实体化，初始化器条目则覆盖存入它们；复制复制所存的值，不会重新应用默认值（§4.6）。

结构体构造器按类构造器的语法声明（§8.1），可以重载（§7.3）。构造器只在显式构造时运行——构造器调用或直接初始化声明；裸声明与初始化器列表不运行它，其字段取默认值（§4.6）。结构体构造器调用只接受按位置的实参（§7.2）。
