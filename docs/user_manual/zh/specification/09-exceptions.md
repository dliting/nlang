# 9. 异常

异常处理是结构化的：抛出的异常是一个普通对象，所在的`try`语句可以处理它，未处理的异常终结程序。`throw`语句与`try`语句的语法见§2.5。

## 9.1 抛出与传播

`throw e;`求值`e`。该值必须是`Exception`或其子类的实例（§9.3、§9.4）；其他任何类型都是编译期错误。抛出的异常是一个普通的类实例（§4.7），所以抛出形式是一次构造器调用：`throw Exception("message");`。`throw`接受一个值，而非类名。

`throw;`重新抛出当前正在处理的异常。它只在`catch`子句体的词法内部有效；其他任何地方都是编译期错误。重新抛出传播同一个异常对象：它的类、它的`message`与它的`backtrace`都不变（§9.3）。

一次抛出把控制传出正在运行的函数，传到调用方及调用链更上方、最近的带匹配`catch`子句的外层`try`语句（§9.2）；路径上的各`finally`体按§9.2的规定运行。若没有处理者匹配，宿主报告未捕获的异常，程序以退出码1终止（第10章）。

语言、标准库与VM对其所报告的错误抛出§9.3的内建异常，且这些异常可捕获：经由`null`引用的访问（§4.7、§5.6、§5.7）、除以零或取余零以及越界的移位计数（§5.2）、越界的下标（§5.7）、失败的断言（§6.5）、失败的`as`向下转型（§5.5），以及第19章的库错误。

*宿主级*执行期错误（§7.1）不是异常：没有`catch`子句处理它，程序结束。定义宿主级失败的各节指明其发生位点——调用深度界（§7.1）、缺失的原生函数（§7.5）、§5.5的拆箱与`null`向下转型失败、超出成员表的枚举`toString()`（§4.5）、§13.2的`toString`嵌套界、§15.5的流失败，以及第11章的并发失败。

## 9.2 try / catch / finally

语法（§2.5）允许空的catch表，但既无`catch`子句也无`finally`子句的`try`语句是编译期错误；没有`catch`的`try { } finally { }`是合法的。

`catch`子句的类型必须是`Exception`或其子类；其他任何类型都是编译期错误。一个`try`语句的各子句按声明顺序匹配。第一个类型等于所抛异常之类或其祖先的子句运行其体；其余子句被跳过。因此`catch (Exception e)`匹配每个异常，列在它之后的、更具体类的子句不可达。`catch`参数是`catch`体中一个普通的局部变量（§3.5）：可以读取也可以赋值。

每当控制离开`try`区域，`finally`体都运行，每条路径皆然：

- `try`体正常完成；
- 匹配的`catch`体完成；
- 异常展开穿过：`finally`体运行，异常继续传播——包括从`catch`体抛出的异常；
- `break`或`continue`传出该区域：`finally`体在跳转之前运行，嵌套的`try`语句内层先；
- `return`：先求值返回表达式，然后`finally`体运行，然后函数返回。

每次控制流经过，每个`finally`体恰好运行一次。嵌套的`finally`体内层先运行；它们运行之后，外层的`catch`看到在途的异常。

在`finally`体内部，`break`、`continue`、`return`与`throw`都是编译期错误：该体不得置换在途的控制流。

## 9.3 内建异常

`Exception`扩展`Object`（§4.9）。内建异常类是`Exception`及其六个直接子类：

| 类 | 由谁抛出 |
| --- | --- |
| `Exception` | 对用户`throw`抛出`Exception`自身；对不存在的键做`Dict`读取（§4.10）；没有专属类的VM位点：越界的移位计数（§5.2）、Unicode标量值之外的`char`转换（§5.5）、以负容量构造的`Channel`（§11.4） |
| `NullPointerException` | 经由`null`的类、接口或函数引用的成员访问、方法调用或调用（§4.7、§5.6、§5.7） |
| `DivByZeroException` | 任意数值宽度上的除以零或取余零（§5.2） |
| `IndexOutOfBoundsException` | 越界的数组或`List`下标（§5.7）；带长度的数组创建中长度为负或元素数超过上限（§4.3）；越界的`string`的`substring`或`charAt`（§13.3） |
| `AssertionException` | 失败的`assert`（§6.5） |
| `InvalidCastException` | 失败的`as`向下转型（§5.5） |
| `IOException` | 失败的`io`或`fs`操作（第15章、第16章） |

`concurrent`包（§12.4）声明了再一个直接子类`ChannelClosedException`，由对已关闭通道的操作抛出（§11.4）；它经`import concurrent;`像任何包类一样进入作用域，`catch`对它的处理与其他子类无异。

每个异常实例携带两个字段，从`Exception`继承：

- `message`（`string`）——由创建该实例的构造器调用设置，或由抛出VM异常的位点设置。某节固定了文本时（§6.5），该文本是规范性的；否则消息以实现选定的措辞描述错误。用户代码可以读取并赋值该字段。
- `backtrace`（`List<string>`，§4.10）——对VM抛出的异常，是抛出时拍摄的调用栈快照：每帧一个条目，最内层在前，每个条目形如`qualifiedFuncName (file:line)`。用户代码创建的异常以空backtrace开始。用户代码可以读取并赋值该字段。

## 9.4 用户异常类

用户可以定义类扩展`Exception`（§8.1）以携带额外状态。其构造器用`super(msg)`转发消息（§8.1）；没有声明构造器时，合成的零参构造器让继承的字段保持其默认值（§8.1）。类自身的字段在对象布局中排在继承字段之后（§8.1）。

用户异常的抛出与处理和内建异常完全一样：`catch (MyException e)`在§9.2的规则下匹配`MyException`及其子类，而`catch (Exception e)`同样匹配它。
