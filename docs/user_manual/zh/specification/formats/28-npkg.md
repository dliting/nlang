# 28. `.npkg`包档案

*包档案*是一次构建的分发形态：它打包该构建的成员——第27章的单元映像，每个包一份（§3.9.1），外加构建附带的宿主原生库。单元成员以其包路径命名，原生成员以其文件名命名（§28.3）。程序档案携带一条*入口记录*；库档案省去它，标准库的十三个领域包都是库档案（§3.9.4）。§28.1界定范围并固定格式版本；§28.2固定容器；§28.3定义入口记录与成员同一性；§28.4固定成员校验和；§28.5陈述读取与消费契约。

## 28.1 范围与版本

**格式版本。**本章描述格式版本 **1.1**，在头部中记为主`1`、次`1`（§28.2）。读取器接受主号`1`且次号不高于自身的档案——较新的读取器读较旧的次号，绝不反向——并拒绝其他一切版本（§28.5）。格式变更会提升版本并整章替换本章；规范只描述当前版本。

**本章固定的内容。**容器布局（§28.2）、入口记录与成员同一性（§28.3）、成员校验和（§28.4）与读取契约（§28.5）。

**本章不固定的内容。**每个成员内部存放的单元映像——第27章——以及消费被提取映像的链接闭包语义（§3.9.3）。

**确定性。**同一组成员打包两次产出字节相同的档案：成员按名字排序，且头部不记录时间戳。

## 28.2 容器布局

**约定。**同§27.2：小端二进制补码整数与长度前缀字节串；宽度记号`u8`、`u16`、`u32`与`u64`相同。

**头部。**档案以下列内容开始：

| 字段 | 宽度 | 内容 |
|---|---|---|
| 幻数 | 8字节 | `NLANGPKG` |
| 版本主号 | u16 | `1` |
| 版本次号 | u16 | `1` |
| 包名 | u16长度 + 字节 | 构建记录的制品名（输出模块名）；它在诊断中命名该档案 |
| 旗标 | u32 | 写`0`；未定义任何旗标，读取器忽略该字段 |
| 签名算法 | u16 | `0` = 无签名；签名块为预留 |
| 签名偏移 | u64 | `0` |
| 签名长度 | u64 | `0` |
| 成员数 | u32 | |
| 入口 | — | 零字节标记库（无入口记录）；否则为入口记录：u16长度加入口单元的包路径，然后u16长度加入口函数的名称（§28.3） |

**成员表。**紧接头部之后，每个成员一个条目，按成员名字的字节序升序：

| 字段 | 宽度 | 内容 |
|---|---|---|
| 模块路径 | u16长度 + 字节 | 该成员的名字：单元成员所容纳单元的包路径（§3.9.1），或原生成员的文件名（§28.3） |
| 种类 | u8 | `0` =单元映像；`1` =宿主原生库 |
| 偏移 | u64 | 该成员映像字节的绝对文件偏移 |
| 长度 | u64 | 映像字节数 |
| 校验和 | u64 | §28.4 |

**数据块。**写出器按表序把成员映像排在表之后，每个从其记录的偏移开始；读取器跟随记录的偏移，不要求映像相邻。单元成员的字节是一张完整的单元映像（第27章）；原生成员的字节是构建附带的库文件本体。

## 28.3 入口记录与成员同一性

**入口记录。**程序档案指明其入口：入口单元的包路径与入口函数的名称（当前为`main`，§3.2，§9.3）。库档案改带零标记。在档案内部，只有持有入口的成员映像保留非空入口键（§27.2）；档案的入口记录才是权威入口。

**成员同一性。**每个名字一个成员：打包器拒绝重复名字。单元成员的名字是它所容纳单元的包路径，所以对包路径的引用恰好解析到一个成员。原生成员的名字是其库文件名——宿主平台装载该库所用的名字——没有导入会解析到它（§28.5）。

## 28.4 成员校验和

成员的校验和是其精确映像字节的64位哈希，按FNV-1a递推计算：从偏移基数14695981039346656037开始；对每个字节，把该字节异或进哈希再乘以素数1099511628211（2^40 + 435），全部按2^64取模。校验和检测意外损坏；它不是安全原语——§28.2预留的签名块才是它的位置。提取时校验它，不匹配即是同时命名档案与成员的错误（§28.5）。

## 28.5 读取与消费

读取器在使用容器之前先校验它：

- **幻数。**除幻数以外的头部字节 → 拒绝。
- **截断。**越过文件尾的头部或成员表条目 → 拒绝。
- **版本。**除`1`以外的主号，或高于读取器自身的次号 → 拒绝。
- **成员边界。**记录的偏移或长度不在文件之内的成员 → 拒绝，并命名该成员。

提取一个成员时校验其校验和（§28.4）；不是该档案成员的路径即是错误。

编译期，导入按§3.9.2所述对包的单元成员解析：模块路径取同名成员，通配取匹配成员的并集。原生成员不回应任何导入——它的名字是文件名而非模块路径，编译器不读取它的字节。

运行期，加载器按模块路径取单元成员映像，随导入闭包的需要取用（§3.9.3）。操作系统无法直接从档案映射一个库，所以打开包还会把每个原生成员抽取到用户包缓存下该包专属的目录中（`NLANG_PKG_CACHE_ROOT`环境变量可重定位缓存根），装载时把该目录追加进原生搜索路径（§7.5）——可执行文件旁或更早层上的散装库仍然优先于打包副本。字节与成员一致的缓存副本保持原样，不一致的则被替换。声明不进入程序闭包的包因此被抽取但从不装载。
