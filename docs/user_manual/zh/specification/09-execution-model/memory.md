# 9.2 生命周期与垃圾回收

对象——类实例、结构体记录、数组、函数值与字符串——生活在由实现管理的堆中。语言不提供释放操作：程序从不释放对象，回收也不运行用户代码（没有终结器，也没有析构器）。

若一个对象能经由引用从根出发找到，它就是*可达*的：活动函数帧的活跃槽（参数、局部变量、临时值与暂存槽）、可达对象的字段、可达容器的元素、存活函数值被捕获的接收者，以及宿主持有的引用。实现做出两条承诺：

- 可达对象绝不被回收；
- 不可达对象MAY在任何时刻被回收；回收何时发生是*未指明*的（§0.4）。

由于回收不运行用户代码且其时机未指明，程序无法观察一个对象何时——或者是否——被回收。结构体记录由其持有者（一个局部槽、一个字段，或数组或容器的一个元素）拥有，并随之一起变为不可达。

实现无法为新对象取得内存时会发生什么，是*未指明*的。

### 回收何时发生

*资料性：*NLang是垃圾回收语言：没有`delete`，也没有可调用的释放函数——对象在不可达后自动回收，无需手动释放内存。

回收在安全点运行——函数入口与循环迭代边界——条件是有回收请求待决，且堆大小或字符串对象数量超过各自阈值。回收不移动对象：对象创建后堆索引不变，回收只是把不可达对象标记为空闲，供新分配复用。

### 什么算可达

*资料性：*回收器从根出发标记所有可达对象，未标记的即被回收。根包括：

- 各函数的局部变量与正在求值的返回值；
- class与struct的字段、数组与`List`/`Dict`的元素、字符串字段与字符串数组元素；
- 挂起中的虚拟线程的调用栈，以及通道缓冲里的元素（第10章）；
- 宿主程序通过嵌入接口持有的引用（见[嵌入NLang](../../libraries/embedding-api.md)）。

struct随宿主释放（值语义）：局部struct存活到函数返回；class持有的struct字段随宿主class一起回收；嵌套struct随父级递归释放。字符串字面量随模块常驻，永不回收。

回收器内部的完整机制——标记方式、空闲表、并发收集的停止世界握手——见[垃圾回收设计](../../vm-architecture/garbage-collection-design.md)。
