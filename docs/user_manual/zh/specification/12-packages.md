# 12. 包与导入查找

## 12.1 文件角色

NLang以四种文件搬运代码。

- **`.n`——源文件。** 一个文件是一个编译单元（§3.1），也是代码同一性的单位——*包*。包的名字是它被发现时所在搜索根（§12.2）之下的相对路径，每个目录一个点分段；没有任何文件内语法为包命名。
- **`.ncu`——单元映像。** 一个包的编译产物。其中的跨包引用是*导入槽*——一个目标包路径加一个限定名——绝不是体（§12.3）。格式见第20章。
- **`.npkg`——包档案。** 单元映像的容器，每个包一个成员，每个成员以其包路径命名。一次项目构建产出一个带*入口记录*的档案，记录命名入口单元（§3.2）；库档案省略该记录——标准库以`stdlib.npkg`分发（§12.4）。格式见第21章。
- **原生宿主库。** 承载`native`实现的宿主动态库，由声明它的包命名，而该包必然是单段的（§7.5）。

各单元没有提供入口（§3.2）的构建产出库产物：可被其他构建导入，不可运行。

## 12.2 导入解析

一个有序目录集合——*搜索路径*——服务于编译期源码发现、运行期产物装载（§12.3）与原生宿主库（§7.5）。路径按此顺序组装，靠前的条目优先：

1. 每个`-I <dir>`命令行选项，按出现顺序；
2. 项目文件的`<ImportPaths>`条目；
3. 本地目录：项目、源码或模块所在目录；
4. 环境变量`NLANG_PATH`，在Windows上按`;`切分，在POSIX上按`:`切分；
5. 系统默认：标准库目录、可执行文件所在目录、当前目录。

条目会被规范化；一个目录被列出多次时保留其首次出现（路径在Windows上不区分大小写地比较）。每个工具都包含全部三个系统默认目录；它们的相对顺序是*未指明*的（§0.4）。

对包路径`a.b.c`的导入（§3.3）命名某个搜索根之下的源文件`a/b/c.n`。编译期：

- 若恰好一个根提供该文件，该单元被内联进本次编译（§3.1）；每个文件只内联一次，被内联单元的导入按同样的规则解析，直至不动点；
- 若两个或更多根提供它，那是点名各源路径的编译期错误：一个包名在一次构建中唯一，绝不静默遮蔽；
- 若没有根提供源码：单段路径`c`（§3.3）解析到一个外部产物——第一个持有`c.ncu`或`c.npkg`的搜索目录，同名时单元映像先于档案——其声明以桩的形式进入构建；构建内没有源码的带点路径是编译期错误，因为外部产物只承载单段名字（§3.3、§20.2）。

内联为发起导入的编译解析声明；它不复制任何体。编译产物以包路径点名其依赖，并在运行期与它们链接（§12.3）。

## 12.3 模块同一性与装载

包的同一性就是那个点分名。一次构建对每个包名至多携带一个源码（§12.2），而编译产物中的每个类、结构体与函数都以其包限定名为键（`main.main`、`alib.Point`）；实现自有的内建保持其裸键（`Object`、`List`）。限定键就是链接的拼写——链接、流与各工具皆然。

运行期，装载器从入口产物出发，急切地走完导入闭包：被导入单元点名的每个包路径都在执行开始之前解析并装载。解析遵循搜索路径（§12.2）：入口档案自身的成员最先——与入口同批分发的兄弟单元——然后按顺序逐个搜索目录，同一目录内`<path>.ncu`文件先于任何`.npkg`的成员（档案按文件名顺序扫描）。首个匹配胜出，且每个包路径至多装载一次。

所有装载的单元以限定名链接进一个运行时模块：一次跨包调用到达被解析产物的体。作为单个模块导入的档案必须恰好暴露一个单元——一个入口记录，或恰好一个成员。

闭包问题——缺失的包、不可读的产物——被一次性收集并报告，列出搜索过的每个目录，而不是每次浮现一个失败。

## 12.4 标准库引导

标准库以两种形态随工具链分发：`.n`源码，经标准库目录发现并在编译期内联，以及`stdlib.npkg`，每个库单元一个成员，运行期从可执行文件所在目录装载。两个目录都是系统默认搜索条目（§12.2），所以一次普通构建无需配置就能找到标准库。

标准库包像其他包一样导入（§3.3）；第14–18章描述它们所持有的单元。实现自己提供的类——第4、8、11章的内建值类、容器类与句柄类——无需导入。

> 实现注记。内建类目前由实现注册；规划中的方向是把它们声明在以内建预置包形态分发的`.n`声明文件里，让这些声明成为真源。
