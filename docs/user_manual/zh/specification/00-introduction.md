# 0. 引言

## 0.1 范围与状态

本规范是NLang编程语言的规范性定义，覆盖三部分：核心语言（第一部分）、标准库（第二部分），以及实现产生与消费的二进制格式（第三部分）。

它是一份活文档：描述当前语言，不附带兼容性附录。语言变更时文本随之变更，仓库历史（标签与提交）就是版本记录。可观察语义的变更——新增或移除特性、类型系统规则、格式变更、库接口的增加或删除——先写成NLang增强提案（NLEP）；文本的澄清与更正可以直接提交。

本规范是语义问题的权威。用户手册是教程，属资料性；它把所摘要的规则链接到本规范的对应条款。

## 0.2 规范性用语

本规范中的关键描述词MUST、MUST NOT、SHOULD、SHOULD NOT与MAY按RFC 8174解释。标注为资料性的陈述是指引，不是要求。本规范未作规定之处，行为未指明：实现可以任选行为，但不得把另一种行为记为符合规范。

在程序运行之前拒绝该程序的规则，表述为「……则是编译期错误」。被拒绝的程序必须得到诊断，实现不得静默执行它。关于执行期行为的规则陈述可观察的结果，包括（当抛出异常时）抛出的是哪个异常。

## 0.3 条款引用

本规范中每个编号标题都是一个条款，引用形式为`§n`、`§n.k`或`§n.k.m`。条款编号在全树唯一、章内连续、保持稳定：自动守卫拒绝空缺、重复与悬空引用。按编号引用条款对用户手册、更新日志条目与NLEP有效；这些引用只以编号指称条款，绝不使用指向本仓库内部的路径。

## 0.4 术语与定义

定义的术语在首次定义处以斜体排印，后续使用处链接回该定义。

*编译单元*：编译器所处理的单个`.n`源文件，连同它导入的声明（第12章定义）。

*规范性*：对实现具有约束力。本规范的英文文本是规范性的；译文是资料性的。

*资料性*：指引与说明，实现可自由忽略。

*未指明*：规范不施加要求；不同实现、或同一实现的不同运行，可以彼此不同。

*实现定义的*：实现自行选择一个行为，但必须记录该行为，且不得与本规范的其余部分矛盾。

## 0.5 符合性

当且仅当一个实现所接受的每个程序的可观察行为都与本规范一致时，该实现才符合规范：包括它接受与拒绝哪些程序、必须产生哪些诊断、程序可观察到的值与异常，以及并发执行允许的交错方式。

实现内部发生的事情在本规范之外。虚拟机的内部表示、它的寄存器分配、所做的优化、其垃圾回收器的内部结构，在此都不受约束，只要每个可观察结果仍与第10章一致。第三部分的二进制格式是例外：之所以规定它们，是因为工具与宿主程序直接消费这些格式。
