# 14.5 ByteStream与FileStream

`ByteStream`与`FileStream`是`io`包的内建句柄类（§11.1），使用前`import io;`（§3.9.4）：`ByteStream`读写内存缓冲，`FileStream`读写磁盘文件。`ByteStream()`构造一个空缓冲。`FileStream(path, mode)`打开文件：模式`"w"`创建或截断，`"a"`创建或追加，`"r"`只以读方式打开；直接初始化声明同样合法（`FileStream fs("data.bin", "w");`，§4.8.4）。未赋值的流句柄为null；经由null句柄的方法调用抛出`NullPointerException`（§8.3）。其他一切流失败都是*宿主级*执行期错误（§8.1）：没有`catch`子句处理它，程序结束。失败位点有：无效模式、打开失败（包括对缺失文件用`"r"`）、经由已关闭或无效句柄的访问、对只读流的写入或对只写流的读取、越过流末的读取、命名了程序未声明的类型的结构体或对象读取，以及由`writeStruct`或`writeObject`写出的函数类型字段、元素为类引用的数组经`writeObject`写出（标量与结构体元素可序列化，§14.6）。

```nlang
ByteStream bs = ByteStream();
bs.writeInt(1);
bs.writeDouble(0.5);
bs.reset();                  // 回卷游标，保留缓冲区
int n = bs.readInt();        // 1
double d = bs.readDouble();  // 0.5
```

方法面除注明处外完全相同：

| 方法 | 效果 |
| --- | --- |
| `writeInt(x)` / `readInt() → int` | 4字节整数 |
| `writeFloat(x)` / `readFloat() → float` | 4字节浮点数 |
| `writeLong(x)` / `readLong() → long` | 8字节整数 |
| `writeDouble(x)` / `readDouble() → double` | 8字节浮点数 |
| `writeString(s)` / `readString() → string` | 4字节长度，随后是各字节 |
| `writeStruct(v)` / `readStruct(name)` | 结构体各字段的递归写出；读取以字符串命名类型，产出该类型的值 |
| `writeObject(c)` / `readObject(name)` | 类图或数组值的递归写出；读取以字符串命名类型，产出该类型的值 |
| `readArray()` | `writeObject`写出的数组，以`Object`返回（经`as`转型，§4.5） |
| `length() → int` | 流的总字节数 |
| `position() → int` | 当前游标 |
| `reset()` | 把游标回到0并清除对象身份状态；缓冲保留（仅`ByteStream`） |
| `close()` | 释放缓冲或文件句柄；句柄变为无效 |

标量写方法按宽度准入实参。8字节写入器接受§4.4能隐式赋值到其槽类型的任何值：`int`进入`writeLong`，`float`或整数进入`writeDouble`，转换在调用点施加；`ulong`超出`long`值域，需要显式`as long`。4字节写入器按声明形参准入：`writeInt`接受至多32位的整数；`writeFloat`接受`float`，能无损落入`float`的常量实参同样合法——`writeFloat(1.0)`与§4.2的常量适配特例（`float f = 1.0;`）同一条规则。被拒绝的实参是编译期错误，给数值方法传`char`或`string`实参也是编译期错误。

读取按写出顺序消耗流——示例先读回int，再读double——越过流末的读取抛出宿主级错误而非产出值。`writeObject`同样接受数组值：数组写成一条自描述记录——视图写出其逻辑内容，往返得到独立的拥有数组——由`readArray()`读回。`readArray()`返回`Object`；用`as`把结果转到标注数组类型，转型按数组值一贯的规则校验秩与元素类型（§4.5）。由`writeObject`写出的`null`类引用读回为`null`。在同一张`writeObject`图内，共享引用被保持：指代同一实例的两个字段读回为一个实例。对`FileStream`调用`close()`释放操作系统句柄并使流句柄失效；对同一引用的后续调用报告无效句柄错误。值的字节级编码——字节序以及结构体与对象的形式——由§14.6固定。

## 14.6 流编码

本节固定§14.5的写方法与读方法交换的字节级编码。`ByteStream`与`FileStream`的编码相同。流不携带头部：每个方法在游标处追加它的记录，由逐次调用写出的流是这些记录的串接。

**字节序。** 每个多字节值都按小端序写出，最低有效字节在前。整数按其类型的宽度以二进制补码形式写出，`float`与`double`写作该值的IEEE 754 binary32与binary64编码（§4.2）。

**标量方法。** `writeInt`与`writeFloat`追加4字节，`writeLong`与`writeDouble`追加8字节：即值在该方法槽类型下的编码。§14.5的隐式加宽在调用点施加，所以字节总是携带槽类型的宽度——`writeLong(42)`追加`long`值42的8个字节。

**字符串。** `writeString(s)`追加一个4字节的有符号长度——`s`的字节数——随后恰好是那些字节。字节就是字符串所持有的一切（§4.3）；编码不对它们强加文本形式。`readString`对负长度、超过16 MiB的长度、以及越过流末的长度一视同仁：每一种都是宿主级执行期错误（§8.1）。

**结构体。** `writeStruct(v)`不追加头部也不追加类型名：按声明顺序写出`v`的类型的各字段，每个字段按其自身类型编码——

| 字段类型 | 编码 |
|---|---|
| 标量基本类型（§4.2） | 以其自身宽度的值：`byte`与`ubyte`为1字节，`short`与`ushort`为2字节，`int`、`uint`、`float`、`bool`与`char`为4字节，`long`、`ulong`与`double`为8字节；`bool`为`0`或`1`，`char`为其码点 |
| `string` | `writeString`的形式 |
| 结构体 | 同样的结构体编码，内联且递归 |
| 类 | 下面的类记录 |
| 数组 | 下面的数组记录 |

`readStruct(name)`对照被命名的类型恰好消耗那段字节序列：流与程序必须在类型的形状上一致。函数类型的字段在写侧被拒绝（§14.5）。

**类记录。** `writeObject(c)`为每个类类型的值追加一条记录，以其首字节作标记：

| 标记 | 值 | 编码 |
|---|---|---|
| `0` | `null` | 仅标记字节 |
| `1` | 首次写出的实例 | 标记字节、4字节无符号长度、该类的限定名（§3.6），然后是实例的各字段——继承的字段在前，从基类到派生类——每个字段按结构体表中的方式编码 |
| `2` | 已在此流上写出的实例 | 标记字节与4字节对象编号 |

对象编号按写出顺序分配，从0起算，每条标记`1`的记录一个编号。`readObject(name)`重建该图：标记`1`记录的名字必须命名一个程序声明的类，且该类必须是被命名的类型或它的子类（§4.8.5）；实例在其字段被读取之前注册到下一个编号之下，因此环解析为同一实例。`0`、`1`、`2`之外的标记、尚未读到的对象编号、程序未声明的名字，以及既非被命名类型也非其子类的类，都是宿主级执行期错误（§8.1）。

**数组记录。** 对数组值调用`writeObject`——以及结构体或类记录内的数组字段——追加一条数组记录，在类标记空间中取标记`3`：标记字节、元素种类字节，随后——仅结构体元素——4字节无符号长度与该结构体的限定名（读取侧按名重建，与类相同）、单字节的秩、每个维度一个4字节有符号整数，最后是行主序的各元素。标量元素与结构体字段一样按自身宽度编码，`string`元素按`writeString`的形式，结构体元素为裸结构体记录，每元素一条。`readArray()`消耗这样一条记录并返回新建的拥有数组（绝不是视图）；图中写出的`null`数组字段按§14.6类记录的标记`0`读回。`readArray`读到`0`与`3`之外的标记、程序未声明的结构体名字、1到64之外的秩、以及没有线上形式的元素种类，都是宿主级执行期错误（§8.1）。

**身份状态。** 编号的分配属于流而非属于调用：同一流上逐次的`writeObject`调用延续编号，逐次的`readObject`调用重建一个共享配对，因此较早调用写出的实例可以被较晚的调用引用。`reset()`与`close()`清除两侧的该状态（§14.5）。

**深度。** 嵌套超过64层的值——结构体内嵌结构体、类内嵌类，或两者互嵌——抛出宿主级执行期错误（§8.1），写侧与读侧皆然。
