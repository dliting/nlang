# 14. io包与流

`io`包提供控制台输出、控制台输入与整文件内容搬运。流类`ByteStream`与`FileStream`提供值、结构体与类图的二进制序列化。§14.1固定包形态以及管辖每一次包调用的实参准入规则；§14.2–§14.4定义io函数；§14.5定义原生库构建于其上的通用输入输出（IO，input/output）设施；流类（§14.6）与流值的字节级编码（§14.7）在专页定义。

## 14.1 包形态

`io`是标准库包（§3.9.4）：`import io;`把它带入作用域，每个函数都经包限定符调用（`io.print(s)`）。包名是单段的（§3.3）。它的声明是标准库的`.n`源码；输出三函数、输入函数与文件函数是`native`函数（§7.5），而带类型的读取器是建立在`readToken`与字符串转换方法（§17.2）之上的NLang源码包装。

**实参准入。** 对包函数的调用把每个实参对照声明的形参类型绑定（§7.3）；§4.4到`string`的隐式转换不适用于包实参。包函数的`string`形参只接受`string`实参；任何其他类型都是编译期错误。对用户声明的函数的调用保持§4.4的关系：在`emit`声明一个`string`参数处，`emit(42)`能编译，但`io.writeFile(42, "x")`不能。

例外是输出三函数`io.print`、`io.write`与`io.eprint`（§14.2）。这三者额外接受渲染为文本的实参（§5.3）：标量基本类型、数组与函数值。类、接口或枚举值被拒绝——类或接口值要先调用`.toString()`（§11.2），枚举变量同样如此；枚举成员常量被接受，打印其成员名（§5.3）。结构体值被直接拒绝：结构体没有`toString`（§11.2）。`null`实参被拒绝：它会打印成`0`。该例外以`io`包路径下的这三个名字为键；遮蔽`io`的用户包恰在这些名字上继承它。

## 14.2 控制台输出

- `io.print(s)`把`s`的文本写入标准输出，随后跟一个换行。
- `io.write(s)`把`s`的文本写入标准输出，不带尾随换行。
- `io.eprint(s)`把`s`的文本写入标准错误，随后跟一个换行。

每个函数按§14.1的三函数准入接受一个实参——打印多个值需要多次调用——非字符串实参在写入之前按§5.3与§11.2渲染为文本。`io.write`是提示形态：`io.write("Name: ")`把光标留在行上，键入的回复落在提示之后；`io.eprint`在标准错误上镜像`io.print`，让诊断输出与正常输出保持可分离。目的地是宿主的输出通道；宿主写入失败的效果是*未指明*的。调试会话内两个流合并进会话的单一输出视图。

## 14.3 控制台输入

输入函数经一个共享游标读取程序的标准输入：行读取、记号读取与码点读取在同一位置上交错，游标恰好按一次调用所消耗的内容前进。每个输入函数都是阻塞的原生函数：它声明阻塞段（§10.1），所以在调用等待期间调用上下文停泊、载体锁被释放。

- `io.hasInput()`在仍有输入可读时返回`true`，在输入结束时返回`false`。它从不抛出。没有输入通道时，它返回`true`，直到某次读取抛出`IOException`。对重定向的文件或管道，答案是精确的；在控制台上，它只报告宿主已经缓冲的输入；在调试会话里，只报告已缓冲的行。
- `io.readLine()`返回不含行终止符的下一行；尾随的回车被剥去。在输入结束时它返回`""`：空行与输入结束无法由返回值区分，`hasInput()`把两者分开。没有输入通道时它抛出`IOException`（§8.3）。
- `io.readToken()`返回下一个以空白分隔的记号，跨行跳过空白。在输入结束时它抛出`IOException`；没有输入通道时同样。
- `io.readChar()`返回下一个非空白码点，从输入的Unicode转换格式（UTF-8）字节解码而来；前导空白被跳过，与`readToken`相同。它返回字面字符——输入`x`得`'x'`——与`toChar`的数值解析（§17.2，`"120"`得`'x'`）有意不同。在输入结束时它抛出`IOException`；没有输入通道时同样。不是有效UTF-8的字节序列抛出`Exception`（§8.3），而非`IOException`。
- `io.readInt()`、`io.readLong()`、`io.readFloat()`、`io.readDouble()`与`io.readBool()`读取下一个记号，并用对应的字符串方法转换它（§17.2）：输入结束抛出`IOException`（来自`readToken`），没有输入通道时同样，格式不当的记号以与该字符串方法完全相同的方式失败。

混合读取遵循C++里`cin >>`与`getline`的组合语义：取词读取只消费到词尾，随后的`readLine()`返回该行剩余部分（含前导空白），当前行耗尽后才取下一行。输入`"10 20\n30\n"`时：`readInt()`得10，`readInt()`得20，`readLine()`得`""`（行剩余为空），`readLine()`得`"30"`，再读返回`""`（输入结束）。

```nlang
while (io.hasInput()) {
    string line = io.readLine();
    io.print(line);
}
```

> 实现注记。当程序为输入而阻塞、且标准输入与标准输出都是控制台时，宿主在等待之前打印一个`"> "`提示符——与Python、sqlite3等REPL的惯例一致，`nvm`直接运行与ncc进程内运行皆然；nide调试页终端在行模式下自行绘制同一记号。该提示符不是语言的一部分，且只要任一端是管道或重定向，两个流都保持逐字节不变。

## 14.4 文件内容IO

- `io.readFile(path)`把`path`处文件的完整内容以字节的`string`返回（§4.3）。当文件无法打开、其大小无法确定、大小超过16 MiB，或读取中途失败时，它抛出`IOException`（§8.3）。
- `io.writeFile(path, content)`创建文件，或截断已存在的文件，并写入`content`；`io.appendFile(path, content)`在需要时创建文件并追加`content`。两者在文件无法打开或无法写入时抛出`IOException`。

`path`是平台原生形态的宿主路径；io包不定义自己的路径语法（第16章的`fs`包定义）。内容是字节：io函数不对其读写的内容强加任何文本编码。

## 14.5 通用IO设施

三个函数是面向原生库后端的通用输入输出（IO，input/output）设施，而非日常用户工具：普通程序经`net`包（第21章）的阻塞调用或§14.6的流类达到同样行为，很少直接调用这些。

- `io.parkForIo(fd, events, deadlineMs)`停泊发起调用的虚拟线程，直到描述符`fd`就绪（`events`：`1`读、`2`写）或到达绝对截止时刻`deadlineMs`（`deadlineMs <= 0`表示无截止）；`fd < 0`是纯定时唤醒，而`fd < 0`且无截止时刻时立即返回——没有任何东西能唤醒这样的停泊，调用不会等待。调用在唤醒后返回——调用方重新检查自己的条件，可以再次停泊。这是`net`包的阻塞方法构建其上的停泊原语（§21.1），而且是通用的：持有描述符的原生库经同一个调用停泊，将来的管道与进程管线亦然。
- `io.toBytes(s)`把`s`的原始Unicode转换格式（UTF-8）字节以`byte[]`数组返回；`io.fromBytes(data)`把`byte[]`数组解码回`string`。转换绕过字符串方法表面（§17.2），不带长度前缀也不带终止符——套接字与流载荷的字节级桥梁。

*供参考：*`toBytes`与`fromBytes`从`net`包移到这里——字节转换不是网络特有的。
