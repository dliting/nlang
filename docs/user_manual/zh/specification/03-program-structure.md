# 3. 程序结构与名称解析

## 3.1 编译单元

程序由一个或多个`.n`源文件编译而成。每个文件是一个编译单元（§0.4）：文件本身，加上它的导入所拉入的库单元（第12章）。一次编译的全部单元——项目自身的源码，以及经库搜索路径内联进来的库源码——合并为单一的程序作用域：每个顶层声明都汇入同一棵命名空间树，不同单元中的声明按§3.6的规则互相可见。

编译单元的体是有序的（§2.2）：先是导入表，然后是using指令，最后是顶层成员。第一个顶层成员之后再出现`import`或`using`指令是语法错误。

顶层成员有：

- 类型声明：`enum`、`struct`、`class`与`interface`（第4章与第8章）；
- 顶层函数，裸函数或带修饰符的函数（§2.2，第7章）；
- 顶层语句（§3.2）。

没有顶层变量。写在文件作用域的变量声明是一条顶层语句而非全局声明，遵循§3.2。

## 3.2 程序入口

编译单元的顶层语句构成它的*脚本体*。当该单元作为程序的一部分被编译时，编译器合成一个入口函数`int main()`，其体按源码顺序就是脚本体；该单元的声明照常保持其程序作用域。合成的入口是一个普通的、无参数、返回`int`的函数。

- 编译单元同时含有脚本体与显式`main()`函数时，是编译期错误：脚本体在第二个入口之内不可达，因此两种形式都不会被静默丢弃。
- 被导入的单元含有顶层语句时，是编译期错误：被导入的单元只贡献声明，其语句否则会在不可预测的时点运行。

一次构建至多有一个入口函数。若一次构建的多个单元各自提供入口——显式`main()`或脚本体——则是编译期错误。单元不提供任何入口的构建，产生一个没有入口函数的库模块（第12章）。

程序的执行从调用其入口函数开始；入口返回的值成为进程退出状态（第10章）。

## 3.3 导入指令

导入指令命名一个*包路径*：一个点分名字，指代被编译程序中的一个模块、一个标准库包，或一个外部编译模块（第12章）。语法见§2.2；两种形式是：

```nlang
import utils.helper;      // one module or package
import utils.*;           // wildcard: the whole subtree
```

导入对发起导入的编译单元有两个效果：

- 被导入单元的声明汇入程序作用域（§3.1）；
- 该名字路径在该单元的*导入门*中被*打开*，导入门管辖对该路径成员的限定访问（§3.6）。

项目单元自动打开同一目录中所有项目单元的路径；对它们的限定访问无需导入。经搜索路径内联进来的库单元不自动打开任何东西：它只看见自己显式导入的内容。

通配形式`import p.*;`在项目自身的单元中打开`p`以及`p`之下递归的每个模块路径。通配没有匹配到任何项目单元时是编译期错误；`p`指代库包时也是编译期错误——库包是单一单元，所以`import p;`是唯一有意义的形式。通配永远达不到外部编译模块，它们的名字是单段的（第12章）。

对一个既解析不到项目单元、也解析不到库包或外部模块的路径做导入，是编译期错误。对同一路径导入多次——无论来自一个还是多个单元——是幂等的。

## 3.4 using指令

using指令跟在导入表之后、顶层成员之前（§3.1）。语法见§2.2；两种形式是：

```nlang
using Buffer = FileStream;   // alias form
using utils;                 // scope-opening form
```

别名形式`using Name = Type;`在整个编译单元内把`Name`绑定为该类型的另一个名字。第4章定义类型别名及其展开。别名名在一个编译单元内被声明两次，或与本单元的某个顶层声明、库索引中的内建类型名、内建类名、库包名冲突时，是编译期错误。别名可以与另一个编译单元的声明同名：别名在单元合并之前、于自身单元内展开。

开域形式`using Name;`命名一个包：`Name`解析到非包，或什么都解析不到时，是编译期错误。

*资料性：*在当前实现中，没有裸标识符指代一个包——包只能经导入路径与限定名到达——所以开域形式今天总被拒绝。语法保留该形式，留给将来让包名获得裸拼写的提案。

## 3.5 作用域

*作用域*是程序中一个名字指代其声明的区域。NLang有三种作用域：

- *程序作用域*：本次构建中每个编译单元的顶层成员（§3.1）；
- 每个函数的*函数作用域*：它的参数，以及其体最外层块的声明；
- 每个花括号段的*块作用域*（§2.5）：直接写在其中的声明。

声明从其声明语句起可见，直到所在作用域结束；在声明之前引用局部名字是编译期错误。局部声明语句`T x = e;`在该语句处绑定`x`，并在语句顺序的这个时点求值`e`（第6章）。

在一个函数内，存储绑定到名字而非声明：重新声明一个已在某外层块或先前的兄弟块中声明过的名字的块，复用同一份存储；经由内层声明的写入，在内层块结束后仍可经由外层名字观察到。以不同类型重新声明一个名字是被接受的；此后经由外层名字可观察到的值未指明（§0.4）。

*资料性：*块作用域只约束可见性。将来的提案可能给每个块独立的存储；在此之前，上述共享规则是可观察行为。

## 3.6 名字查找

*裸标识符*是不带限定路径书写的标识符。在值位置，裸标识符按从最内层作用域向外的一次行走解析：先是所在各块，然后是函数作用域，最后是程序作用域。找到的第一个绑定胜出；内层绑定何时遮蔽外层绑定由§3.7规定。

在程序作用域，可见性取决于名字指代什么：

- *顶层函数*只有在它是内建函数、或声明它的单元与发起引用的单元同目录时，才以裸名可见。另一目录中声明的函数不具裸可见性；诊断信息会指明声明它的模块。
- 在顶层声明的*类型*（类、结构体、枚举或接口）在全程序可见，无论其单元位于哪个目录。
- 若行走没有找到任何绑定，裸标识符仍可能解析为一个内建类名；§4.9、§4.10、§9.3与第11章列举内建类。

在类型位置，同一行走限定于类型绑定：一个值绑定不会隐藏一个类型绑定。

*限定名*`p.m`只能经由发起引用的编译单元的导入门（§3.3）到达模块或包`p`的成员：路径`p`必须已被打开——通过显式导入或同目录规则。`p`内部的成员查找不会继续走到外层作用域。第12章完整定义模块命名、路径解析与导入门。

同名函数之间的重载选择在第7章定义。

## 3.7 遮蔽与重新声明

内层绑定遮蔽同名的外层绑定：在内层作用域的可见区域内，裸名指代内层声明。遮蔽只改变可见性；存储遵循§3.5。

- 局部声明可以遮蔽顶层函数名。
- 局部声明复用在声明点可见的类型名时，是编译期错误。
- 同一裸池中两个同类同名的顶层声明冲突，是编译期错误；例外是顶层函数可以重载：同名、不同参数表（第7章）。一个单元的*裸池*是它的顶层函数能以裸名看见的那些单元的集合（§3.6）。
- 不同裸池中的同一函数名或同一类型名是被接受的：这些声明在各自的限定路径下保持独立的身份（第12章）。函数名与类型名只要在全程序任何位置相撞就冲突，无论它们位于哪些裸池。
