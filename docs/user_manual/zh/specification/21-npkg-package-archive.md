# 21. `.npkg`包档案

*包档案*是一次构建的分发形态：它为构建的每个包打包一个*成员*——第20章的单元映像——每个成员以其包路径命名（§12.1）。程序档案携带一条*入口记录*；库档案省去它，且标准库以`stdlib.npkg`分发（§12.4）。§21.1界定范围并固定格式版本；§21.2固定容器；§21.3定义入口记录与成员同一性；§21.4固定成员校验和；§21.5陈述读取与消费契约。

## 21.1 范围与版本

**格式版本。**本章描述格式版本 **1.0**，在头部中记为主`1`、次`0`（§21.2）。读取器接受主号`1`且次号不高于自身的档案——较新的读取器读较旧的次号，绝不反向——并拒绝其他一切版本（§21.5）。格式变更会提升版本并整章替换本章；规范只描述当前版本。

**本章固定的内容。**容器布局（§21.2）、入口记录与成员同一性（§21.3）、成员校验和（§21.4）与读取契约（§21.5）。

**本章不固定的内容。**每个成员内部存放的单元映像——第20章——以及消费被提取映像的链接闭包语义（§12.3）。

**确定性。**同一组成员打包两次产出字节相同的档案：成员按模块路径排序，且头部不记录时间戳。

## 21.2 容器布局

**约定。**同§20.2：小端二进制补码整数与长度前缀字节串；宽度记号`u8`、`u16`、`u32`与`u64`相同。

**头部。**档案以下列内容开始：

| 字段 | 宽度 | 内容 |
|---|---|---|
| 幻数 | 8字节 | `NLANGPKG` |
| 版本主号 | u16 | `1` |
| 版本次号 | u16 | `0` |
| 包名 | u16长度 + 字节 | 构建记录的制品名（输出模块名）；它在诊断中命名该档案 |
| 旗标 | u32 | 写`0`；未定义任何旗标，读取器忽略该字段 |
| 签名算法 | u16 | `0` = 无签名；签名块为预留 |
| 签名偏移 | u64 | `0` |
| 签名长度 | u64 | `0` |
| 成员数 | u32 | |
| 入口 | — | 零字节标记库（无入口记录）；否则为入口记录：u16长度加入口单元的包路径，然后u16长度加入口函数的名称（§21.3） |

**成员表。**紧接头部之后，每个成员一个条目，按模块路径的字节序升序：

| 字段 | 宽度 | 内容 |
|---|---|---|
| 模块路径 | u16长度 + 字节 | 该成员的包路径（§12.1） |
| 偏移 | u64 | 该成员映像字节的绝对文件偏移 |
| 长度 | u64 | 映像字节数 |
| 校验和 | u64 | §21.4 |

**数据块。**写出器按表序把成员映像排在表之后，每个从其记录的偏移开始；读取器跟随记录的偏移，不要求映像相邻。成员的字节就是一张完整的单元映像（第20章）。

## 21.3 入口记录与成员同一性

**入口记录。**程序档案指明其入口：入口单元的包路径与入口函数的名称（当前为`main`，§3.2，§10.3）。库档案改带零标记。在档案内部，只有持有入口的成员映像保留非空入口键（§20.2）；档案的入口记录才是权威入口。

**成员同一性。**每个包路径一个成员：打包器拒绝重复路径。成员的模块路径就是它所容纳单元的包路径，所以对包路径的引用恰好解析到一个成员。

## 21.4 成员校验和

成员的校验和是其精确映像字节的64位哈希，按FNV-1a递推计算：从偏移基数14695981039346656037开始；对每个字节，把该字节异或进哈希再乘以素数1099511628211（2^40 + 435），全部按2^64取模。校验和检测意外损坏；它不是安全原语——§21.2预留的签名块才是它的位置。提取时校验它，不匹配即是同时命名档案与成员的错误（§21.5）。

## 21.5 读取与消费

读取器在使用容器之前先校验它：

- **幻数。**除幻数以外的头部字节 → 拒绝。
- **截断。**越过文件尾的头部或成员表条目 → 拒绝。
- **版本。**除`1`以外的主号，或高于读取器自身的次号 → 拒绝。
- **成员边界。**记录的偏移或长度不在文件之内的成员 → 拒绝，并命名该成员。

提取一个成员时校验其校验和（§21.4）；不是该档案成员的路径即是错误。

编译期，把档案作为外部制品导入（§12.2）取的是提供声明的那个成员：程序档案取入口记录成员，库档案取唯一成员。有多个成员且无入口记录的档案会被拒绝，而不是被静默缩减为一个成员——否则消费方将只对部分接口面编译，到运行期才发现遗漏其余。

运行期，加载器按模块路径提取成员映像，随导入闭包的需要取用（§12.3）。
