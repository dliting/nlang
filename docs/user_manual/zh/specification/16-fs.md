# 16. fs包

`fs`包检查并安排文件系统名称：类型谓词、文件大小、目录列举、目录创建、删除与路径合成。它从不读写内容——内容归`io`包（第15章）。§16.1固定包形态；§16.2定义路径值与`join`；§16.3定义各操作；§16.4固定错误模型。

## 16.1 包形态

`fs`是标准库包（§12.4）：`import fs;`把它带入作用域，每个函数都经包限定符调用（`fs.exists(p)`）。包名是单段的（§3.3）。它的声明是标准库的`.n`源码；每个函数都是`native`函数（§7.5）。实参准入是§15.1的包规则：每个形参都是`string`，所以每个实参都必须是`string`表达式。

除`join`外，每个`fs`函数都是阻塞的原生函数：它声明阻塞段（§11.1），所以在调用等待期间调用上下文停泊、载体锁被释放。`join`合成字符串，不阻塞。

## 16.2 名称与路径

路径实参是平台原生形态的宿主路径；`fs`包不定义自己的路径语法。路径值就是普通的`string`。

`fs.join(a, b)`把段`b`追加到路径`a`之后，以通用形态返回结果：在各平台上分隔符都是正斜杠，且结果是有效的路径实参。命名绝对路径的右段完全取代左段；空的右段留下一个尾随分隔符；空的左段只产出右段。

## 16.3 目录与元数据

- `fs.exists(p)`、`fs.isFile(p)`与`fs.isDirectory(p)`报告`p`是否存在、是否为常规文件或是否为目录。它们从不抛出：无法检查的路径——缺失或不可访问——回答`false`。
- `fs.size(p)`返回`p`处常规文件的字节大小。当`p`不是常规文件、其大小无法确定、或大小超出`int`的值域时，它抛出`IOException`（§9.3）。
- `fs.listFiles(dir)`把目录`dir`中直接位于其中的常规文件的名称以`List<string>`返回：名称不带目录前缀，列举不递归，目录与其他条目被排除，且名称按字典序排序。当`dir`无法打开或读取时，它抛出`IOException`。
- `fs.makeDirs(p)`创建`p`的每一个缺失的目录组成部分；已存在的目录即为成功。当某个组成部分无法创建时，它抛出`IOException`。
- `fs.remove(p)`删除`p`处的文件或空目录。缺失的路径是静默的空操作。当条目存在但无法删除时，它抛出`IOException`。

## 16.4 错误行为

每个会抛出的`fs`失败都抛出`IOException`（§9.3）：抛出位点是§16.3的大小、列举、创建与删除失败。三个谓词从不抛出，而`remove`把缺失的路径当作成功而非失败。

> 实现注记。在Windows上，随包发布的命令行工具在其内嵌清单中把Unicode转换格式（UTF-8）声明为进程的活动代码页，所以非美国信息交换标准代码（ASCII）路径能够往返；在系统代码页下运行VM的宿主受该代码页约束。
