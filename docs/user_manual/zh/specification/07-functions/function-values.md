# 7.4 函数值与委托

函数类型写作`func<R, P1, ..., Pn>`：第一个类型实参是返回类型——函数不返回值时为`void`——其余实参按顺序是参数类型（§2.3）。参数类型实参可以携带`out`前缀。无参数的函数写作`func<R>`。

`void`只作为`func<...>`返回槽的类型实参出现；任何其他写作`void`的类型实参——如`List<void>`——都是编译期错误。

两个函数类型是同一类型，当且仅当它们的返回类型、参数类型与`out`标记逐位置一致。没有变异性：返回类型与参数类型都不允许不同，即使差异只是一次隐式转换也不行（§4.4）。

函数类型的值指代一个函数：自由函数、静态方法，或绑定到某个实例的方法（§5.9）。默认值是`null`；调用`null`函数值是执行期错误。函数值是引用类型，其唯一的隐式转换是到`string`（§4.4）：它不进入`Object`。

引用形式——自由函数、经类型名引用的静态方法、绑定到接收者的实例方法，以及每次调用时迟绑定的虚方法或接口方法——见§5.9。

函数引用只在期望函数类型的地方形成：局部声明、初始化器、赋值、返回、实参、数组元素或花括号条目（§5.8）。没有期望类型时，该引用是编译期错误。所指代的签名必须与期望的函数类型完全一致：没有变异性，参数与结果都不做转换。参数带默认值的函数不能被引用：默认值只在直接调用处填充（§7.2）。枚举方法与原生实例方法不能被引用，带`out`参数的虚方法或接口方法也不能被引用（§7.2）。

绑定引用在值形成时捕获其接收者；经由该引用做的状态改变持续留在接收者对象中。虚方法或接口引用在每次调用时按接收者的运行时类分派（§5.9，§4.8.9，§4.9.4）。

函数值以`v(a1, ..., an)`调用（§5.6）；函数类型的字段以`obj.cb(a1, ..., an)`调用。函数类型的局部遮蔽同名的函数（§3.7）。经由函数值的调用不接受命名实参（§7.2）；`out`实参在调用返回后写回（§7.2）。调用null函数值是可在执行期捕获的错误（§5.6）；在null接收者上形成绑定引用，在形成处抛出可捕获的执行期错误。

两个函数值在`==`下相等，当它们指代同一个函数，且对绑定引用而言携带相等的接收者；`!=`是补集，`== null`是允许的。排序比较是编译期错误。函数值经由`toString`渲染（§5.3，§4.11.2）。

函数值不进入`Object`。它不能作`Dict`的键、`switch`的判别式，也不能作序列化方法的目标（第15章）。

### 函数类型语法

*资料性：*`func`关键字引入函数类型：第一个类型实参恒为返回类型，其余实参按声明顺序是参数类型，每个可选地以`out`前缀。

```nlang
func<int>                  // int f()
func<void>                 // void f()
func<int, int>             // int f(int)
func<void, out int>        // void f(out int)
func<int, int, out int>    // int f(int, out int)
```

### 函数引用

*资料性：*不带括号的函数名或方法名是引用——一等值，可存入局部变量、参数、字段、数组与容器，四处传递，稍后调用：

- **自由函数引用**（`bar`）——指向该函数的静态绑定句柄。
- **静态方法引用**（`Util.twice`）——指向静态方法的无接收者句柄；在所属类内也可用裸名。
- **绑定方法引用**（`c.foo`）——捕获接收者：对象随句柄一起走，其**状态跨调用保持**。
- **虚 / 接口方法引用**（`c.tw`、`ifaceVar.run`）——句柄持有方法名，在每次调用时于接收者的**运行期类**上解析覆写链（晚期绑定）。

```nlang
import io;
using BinOp = func<int, int>;

class Counter {
    int n;
    public static int twice(int x) { return x * 2; }
    public int foo(int x) { n = n + 1; return n + x; }
    public virtual int tw(int x) { return x * 2; }
}
class Big : Counter {
    public int tw(int x) { return x * 100; }
}
int bar(int x) { return x + 1; }
void apply(BinOp f) { io.print(f(10)); }

int main() {
    Counter c = Counter();
    apply(bar);       // 11自由函数
    apply(Counter.twice); // 20静态：无接收者
    apply(c.foo);     // 11绑定：n变为1，1 + 10
    Counter b = Big();
    apply(b.tw);      // 1000虚分派：运行期类Big获胜
    BinOp g = c.foo;
    return g(1) + g(1);   // 状态保持：3 + 4 = 7
}
```

绑定发生在**消费者位点**——即存在期望函数类型的位置：声明/赋值右值（含字段与下标存储）、返回位置、调用实参、容器方法实参（`l.add(bar)`）、初始化列表条目（`[bar]`）。无期望函数类型的引用是编译错误，诊断会点名该引用。

### 调用

*资料性：*两种调用形状：

- **裸标识符**——`f(x)`。`func`类型的局部变量/参数/字段**遮蔽**任何同名函数。
- **成员字段**——`obj.cb(x)`，其中`cb`是`func`类型的字段。

实参按`func`类型的签名暂存；`out`参数在调用后写回调用者的局部变量；绑定方法的接收者由调用自动处理。委托调用不支持具名实参。

### 相等、null、toString

*资料性：*`f == g` / `f != g`比较**句柄内容**（目标 + 接收者 + 形式）：指向同一函数的两个引用相等。`f == null`与`f != null`合法。排序比较（`< <= > >=`）以及与`func`之外操作数的比较是编译错误。

- `f = null`存入空句柄；**调用它在运行期抛出空指针异常**。在**null接收者**上绑定引用（`Counter c = null; register(c.tw);`）在绑定时刻抛错。
- `f.toString()`、`f as string`、`"" + f`、`io.print(f)`与容器格式化产生的字符串形式为`"func <name>"`（静态句柄——含绑定的非虚方法引用）或`"method <name>"`（虚分派句柄）。
- **已知不一致**：`List<func<...>>.contains` / `indexOf`按**恒等**比较元素（每个引用都是独立的堆记录），不按`==`的内容相等。

### 限制

*资料性：*下列每一项都是编译期错误：

- 引用签名与期望`func`类型不精确匹配的函数/方法。
- 引用带**默认参数**的函数或方法——默认值只在直接调用路径上填充。
- **静态方法引用**——静态方法经类型名（`Util.twice`）绑定为函数值，含继承的静态方法、接口静态方法、native静态方法，以及所属类内的裸名形态；经对象接收者（`b.twice`）仍被拒（"the static method must be called through the type name"）。
- **经类型名的实例方法**——被拒（"the instance method must be called through a receiver object"）。
- **枚举方法**——接收者是int值，不是堆对象。
- **native实例方法**的任何可达形式：声明为`native`、虚基类下的覆写、或接口成员的实现（native调用没有供接收者使用的被调方栈帧）。native静态方法可经类型名引用。
- **`func`类型带`out`参数的虚/接口引用**——运行期分派可能与编译的out掩码不一致。
- **返回位置的`out`**（`func<out int, ...>`）——报出明确的编译错误"out is only allowed on func<...> parameters."并拒绝。
- **`func<...>(...)`**——不支持以名称构造；请绑定引用。
- **`Dict<func<...>, V>`**——`func`作Dict键（见上文恒等说明）。
- **装箱成`Object`**（`Object o = f`，见[Object与装箱](../04-types/object.md)）——经泛型的不兼容类型诊断拒绝。
- **`func`之外的`void`或`out`类型实参**（`List<void>`、`List<out int>`）。
- 函数值作`switch`判别式（没有case家族能匹配）。
- 函数值不能穿过序列化方法——对持有`func`字段的struct/class调`writeStruct` / `writeObject`是运行期错误（第15章）。
