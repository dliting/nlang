# 内存管理

规范性规则见规范第10章。
NLang是垃圾回收语言：没有`delete`，也没有可调用的释放函数——对象在不可达后由垃圾回收器自动回收，无需手动释放内存。本页描述堆的布局与回收机制。


### 堆布局

所有struct与class对象共享单一堆。每个堆槽位是一个32位整数序列：

- **struct槽位**：`[field0, field1, ...]`（没有类型头）
- **class槽位**：`[类型ID, field0, field1, ...]`（首格存运行期类型标识符（ID，identifier））

堆索引0是哨兵（null/无效）。有效索引从1开始。

### 垃圾回收

NLang对堆记录（class、struct、数组与函数值）以及字符串对象使用标记-清扫垃圾回收器。字符串对象存放在独立的字符串对象仓中（不在该堆内），但与堆记录共用同一次标记-清扫循环：

1. **触发**：垃圾回收（GC，garbage collection）在安全点运行，条件是回收请求待决，且堆大小超过阈值或字符串对象仓大小超过其独立阈值（字符串对象仓的阈值随每次清扫退避到不低于存活数的2倍——只升不降）。安全点是函数入口、循环回边与线程派生（`thread.spawn`）。
2. **标记阶段**：精确扫描帧内的引用槽位。参数槽按局部变量描述符（源码中称`LocalDescriptor`）扫描——声明为引用种类（class、struct、数组或函数记录）的参数会被扫描；字符串参数则按句柄标记字符串对象；基本类型永不扫描。进行中的返回值槽按函数声明的返回种类同样扫描。帧内其余全部槽位——用户局部变量、临时槽池、嵌套调用实参暂存、求值暂存区——由随函数记录序列化的句柄位图分类：每槽为标量（不测试）、字符串句柄、堆索引或未知（双域值测试）；回收器只测该类别对应的域，位图不依赖帧布局的逐字节知识——未知类别槽位的值落入哪一有效域即按该种类标记，垃圾回收不移动对象，误标只造成暂留，不会误收。class/struct的字符串字段、字符串数组元素、容器中装箱字符串的内容以及拼接节点的子节点同样作为字符串根被标记；停泊中的虚拟线程帧栈、通道缓冲元素、宿主持有的引用以及在途阻塞原生暂存的实参格与返回槽也是根（见[垃圾回收设计](../vm-architecture/garbage-collection-design.md)）。标记使用迭代式工作列表（非递归），避免深对象链上的栈溢出。
3. **清扫阶段**：未标记的引用记录（class、struct、数组、函数）被释放。class持有的struct字段（值语义）随其宿主class一起释放。class字段（引用语义）不可达时由GC独立释放。字符串对象仓在同一次收集中独立清扫：随模块执行物化的常量对象（常驻）永不回收；被回收的驻留短串同步净化驻留表条目。
4. **空闲表**：被清扫的槽位进入空闲表。新分配优先复用空闲槽位（字符串对象仓维护自己的空闲表）。

**设计决策**（与源码的对应关系见`VmExecutor.h`的注释）：
- 由安全点触发，而非由分配点触发（避免在标记阶段追踪暂存槽）
- 参数槽按局部变量描述符精确扫描；帧内其余槽位带（含用户局部变量）由句柄位图分类（标量/字符串句柄/堆索引只在各自域内测试，未知类别保留双域保守值测试；GC因此不依赖帧内布局的逐字节知识，暂存值也绝不漏标）
- 一张与堆槽位平行的struct类型索引表识别struct类型（struct没有类型头；比添加类型头改动更小）
- 迭代式标记 + 工作列表，而非递归（深对象链会溢出C++调用栈；内存用量为O(可达对象数)）

### struct生命周期

struct的生命周期与宿主绑定（值语义）：
- 局部struct变量：存活到函数返回（或变量被重新赋值——旧记录随即不可达，由下一次回收释放，其持有的嵌套struct递归释放）
- class持有的struct字段：宿主class对象被GC清扫时释放
- struct持有的嵌套struct：随父级递归释放
