# 已知限制

本页汇总语言层面对用户程序可见的限制与可行的替代做法；虚拟机层面的限制见[虚拟机已知限制](../vm-architecture/known-limitations.md)。

### 类型、数组与集合

- **泛型类声明仅签名面（全native成员）**：`class Box<T> { ... }`声明被接受，但只承载签名——成员必须是native方法，泛型体内的nlang方法体、字段初始化器、参数默认值一律在编译期被拒绝；无宿主绑定的native成员能编译通过，运行期才报`native function not registered`。日常泛型请用内建容器（`List<T>`、`Dict<K,V>`、`Channel<T>`、`Future<T>`）与预置`Promise<T>`。

- **string → 数值的`as`被禁止**：`"5" as int`是编译错误（``Invalid cast: `String as Int32` is not allowed``）。等价功能由string方法族覆盖（`toInt`/`toLong`/`toFloat`/`toDouble`/`toBool`/
  `toChar`，见[string方法](stdlib-string.md)）；本条是有意的规格缩窄，不是缺陷。

- **标量上下文中的数组值**：数组值只有两类合法去向——自身数组类型（元素类型必须完全一致），与**全部**位置上的`string`目标；`null`恒可转换到数组目标；比较恒为恒等比较；其余用法一律在编译期被明确拒绝。

  细则：`string`目标覆盖整值位置与元素槽——string局部变量与字段、返回、拼接、string形参（`f(arr)`）、`io.print(arr)`、数组下标（`string[] sa; sa[0] = arr`）与容器存储（`List<string>`下标与`.add`），都经运行期toString强制转换（得`"[1, 2]"`）；比较只对另一个数组或`null`做`==` / `!=`。拒绝清单：标量、class、interface、`Object`目标，`as`强制转换（`ia as int`），非数组形参，数值二元操作数（`arr + 1`），关系或跨类型比较（`arr < arr2`、`arr == 5`），条件位置（`if (arr)`），`switch`判别式，方法接收者。跨元素与表示互通的数组转换同样拒绝：`string[] b = ia`、协变上转型`Base[] ba = da`、`enum[]`与`int[]`互转都以"an array value only converts to the same array type"失败。从`List<T[]>` / `Dict<K,T[]>`取出的元素遵循同一规则；其数组性对编译器可见——作方法接收者或`switch`判别式（`li[0].rank()`、`switch (li.get(0))`）会被明确拒绝，`foreach`可以把它们迭代进数组类型的循环变量（数组值源可直接使用且只求值一次），以数组类型为键的`Dict`按句柄恒等比较。

- **锯齿数组（`T[][]`）**：多维数组声明在编译期被拒绝（"jagged arrays (T[][]) are not supported"）——局部变量、字段、参数、返回类型、`for`/`foreach`循环变量以及泛型类型实参位置都是如此。VM没有多维数组布局；请声明扁平数组，或改用`List<List<T>>`式容器。

- **裸`{...}`作方法调用接收者**：裸花括号字面量需要带类型目标——作接收者（`{}.length()`）时没有目标，仍被拒绝；请先绑定一个带类型局部。命名实参可推断（`count(items = {1, 2})`）。见[集合初始化器](collection-initializers.md)。

- **空数组字面量**：空字面量对`List<T>`与`Dict<K,V>`目标写作`{}`（`List<T> l = {};`、`Dict<K,V> d = {};`）。数组目标无花括号形式（`int[] a = {};`被拒绝——数组初始化用方括号形式），空数组写作`int[] a = [];`。

- **定长数组声明：尺寸只能写在首个声明符上**：`int a, b[3];`是语法错误——`b`请单独声明。

- **直接初始化的括号形式仅限首个声明符**：`Vec a, b(2);`是语法错误——`b`请单独声明（本页`Vec`指带构造函数的类型示例，见[类](class.md)与[结构体](struct.md)）。

- **混合声明符继承数组类型**：`int a[3], b;`中的兄弟`b`是null的`int[]`（数组类型），不是int。

- **部分初始化是声明位的方括号形式**：`int b[100] = [7, 8];`余位零填充；定长声明上的花括号形式（`int b[100] = {7, 8};`）是语法错误。

- **泛型元素定长数组仅声明形态**：`List<int> a[2];`声明数组；表达式位没有对应的创建形式。

- **`using`别名声明属于文件序言区**：`using`放在其他顶层声明之后是语法错误。

- **`List<struct>`值语义**：把同一个struct变量加入List两次，存入的是同一个底层对象（struct进入容器时按引用存储）。需要独立元素请使用各自的struct实例。

- **创建成本**：`Point[n]`在创建时分配n+1个堆对象（数组本体 + 每元素一个struct）。

- **参数数上限**：超过64个参数的函数（合理性上限）触发编译期错误。除此之外，每个函数的栈帧大小按函数体内的实际使用动态确定。

### 类、接口与模块

- **`List<func<...>>.contains` / `indexOf`用恒等比较**：指向同一函数的两个引用是不同的堆记录，因此新建的引用永远不会`contains`匹配已存储的引用。与`==`（内容相等）的不一致已记录在案。

### 类、接口与模块

- **接口方法的默认参数**：接口方法声明上的默认值合法，按调用点的静态类型解析——接口类型调用省略实参时填充的是接口声明上的默认值（即使实现方法另声明了不同的默认值）；实现方法的默认值不参与接口分派，接口声明未带默认值时调用仍须提供全部实参。覆写与实现签名比对不比默认值（声明带默认值、实现不带同样满足契约）。

- **默认值的方法继承**：派生类覆写不继承基类方法的默认值。每个覆写独立声明自己的默认值。

- **导入struct的实例字段跨模块不可访问**：导入的struct只有类型声明、不带字段布局——对导入struct读写`s.x`是编译错误。构造（`lib.Vec(3, 4);`）与把值传给生产方自己的函数可用，struct字段默认值在分配时照常应用。

- **枚举不能跨模块导入**：`enum`不作为模块成员导出——限定引用（`lib.Color.Red`）报`Type 'Color' is not a member of package 'lib'.`。

- **顶层直接初始化的首实参被当作类型解析**：`Vec p(base.x);` / `Vec p(a<b);`的首实参以标识符开头且该标识符后跟`.`或`<`时，会被当作类型（限定名或泛型）来解析，从而报一条明确的语法错误。仅首实参受影响——调用表达式（`Vec p(f());`）、下标（`Vec p(g[0]);`）与其后每个实参都可正常解析，函数体内不受影响。变通：改用赋值初始化`Vec p = Vec(base.x);`。

- **没有lambda表达式 / 闭包**：只存在对具名函数与方法的引用。绑定方法引用携带接收者状态，覆盖常见的回调场景。

- **`const`引导的顶层函数**：`const int f(){}`不可解析，因为`const`入口与const语句走同一条语法路径，前缀`const int f(`与`const int x =`无法区分。`const int x = 5;`正常；顶层const函数目前没有合法写法（函数体内不受影响）。

### 并发

### 函数与语句

- **跨模块同参数数重载**：导入的自由函数、接口静态方法与枚举方法按名字 + 参数数匹配；同名同参数数但参数类型不同的两个重载在链接期报显式歧义错误，而非静默错链。

- **`super()`只直达直接父类**：没有直接调用祖父构造函数的语法；每个构造函数只转发给自己的直接父级。

- **`implements限定名.接口`形式不被文法接受**（如`implements lib.IF`）：须先`import`再用非限定名。

### 函数与语句

- **finally体内没有控制流**：`finally`体内出现`break` /
  `continue` / `return` / `throw`是编译错误（finally体不得吞掉在途的控制流或异常）。

### 并发

- **并发：main返回即结束**：`main`返回时仍挂起或排队的虚拟线程被静默丢弃——没有隐式的等待全部；需要完成顺序请显式`thread.join`。运行队列排空而main仍未完成时虚拟机报告死锁错误。见[并发](concurrency.md)。

- **并发：存储按类别加锁，同类串行**：堆与字符串分配按载体各自进行、不加锁，对象字段读写不加锁；容器（List/Dict）、同步原语、流与字符串维护各持一把锁——同类操作互斥，跨类并行。纯计算段与对象字段访问可跨载体并行，但依赖容器或字符串维护的密集循环仍在对应的锁上串行；共享对象（经`spawn`实参或通道共享）的字段并发读写属于数据竞争——可能读到过渡值，单值状态用`AtomicInt`（见[AtomicInt](concurrency-atomic.md)），多字段不变式用`Mutex`协调。每个虚拟线程连续执行约1000次循环迭代让位一次，保证公平轮转。载体数经`VmExecutor::SetCarrierThreadCount`（嵌入宿主，默认1）或`nvm --carriers=N`（工具，默认至多4）调节。见[载体与并行](concurrency-carriers.md)。

- **并发：多载体下调度顺序未指定**：单载体（库默认）完全确定——同一程序重复运行产生相同的交错顺序；多载体下调度器可按任意顺序取项（为缓存局部性优先取上次执行过的），交错顺序不保证，程序正确性只依赖`join`、通道与互斥的happens-before（先行发生）。见[并发](concurrency.md)。

- **并发：调试暂停为全停**：调试器停机时阻止新的虚拟线程开始执行——正在执行的段跑完后停住，停机期间不再有虚拟线程推进；到期定时器可能已在停机期间入队，但一律等到恢复后才开始执行（时间冻结语义）；挂起上下文的调用栈与局部变量停机时可查。`ndb`固定单载体执行，保证步进与断点的确定性；多上下文检查见[ndb](../cli-tools/ndb.md)。

- **并发：没有`await`关键字**：函数不做异步着色（见[并发](concurrency.md)的模型一节）；`Future.get()`就是阻塞式等待，`thread.join`等待无返回值的`Thread`。

- **并发：多路等待限于`Future`域**：`Future`可经`Promise`手工完成（[Promise](concurrency-promise.md)），`Future.selectAny`提供「任意一个先决定」的多路等待；但通道上没有「任意一个就绪」的`recv`变体——多源通道要任意收，须为每个源经`Promise`组合一层再对`Future`数组`selectAny`。

- **并发：派生线程的失败不传播给宿主或main**：未捕获异常被遏制在失败上下文内。等待侧经`join`/`Future.get`观测失败（原异常对象的重抛）；非阻塞观测走`thread.isFailed`/`thread.failure`（见[探测任务失败](concurrency-thread.md#探测任务失败)）。无人等待也无人取回的失败不会无声丢失：运行结束时VM对每个这样的任务在stderr打一行（任务id、异常类型与消息）。

- **并发：`Mutex`不可重入**：互斥体不可重入，持有期间再次`lock`会挂起直至死锁报告——方法组合或递归场景请用[ReentrantMutex](concurrency-reentrant-mutex.md)。见[Mutex](concurrency-mutex.md)。

- **并发：无载体宿主窗口内不能挂起**：run**进行期间**的重入求值——集合格式化时调用`toString`覆写、运行中触发的宿主回调——各等待点与别处一样正常挂起。只有嵌入宿主在run**之外**经`call()`发起的窗口没有在飞载体来服务等待，那里`yield`/`sleep`/未完成的`join`/未完成的`Future.get`/竞争中的`lock`/零许可`acquire`/空通道`recv`/有界通道满时的`send`/`spawn`一律以"cannot suspend"运行期错误拒绝。阻塞原生调用不受此限：发起调用的虚拟线程挂起并放锁，等待期间其他载体照常运行。

- **并发：并发阻塞受载体池规模上限**：声明为阻塞的原生调用挂起发起调用的虚拟线程并放锁，执行期间其余载体继续运行其他虚拟线程；同时在阻塞中的原生调用数受载体池规模限制，超出时最坏退化为排队等待。未声明阻塞的原生按约定不得等待——第三方原生违规等待只会占住执行它的那个载体，其余载体照常运行；补上阻塞声明即可挂起放锁。输出重定向回调不持全局锁，并发输出经控制台互斥量串行，保持回调短小可减少排队。见[载体与并行](concurrency-carriers.md)。
