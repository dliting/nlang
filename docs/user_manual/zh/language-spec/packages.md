# 包

规范性规则见规范第12章。
**包**是NLang的代码身份单位。每个`.n`文件就是一个包，包名只有一个来源：文件相对其匹配搜索根的路径。文件内没有任何为包命名的语法。

```nlang
// stdlib/io.n            -> 包 "io"
// <根>/vendor/graphics.n（配 -I <根>）-> 包 "vendor.graphics"
// <根>/gfx/color/deep.n  （配 -I <根>）-> 包 "gfx.color.deep"
import io;
import vendor.graphics;
import gfx.color.deep;
```

## 限定名

包声明的一切都可以通过限定名访问——`包.成员`（点分包则是`包.子包.成员`）。导入只开放限定名：`import lib;`之后写`lib.f()`，裸名`f()`不会经由导入解析。（与调用方同目录的文件共享该目录的裸名池——同目录规则不变。）

限定类型名同样这样拼写：`alib.Point`、`gfx.color.deep.Shade`。与函数不同，类型在全程序内还可以裸名访问，无论由哪个包声明（规范§3.6）。末段相同的两个包（`a.io`与`b.io`）是两个不同的包，各自的函数与类型互不相串；同一次构建内每个点分包名只能存在一份——两个单元解析出同一包名是编译错误，诊断指名两条来源路径。

## 编译产物与限定表键

每个包编译为一幅独立的**单元映像**（`.ncu`，格式v2.9），映像里每个struct/class/函数表键都**带包名限定**：`main.main`、`utils.helper.help`、`alib.Point`。无属主的内建保持裸键（`Object`、`List`）。对其他包的引用以**导入槽**记录（目标模块路径 + 限定名），执行时由加载器沿搜索路径装齐整个引用闭包、按限定名链接成唯一的运行期模块——跨包符号在产物里没有实体，只有名字。凡指名符号之处，限定键就是调试器与工具的统一拼写：

- 断点写限定名：`b main.main`、`b mathutil.triple`；
- 回溯与停止行打印限定名：`#0  main.main (main.n:6)`、`Stopped: utils.helper.inner (helper.n:6)`；
- `ndisasm -func main.main`按同一拼写过滤；
- 函数类型的值格式化为其键：`func alib.twice`。

面向读者的值的格式化输出——对象的默认`toString()`（`Point@1a2b`）与调试器的值显示（`Point{x=2, y=5}`）——用**末段名**：限定键的最后一段，即源代码书写类型的原名。限定键仍是链接（链接期、流、反汇编）的拼写；值的格式化输出展示的是类型本身，不是它的链接身份。

跨模块边界上重载同样按参数类型解析：当一个包声明了两个同名同参数数但参数类型不同的函数时，调用点按类型的选择会传到链接器，链接器把每处调用连到被选中重载自己的记录。因此导入的重载集精确链接，没有按名字＋参数数的歧义。见[重载解析](overload-resolution.md#跨模块重载)。

## 流与字面量

`readStruct`/`readObject`以字符串取类型名。该字面量在**编译期**按本文件可见的包（自身包＋已导入的包）定身，并改写为声明的限定表键，到达VM的永远不会是裸名。两个可见包声明同名类型时字面量有歧义——编译错误要求写限定形（`readStruct("alib.S")`）。对象流同样存限定类键：一个程序写出、另一个程序读入的对象必须来自相同的包布局，因为读取端按键直接查表。

## native声明

`native`声明的宿主动态链接库（DLL，dynamic-link library）按包的**首段**命名（`nlang_<段>.dll`），因此多段包（`gfx.color.deep`）里的`native`无法命名宿主库，会在编译期得到诊断。单段包中的`native`声明按上述规则命名宿主库。

## 限定类型上的泛型

内建泛型容器支持类型实参（`List<int>`、`Dict<string, int>`）。带类型实参的限定**用户**类型（`alib.Box<int>`）不是语言的一部分：解析器以syntax error拒绝该形状。
