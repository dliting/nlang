# 内存管理


### 堆布局

所有 struct 与 class 对象共享单一堆。每个堆槽位是一个 32 位整数
序列：

- **struct 槽位**：`[field0, field1, ...]`（没有类型头）
- **class 槽位**：`[类型ID, field0, field1, ...]`（首格存运行期
  类型 ID）

堆索引 0 是哨兵（null/无效）。有效索引从 1 开始。

### 垃圾回收

NLang 对堆记录（class、struct、数组与函数值）以及字符串对象使用
标记-清扫垃圾回收器。字符串对象存放在独立的字符串对象仓中（不在
该堆内），但与堆记录共用同一次标记-清扫循环：

1. **触发**：GC 在安全点运行，条件是回收请求待决，且堆大小超过阈值
   或字符串对象仓大小超过其独立阈值（字符串对象仓的阈值随每次清扫
   退避到存活数的 2 倍）。安全点是函数入口与循环回边。
2. **标记阶段**：经局部变量描述符（源码中称 `LocalDescriptor`）精确
   扫描——声明为引用种类的局部槽位（及进行中的返回值槽位）会被扫描
   ——class、struct、数组或函数记录；字符串局部与字符串返回槽则按
   句柄标记字符串对象；基本类型永不扫描。class/struct 的字符串字段、
   字符串数组元素、容器中装箱字符串的内容以及拼接节点的子节点同样
   作为字符串根被标记。没有保守字节扫描（与栈帧物理布局解耦）。标记
   使用迭代式工作列表（非递归），避免深对象链上的栈溢出。
3. **清扫阶段**：未标记的引用记录（class、struct、数组、函数）被
   释放。class 持有的 struct 字段（值语义）随其宿主 class 一起释放。
   class 字段（引用语义）不可达时由 GC 独立释放。字符串对象仓在同
   一次收集中独立清扫：随模块执行物化的常量对象（常驻）永不回收；
   被回收的驻留短串同步净化驻留表条目。
4. **空闲表**：被清扫的槽位进入空闲表。新分配优先复用空闲槽位
   （字符串对象仓维护自己的空闲表）。

**设计决策**（与源码的对应关系见 `VmExecutor.h` 的注释）：
- 由安全点触发，而非由分配点触发（避免在标记阶段追踪暂存槽）
- 按局部变量描述符精确扫描，而非保守字节扫描（把 GC 与栈帧物理
  布局解耦）
- 一张与堆槽位平行的 struct 类型索引表识别 struct 类型（struct
  没有类型头；比添加类型头改动更小）
- 迭代式标记 + 工作列表，而非递归（深对象链会溢出 C++ 调用栈；
  内存用量为 O(可达对象数)）

### struct 生命周期

struct 的生命周期与宿主绑定（值语义）：
- 局部 struct 变量：存活到函数返回（或变量被重新赋值——届时旧
  struct 持有的嵌套 struct 由深拷贝逻辑释放）
- class 持有的 struct 字段：宿主 class 对象被 GC 清扫时释放
- struct 持有的嵌套 struct：随父级递归释放
