# 已知限制


- **用户自定义泛型**：不支持 `class Foo<T> { ... }`。编译器只识别
  内建泛型类（`List<T>`、`Dict<K,V>`）。
- **标量上下文中的数组值**：数组值只有两类合法目标——自身数组类型，
  与赋值、返回、字符串拼接位置上的 `string` 目标（运行期 toString
  强制转换，得 `"[1, 2]"`）。string 目标是整值位置——string 局部
  变量与字段、返回、拼接；而元素槽——数组下标（`string[] sa;
  sa[0] = arr`）与容器下标存储（`ls[0] = arr`）——与任何标量槽
  一样拒绝数组值。数组目标在元素层面以隐式转换表判定：
  `string[] b = ia` 与任何跨元素伪装一样被拒绝；子类元素数组可
  上转型为基类元素数组（`Base[] ba = da`，协变别名——见下方
  「协变数组存储无检查」）；`enum[]` 与 `int[]` 因表示恒等互通。
  其余值位置
  一律是编译期拒绝：赋值或返回到标量、class、interface、`Object`
  目标，用 `as` 强制转换（`ia as int`），或传给非数组形参
  （包括 `string` 形参）都会以具名错误失败，而不是存入裸句柄。从
  `List<T[]>` / `Dict<K,T[]>` 取出的元素遵循同一规则；其数组性对
  编译器可见——作方法接收者或 `switch` 判别式
  （`li[0].rank()`、`switch (li.get(0))`）会按名被拒绝，
  `foreach` 可以把它们迭代进数组类型的循环变量，以数组类型为键的
  `Dict` 按句柄恒等比较。
- **协变数组存储无检查**：通过上转型别名存储（`Base[] ba = da;`
  之后 `ba[0] = new Base()`）编译期与运行期都通过——`Derived[]`
  槽位会静默存入 `Base` 对象（没有 ArrayStoreException 等价物）。
  请通过原类型的别名存储。
- **string 下标能编译、运行期失败**：读或存储位置的 `s[0]` 可以
  编译，但程序以 "null array access" 中止——string 是不可变对象，
  没有元素索引。请改用 `string.substring` / `string.indexOf`；
  编译期拒绝已在计划中。
- **锯齿数组（`T[][]`）**：多维数组声明在编译期被拒绝
  （"jagged arrays (T[][]) are not supported"）——局部变量、字段、
  参数、返回类型、`for`/`foreach` 循环变量以及泛型类型实参位置都是
  如此。VM 没有多维数组布局；请声明扁平数组，或改用
  `List<List<T>>` 式容器。
- **裸 `{...}` 集合初始化**：dict/struct/class 初始化要求显式的
  `new Type{...}` 形式（裸 `{...}` 形式与块语句文法冲突）。见上文
  「集合初始化器」。
- **裸 `[]` 空初始化**：请改用 `new List<T>{}`、`new Dict<K,V>{}` 或
  `new int[0]`。词法分析器把 `[]` 切成单个记号，供数组类型后缀规则
  使用。
- **右移运算符（`>>`、`<<`）**：未实现（无文法产生式，无指令）。
  泛型上下文之外的 `>>` 是编译错误；泛型收尾位置上它被拆成 `'>'`
  记号（见 `List<T>` 下的「嵌套泛型」）。
- **裸初始化列表作函数实参**：要求 `new Type{...}` 显式形式。
- **`List<struct>` 值语义**：把同一个 struct 变量加入 List 两次，
  共享的是底层堆槽位（装箱层是引用语义）。需要独立元素请使用各自
  的 struct 实例。
- **接口类型的 `Dict<K,V>`**：接口类型不支持作泛型类型实参。请使用
  具体类类型。
- **嵌套下标接收者写**：在
  `matrix[i][0].x = v`（数组的数组的 struct）中，接收者内层下标索引
  的求值可能覆写右值临时槽位。单层 `arr[i].field = v` 工作正常。
- **急切物化的成本**：`new Point[n]` 在创建时分配 n+1 个堆槽位
  （数组 + 每元素一个 struct）。
- **被导入函数的默认参数**：跨模块被导入的函数只支持**可常量
  折叠**的默认值——int / float / string / null 字面量，外加数值
  字面量的单次取负（`-5`、`-3.14`）。复杂默认值（`b = a` 之类的
  标识符引用、`b = helper()` 之类的函数调用、强制转换、一元 `-`
  之外的二元表达式、`this.field` 引用）在**消费侧**以编译错误
  拒绝。生产方（被导入模块）接受任何默认表达式；限制只在消费方
  导入该函数时生效。跨模块复杂默认值的变通：在生产方模块里写一个
  只带字面量默认值的包装函数，让消费方调用该包装。
- **被导入函数的具名实参**：跨模块具名实参（`foo` 是被导入函数时的
  `foo(b = 5, a = 3)`）不支持。消费侧桩使用占位形参名
  （`p0`、`p1`、……），因为 `.nmod` 格式不携带形参名。调用被导入
  函数时请只用位置实参。
- **接口方法的默认参数**：接口方法声明（无函数体）不解析其默认值。
  调用方必须提供全部实参。
- **默认值的方法继承**：派生类覆写不继承基类方法的默认值。每个
  覆写独立声明自己的默认值。
- **参数数上限**：超过 64 个参数的函数（合理性
  上限）触发编译期错误。除此之外栈帧布局是动态的——调用参数区
  与求值暂存区按函数体内观察到的实际调用模式定尺寸。
- **finally 体内没有控制流**：`finally` 体内出现 `break` /
  `continue` / `return` / `throw` 是编译错误（finally 体不得吞掉
  在途的控制流或异常）。
- **`super()` 只直达直接父类**：没有直接调用祖父构造函数的语法；
  每个构造函数只转发给自己的直接父级。
- **`C` 无构造函数时 `new C(args)` 静默丢弃 `args`**：与显式
  `super(args)`（会报错）不同，类未声明构造函数时，分配点上的
  构造实参被丢弃。
- **没有 lambda 表达式 / 闭包**：只存在对具名函数
  与方法的引用。绑定方法引用携带接收者状态，覆盖常见的回调场景；
  带捕获的 lambda 是未来方向。
- **`List<Func>.contains` / `indexOf` 用恒等比较**：指向同一函数的
  两个引用是不同的堆记录，因此新建的引用永远不会 `contains` 匹配
  已存储的引用。与 `==`（内容相等）的不一致已记录在案。
- **跨模块函数值被拒绝而非搬运**：引用被导入的函数，或把函数引用
  传给被导入的函数，都是编译错误（`.nmod` 不序列化参数签名）。解除
  此限制需要模块格式中的签名表。
