# NLang 设计改进备忘

写文档、做探针时对 NLang 设计与实现合理性的观察记录。这里只登记问题与改进方向,不改动语言本身;后续版本规划(roadmap)从这里取材。

条目格式:日期 / 位点 / 现状(实测或代码为证)/ 问题 / 改进方向。同一位点再发现时追加说明,不另开条目。

## 1. `Dict.keys()` 的顺序与名称不符(2026-11-01)

- 位点:`Dict<K, V>.keys()`(标准库字典类)。
- 现状:实测(`temp/probes/dict_keys_order.n`)与实现(`INTR_Dict_Keys` 按内部向量序拷贝)均为插入序;e2e `dict_tostring_insertion_order.n` 钉住该行为。
- 问题:`keys()` 之名不携带任何顺序信息,与 `Dict` 组合容易被读成"按字典(键)顺序";插入序这一关键语义只存在于实现里,调用方无从预期。文档合并裁决已按"文档从实现"写明插入序(spec D5#2),但名称本身仍是设计上的含糊点。
- 改进方向:二选一——(a)维持插入序,在类文档与命名上让顺序语义显式化(如文档强调"迭代序=插入序",与 Python 3.7+ dict 先例一致);(b)若确需有序遍历,另提供排序视图(如 `sortedKeys()`)。待将来版本规划时定夺。
