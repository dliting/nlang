# 值类型引用（&）设计

> 2026-11-07。方案裁定：在「A 全引用转向」与「C 值语义＋显式引用」之间选择C——
> struct等值类型的移动语义保持值语义（默认独立），引用能力以`&`显式引入。
> 本设计吸收已知限制清单第26项（`List<struct>`元素匹配恒失败）与第4项
> （用户泛型拒绝struct类型实参）的解决路径。

## 1. 背景与动机

struct现行语义为值语义：赋值、传参、返回、容器出入的每个边界都深拷贝
（`OP_CopyStruct`分配新记录）。已验证的三个问题：

1. **容器元素匹配恒失败**：存储边界深拷贝产生新记录，而`contains`/`indexOf`/
   Dict键按记录身份比较——值相等的元素永远匹配不上（七探针实证，
   temp/struct-alias-probe/）。
2. **用户泛型拒绝struct类型实参**：编译期报错（v0.12.3 staging限制）。
3. **隐藏拷贝开销**：每次赋值分配新堆记录并逐字段复制。

方案A（全引用转向）以别名默认化一条规则解决全部三项，但要求手册全树翻转、
放弃「拷贝独立」的用户预期。方案C保留值语义默认，引用按需显式，迁移面小
一个量级，本设计采纳C。

## 2. 目标与非目标

**目标**：

- `&`引用声明三位置：局部绑定、形参、返回值；
- `&`覆盖全部按槽拷贝移动的类型（标量、enum、struct、string），身份引用
  类型上`&`为等价记号；
- 容器元素别名（`MyStruct &e = list.get(0)`写穿透容器）；
- 用户泛型接受struct类型实参；
- 容器元素匹配修复（值比较，见§3.8）；
- **out参数退役**：`&`形参全面取代（见§3.10）。全部改动不向下兼容
  （既定裁定），以合理性为准。

**非目标**：

- 变量槽级别的引用（C# `ref local`对变量重绑定的跟踪语义）——`&`别名的是
  记录（存储位置的稳定记录），不是变量槽；
- native函数的`&`形参（宿主ABI本版不动；现行native本就不支持out，
  边界对齐，后续ABI版本再议）；
- 标量&引用的存储压缩等实现优化；
- 泛型函数的完整设计（本设计只保证`T&`对泛型合成良构）。

## 3. 语义设计

### 3.1 &的适用域与等价规则

- **按槽拷贝移动的类型**（标量、enum、struct、string）：`T&`是存储别名——
  通过它读写的就是被绑位置的存储（struct是记录本身；标量/enum是值位；
  string是该位置当前持有的串句柄——串内容不可变，别名的是「哪个串」的
  写权）。string纳入的动因：out参数退役后，stdlib的
  `recvFrom(out string peerAddress)`等写回能力由`string&`承接。
- **身份引用类型**（class、interface、数组、容器）：`T&`与`T`是同一类型，
  声明合法但无附加语义。动机：泛型合成——用户泛型类方法与泛型函数声明
  `T&`形参/返回时，T绑定任何类型实参都良构，无需特例。
- 后果（须文档化）：`&`给前者带来别名与写穿透；给后者是空记号——对象字段
  写本来可见（普通引用语义），整值赋值仍只重绑局部。
- **泛型合成的行为分叉（须文档化）**：泛型体内经`T&`形参的写入仅当T绑定
  按槽拷贝类型才对调用方可见；T绑定为身份类型时`T&`是空记号，写入只及局部
  形参（`swap`对`Util<Point>`生效、对`Util<Dog>`静默失效）。同一份泛型代码
  对不同实参行为不同——实例化点对「泛型成员写入`T&`形参且T为身份类型」发
  警告级诊断。
- **const存储不可绑**：`&`只能绑定非const存储位置——const struct变量、
  const字段、const聚合容器上的&绑定与引用循环一律编译期拒绝（具名诊断），
  杜绝const位置被写穿。
- 手册劝阻对具体class类型书写`&`（空记号制造「作者似乎想表达什么」的假
  信号）；`&`只应出现在泛型T处与按槽拷贝类型上。

### 3.2 统一表示

引用的运行时表示为**（基准记录句柄，cell偏移）**二元组，8字节恰好一个统一
槽。各位置的落点：

| 被绑位置 | 基准句柄 | 偏移 |
|---|---|---|
| struct局部/字段/元素 | 该记录句柄 | 0 |
| 记录字段内的标量/enum/string | 属主记录句柄 | 字段cell偏移 |
| 容器内标量/enum/string元素 | 装箱记录句柄 | 载荷cell偏移 |
| 标量/enum/string局部（被&绑定） | 提升后的稳定装箱记录句柄 | 载荷cell偏移 |

- **标量/string局部提升**：局部若在函数内任何位置被`&`绑定，编译器将其
  存储编译为一条稳定装箱记录（槽内放句柄，访问全部间接）——与Python闭包
  cell、Lua upvalue同族技术。未被绑定的局部保持裸槽不变，零开销。成本：
  被提升局部每次函数激活一次装箱分配，访问间接化——编译期静态判定，无
  运行时检查。
- **垃圾回收分类是必改项，不是「不动」**：现行根集扫描按声明的类型类别
  过滤（`MarkFrameLocals`只扫Struct/Class/Array/Func/String/TypeParam，
  装箱与新增的byref类别不在表内；求值区带扫描同样按类别掩码跳过）。`int&`/
  `string&`槽里的基准句柄、被提升局部的稳定装箱记录会被漏扫，函数中途
  GC即回收活数据（`Point&`因struct恰在过滤表内而「侥幸正确」——最危险的
  形态）。改动清单：byref类别（或&性位）进入形参/返回槽根扫描、求值区
  带扫描掩码、静态槽根扫描（若纳入静态&）三处分类。不存在指向栈的指针，
  引用逃逸安全（mark-sweep非移动GC，容器扩容只搬句柄不搬记录——论证经
  代码查证成立）。
- **&引用本身不可被存储**：不能进容器、不能做字段、不能被函数值捕获——
  只能沿局部、形参、返回值传递。与C#托管指针的限制面一致。

### 3.3 记录稳定化（就地写）

每个值类型存储位置终生拥有一条稳定记录；一切写入（赋值、字段写、容器set）
**原位更新**该记录的cell，struct字段沿递归值子图逐层原位拷贝。现行赋值是
「分配新记录＋重绑句柄」（`OpCopyStruct`），本设计改为写目标记录。

- 对不使用`&`的代码**不可观察**：独立性不变（`q = p; q.x = 5`后p不变），
  改变的只是q保留原记录而非换新记录。
- 堆分配收敛到「建立新存储位置」的场景——声明初始化、值形参绑定、容器add、
  值返回；赋值与写入不再分配。
- `&`因此正确跟踪一切后续写入（含被绑变量整体重赋值）——C++引用的跟踪语义。
- 声明期struct环检查（既有，`Circular struct reference`诊断）是原位深拷贝
  终止性的依据，角色从布局限制升格为克隆/拷贝安全条件。

### 3.4 clone()不引入

值语义下一切「存入位置」的动作（赋值、字段写、容器add/set、值传参、值
返回）本就深拷贝，独立性由普通语句天然提供——clone没有独特能力可给
（`Point q = p;`与`Point q = p.clone();`行为完全一致），引入只会多一个与
赋值等价的写法。List/Dict的`copy()`保留现名不改。若未来语义向引用默认
方向扩张（方案A重启），clone作为独立性获取的唯一通道届时再立项（后加
不破坏任何存量代码）。

### 3.5 foreach双形态

```nlang
foreach (Point pt in pts)  { ... }   // 值循环：每轮独立副本（现行语义不变）
foreach (Point& pt in pts) { ... }   // 引用循环：pt每轮重绑为元素引用，写穿透
```

- 文法：foreach头`Type`与标识符之间加可选`&`记号。语言**没有二元按位与
  运算符**（`&`记号现仅存于遗留优先级声明，零产生式使用），真正的约束是
  语句头的声明/表达式歧义机制——`a & b;`不可从语法错误静默变成引用声明，
  foreach头的`&`臂独立成产生式、不挂通用Type后缀；同时覆盖两个foreach
  产生式（List/数组与Dict分立），实施时验证冲突台账无新增。
- 覆盖：List、数组、标量容器（`foreach (int& v in nums)`写穿装箱载荷）。
- **拒绝两形态**：Dict键迭代——现行foreach对Dict先物化`Keys()`副本List再
  走List路径，引用循环别名的是副本表元素、写穿透静默丢失，故
  `foreach (K& k in dict)`编译期拒绝（具名诊断）；string迭代按Unicode码点
  展开，`char&`对不可变串无意义，同样拒绝。
- 迭代中增删容器沿用现行foreach规则；元素被移除后引用仍有效（GC保活）但
  已不在容器内——文档化。

### 3.6 容器getter签名

`stdlib/containers.n`中`List<T>.get`/下标糖与`Dict`取值声明返回`T&`；
intrinsic层零改动（现状已传裸句柄）。类型规则：

- 值绑定（`Point q = pts[0]`）从`T&`返回初始化值变量＝拷贝新记录（现语义）；
- 引用绑定（`Point& r = pts[0]`）别名元素记录；
- **装箱计划&感知是双侧决策表**（值绑定拆箱/&绑定保留只是两格）：按表达式
  出现上下文逐格裁定——声明值绑定、&绑定、实参×被调签名（值形参照旧装箱/
  &形参**抑制拆箱**——否则槽里是裸标量，被调拿到的是垃圾基准句柄）、返回
  ×调用方绑定、复合赋值目标、下标赋值目标、foreach源、一般子表达式
  （`nums[0]+1`拆箱如旧）。OP_Unbox现于成员分派与foreach取元素两处无条件
  发射，&感知改造覆盖两处。
- **容器操作×别名有效性**（须文档化）：set——别名保持且见新值（原位写）；
  removeAt/clear——别名指向孤儿记录，写入安全但对容器不可见；扩容——
  side table只搬句柄不搬记录，别名不受影响。
- Dict取值miss抛异常（现行`Dict key not found`），`V&`返回路径无miss
  绑定形态。
- `pts[0].x = 9`统一为&返回上的成员写（与现行「get＋写穿透」行为一致，
  机制归一）。

### 3.7 用户泛型

- 实参拒绝表删struct臂（func臂保留——函数值是多槽记录，理由不变）；
- 泛型字段T=struct：稳定记录句柄＋存储时原位深拷，与普通struct字段同构，
  staging限制解除。

### 3.8 容器元素匹配修复（配合项）

存储边界仍是副本（值语义），`contains`/`indexOf`/`containsKey`/Dict键查找
对struct元素/键由身份比较改为**字段深值比较**：值字段递归比值、string按内容、
class/数组字段按句柄——与既有记录拷贝的成员规则同构。同步`DictKeysEqual`的
RTK_Struct分支（它是Dict全部键比较的单一汇聚点；`FindListElement`覆盖
contains/indexOf，两处改完三入口全通）。同族第39项（`List<func>.contains`）
不在本设计范围（需先定义函数值相等语义）。
**迁移注记**：现行语义下`if (!pts.contains(p)) pts.add(p);`的去重写法恒
追加（contains恒false），修复后开始真去重——对存量程序是静默行为变更，
CHANGELOG显式标注、known-limitations销账时提示存量代码核查。

### 3.9 函数传参与返回

- `T&`形参（T为按槽拷贝移动的类型）：句柄直传，跳过现行形参深拷贝；被调内
  的写穿透调用方。实参为右值（临时记录）时照常绑定——写穿透发生在临时记录
  上，调用方不可见；合法，文档化。
- `T&`返回：句柄直传；值返回照旧拷贝（保守，免逃逸分析）。
- **可绑位置清单**（`&`绑定初始化器与`&`实参共用同一判定）：
  - 可绑——局部变量、形参、单层字段（`obj.f`）、下标元素（`pts[0]`）、
    下标元素字段（`pts[0].x`，现行已可原位写）；
  - 必拒（具名诊断）——方法调用结果、链式成员（`a.b.c`，现行即拒绝链式
    写，&沿用同一门）、数组创建表达式、枚举成员、const目标、字符串下标、
    静态槽标量（静态存储提升不在本期，见§9）；
  - 判定模板沿用现行out实参的位置检查（`ExprResolverValues`的形式参数/
    const/静态三查）扩为&判定。
- **绑定规则补全**：
  - **&返回局部变量拒绝**（具名诊断）：`Point& make() { Point p; return p; }`
    不悬垂（GC保活孤儿记录）但写入静默无效——比C++的UB更隐蔽，编译期拒绝
    而非警告；
  - **局部位绑定右值**：`Point& r = Point(1,2); r.x = 9;`与形参右值绑定同
    规则——合法，写入丢失，文档化；
  - **&形参禁默认值**（无被绑存储可言，具名诊断）；
  - **`f(x, x)`两&形参别名同一变量**：归调用方责任，文档化不加诊断；
  - 命名实参配`&`形参照常绑定（`f(rem = r)`）。
- **标量转换拒绝**：`&`绑定与`&`传参要求标量种类精确匹配（byte局部不可绑
  到`int&`），一切隐式提升/转换拒绝——转换会破坏别名指向（转换值是新存储）；
  enum与其底层整型同样互斥。
- **异常可见性**：`&`写穿透在异常传播时保持可见、无回滚（被调抛异常前已写
  的部分留在调用方存储里）——与现行out「正常返回后才写回、异常则全无」不同，
  是有意语义，须文档化并加测试钉。
- **调用点无标记**（与class实参的既有调用约定一致——`f(obj)`本就经方法写
  穿透对象，`&`形参是把同一约定延到值类型）：调用点书写`&`实参（`f(&x)`，
  C++习惯）报具名诊断指向`T&`形参声明。
- **同名函数不能只靠`&`区分重载**：一个函数名一套签名，值/引用由声明固定。
- 现有`out`机制退役，见§3.10。

### 3.10 out参数退役

现行`out`与`&`形参同为inout语义（被调方可读调用方当前值），但带一串限制：
实参仅限局部变量（字段/数组元素/表达式拒绝）、struct被拒（变长值语义与
固定槽写回不兼容）、native与enum方法被拒、内建方法不接受、虚/接口分派被拒、
构造调用被拒、单次调用32个上限、「`int x = f(out x)`返回值先于写回」的
时序怪癖。`&`形参逐条超越：任意左值可绑（byref的基准句柄＋偏移表示天然
覆盖字段与元素）、struct原生支持、与分派机制解耦、无写回时序问题、并入
普通参数上限。静态保证损失为零——现行`out`没有「被调方必须写」的确定赋值
契约（inout可只读不写）。

- **迁移**：stdlib的out签名改写为`&`（net.n的`recvFrom(out string …,
  out int …)`→`string&`/`int&`）；函数值类型语法中的out标记
  （`func<out int, …>`一族）由`&`记号取代。
- **文法**：`out`形参产生式移除；源码中的`out`实参/形参报具名迁移诊断
  （指向`&`写法），不保留静默语法错误。
- **实现拆除**：OutSpill/写回掩码机制、`SnMisc`的泛型out标记
  （`m_genericOutFlags`）由&性标记取代；`.ncu`签名格式的out位由&位取代
  （与§4的签名版本升级同批）。
- **迁移行为差异表**（存量代码的可观察变化，CHANGELOG逐条标注）：
  - 异常中断——out：写回全无（写回在正常返回后发射）；&：部分写入持久
    可见（§3.9异常可见性）；
  - `int x = f(out x)`——现行「out写回赢」（返回值先存、随后被out覆盖）；
    新语义「返回值赢」（&无返回后写回步骤）；
  - 实参形态——out仅局部变量；&扩至字段/元素（能力增益，不是破坏）。
- **静态槽标量**：out现行即拒绝静态实参；`&`本期同样拒绝（静态存储提升
  不在本期，见§9）——两机制边界对齐，无迁移痛。

### 3.11 并发交互

多载体并行（纯计算跨载体并行＋存储操作逐次串行）下，记录稳定化改变原子性
粒度：现行struct赋值＝单槽句柄重绑（单次存储操作）；原位更新＝逐cell多写，
另一载体可在写之间观察到半新半旧的撕裂记录。裁定三条：

1. **整记录原位拷贝视为单原子存储操作**——实现契约：原位写路径对共享位置
   （class字段、容器元素）持存储锁贯穿整个记录拷贝，或以等效机制保证无
   中间态可见。实施核验项，进实施计划。
2. **`&`引用不跨线程**：spawn限零参函数值且`&`不可捕获（§3.2不可存储约束
   的推论），别名无法越过线程边界；跨线程数据交换仅经Channel/值拷贝边界。
   把这条既有推论显式化为保证。

## 4. 编译器与运行时改动面

**改造**：struct移动边界按新规则分派——赋值/复合赋值/字段写/数组元素写/
容器set改为原位更新；声明初始化、值形参绑定、值返回保留分配＋拷贝（新存储
位置的建立）；foreach值循环保留拷贝；`&`形参与`&`返回跳过拷贝。
`EmitStructDeepCopy`全部九处调用点逐一归位：

### 4.1 嵌入宿主影响

宿主不需要byref面（&不跨native边界，宿主函数收`vector<Value>`按值）——
ABI二进制面不动。但**记录稳定化改变宿主持有Value的可观测行为**：宿主的

## 7. 代价与被放弃的选项

- 语义规则从一条变两条（值为主＋&特例）——语言永久多出「哪些名字是别名」
  的维度，不可逆；
- **调用点无标记**（C#/Swift式调用点标注被否决）：理由是与class实参的既有
  调用约定完全一致（`f(obj)`本就写穿透对象），调用点标注会制造两套实参语法；
  代价是`f(x)`的数据流可读性依赖声明——手册以「实参修改可见性」表与IDE
  内联提示缓解；本设计同时拒绝右值绑非const&的警告（临时记录写穿透本就
  不可见，警告噪音大于价值——与形参右值绑定同一裁定）；
- **只读免拷贝形参（const T&/in）明示不做**：脚本struct通常小、string本就
  是句柄，痛感有限；当下模式＝`&`＋自律，或const struct类型形参承受拷贝。
  记为远期选项；
- struct数组的内联（扁平）元素表示：C下保留为远期选项，前提是扁平元素布局
  ＋元素原位写语义＋GC不移动承诺（GC已是mark-sweep非移动；byref的
  基准句柄＋偏移表示对内联元素引用即「数组记录句柄＋载荷偏移」，无需新增
  机制）——门是开的，工程量在布局与写路径。A方案则语义层永久排除；
- 装箱计划的&感知、.ncu签名版本升级是纯实现复杂度；
- out退役的代价：声明处失去`out`一词的自文档性（in/out意图改由参数命名与
  文档约定承担）；收益是现行out的整串限制（仅局部实参、struct/native/虚分派
  /构造拒绝、32上限、写回时序怪癖）全部消失。
