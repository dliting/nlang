# 门禁写目录互斥（tools/gate.sh）概要设计

> **状态更新（2026-11-23）**：本文描述的机器锁与随之的`--shared`旗标已被`docs/dev/gate_timing_design.md`D-10整体删除，
> 本文的写目录按键认领升为唯一互斥层，所有腿无条件认领（「只在共享模式下认领」的入口门已随旗标消失，命令行无可派生目录的腿
> 报一行说明即可起跑）；认领家族本身按该spec的D-18未改名，`wdir_key()`（规范化路径的SHA-256前16位十六进制）与`LOCK`行文案仍如本文。
> D-11登记的`build-dir:<规范化目录指纹>`资源名没有落成第二个claim族——命令行看不到的目录（`cd`形态ctest腿、脚本内部的重建）
> 经一次性`NLANG_GATE_WRITE_DIR`声明参与同一个按键认领，同树同键与本文派生收敛为同一把键。正文中的「机器锁」是本文落地当时的历史描述，原样保留。

## 一、引言

v0.13.8收官批的一次门禁误红是这样的：两条`--shared`腿（同一棵build-dev的Debug与Release重建）并发起跑，两条CPack配置写序程抢`build-dev/CPackConfig.cmake.tmp`，报`Permission denied`、rc=127，build-dev于是留着0.13.8的旧二进制，连带5条`version_*`单测假失败（台账`.superpowers/sdd/2026-11-15-json-library/progress.md:141`，原始日志`temp/gate_json_t12_rebuild_release.err:1-3`）。当时的处置只改了批次编排——重建腿跨树配对（同一条目:142），机制本身没动，也就是说下一次还会有人踩同一个坑。

用户裁定（2026-11-15）：这类问题要从机制上改进，让`tools/gate.sh`自己拦下「两条构建门禁写同一个目录」，而不是靠人记住配对规则；排在门禁绿、第三方评审与v0.13.11收尾提交之后做（同一条目:147）。

本文是概要设计（Spec）：钉死目标范围、机制裁定与行为面；逐任务细化留给实施计划。文风与结构仿`docs/dev/json_library_design.md`。

## 二、目标与范围

### 2.1 本版做

- 给`--shared`（只构建、不测量）腿加一道「写目录锁」：目录从该腿命令行里cmake/ctest/nlang_docs显式命名的目录导出，写同一目录的两条构建腿串行，写不同目录的照常并行；
- 持有者信息、陈旧接管、等待与获锁日志行，全部沿用既有机器锁的格式与纪律（`LOCK `前缀、判决行原样）；
- 新增自测`tools/gate_selftest.sh`：以事件先后（不是时长）断言「同目录串行、异目录并行」，并注册进ctest；
- 同步`tools/gate.sh`头部注释，并把仓内全部按行号引用`gate.sh`的地方改成按函数引用（勘察时共七处、三个文件，其中本设计文档自己三处已随本次修订改掉，余下四处见九）。

### 2.2 本版不做

- 不改机器锁（exclusive/shared）的既有语义，也不改`--shared`标志的含义；唯一例外是陈旧判定的一条龄源（见D-6末尾）：独占锁的残骸读不出`started=`时也必须能变老，否则机器永久挂死，而这与`sweep_stale`自己的注释意图相悖。互斥含义、认领与释放的形状、`LOCK`行文案与判决行都不动；
- 不做目录前缀包含判定：父目录与子目录互不排除（理由见D-9）；
- 不为「读另一个目录里的构建产物」（如docs腿读build-dev里的`ncc.exe`）加锁：那是文件级读写竞态，与本次要根治的目录级写写竞态不同源（D-9）；
- 不要求每条`--shared`腿都能导出目录（D-7）；
- 不重构构建树布局（每配置一棵树）——见方案比较C；
- 不提VERSION、不写CHANGELOG、不动用户手册：五类用户可见面均未触及（见九）。

### 2.3 落点

纯贡献者工具改动，占dev线一次独立提交，不占roadmap版本号；排在v0.13.11收尾之后、v0.13.12（WEB框架）开工之前。

## 三、关键事实（勘察所得）

1. `tools/gate.sh`头部注释里`--shared`的用法说明（今天落在`:28-32`）已把`--shared`描述成「只写自己的构建树、可与另一条`--shared`腿并存」。契约里「自己的」这一条从来没有被检查过——本次补的就是这个enforcement，而不是新添语义。
2. 机器锁的现有实现（一律按代码特征定位、不记行号：本次要在这些位置之间增行，行号从写下那刻起就在漂）：独占认领在`acquire()`的独占分支里靠`$lock_dir/exclusive/`的原子`mkdir`，构建腿是`$lock_dir/shared/`下每个holder一个`.info`文件（`acquire()`的共享分支）；`write_holder`写`name`/`pid`/`started`/`dir`/`mode`/`cmd`六行，`holder_age_s`读`started=`，`sweep_stale`按`LOCK_STALE_S`（默认10800s）接管并点名被顶替者；等待行与获锁行（`wait_round`与`acquire()`的两条分支）一律带`LOCK `前缀；锁根可由`NLANG_GATE_LOCK_DIR`改址。认领循环每轮都先重建锁根（`acquire()`开头那段注释写明：临时清理器可能在等待期间把根目录删掉，缺这一步，原子认领会永久失败）。
3. 本机Git Bash（bash 4.4.23，MSYS）里`flock`不存在（`command -v flock`无输出），`cygpath`、`realpath`、`sha256sum`、`mktemp`都在`/usr/bin`。
4. 目录旗标的拼法实测：
   - `cmake --help`只列空格分开的`--build <dir>`与`-B <path-to-build>`；`cmake --build=DIR`实测被拒（cmake 3.25.2），只是消息随调用形态不同：光一个`--build=DIR`报`CMake Error: Unknown argument --build=DIR`、rc=1，后面还跟着参数时降为`CMake Warning: Ignoring extra path from command line: "…"`、仍rc=1。两种形态都不干活。
   - `ctest --test-dir <dir>`存在；`ctest --test-dir=DIR`更糟——没有任何警告，直接改用CWD并回rc=0（实测：`Test project E:/cases/nlang/dev`＋`No tests were found!!!`＋rc=0）。
   - `nlang_docs`的目录旗标是`build`/`check`的`--site-dir`与`snippets`的`--workdir`（`tools/nlang-docs/src/nlang_docs/cli.py:85,107,121`），由argparse解析，因而`--site-dir=DIR`是其**合法**拼法（实测输出里就打出该目录）。
5. 今天所有`--shared`腿的命令形态（全仓`--shared`调用点汇总：`temp/*.sh`、`tools/http_perf/probe_pair_ab.sh:49`、`docs/dev/http_perf_baseline.md`配方）只有三类：`cmake --build <tree> --config … [--target …]`、`python -m nlang_docs build|check --site-dir <dir>`，以及一条不带任何目录旗标的docs片段pytest腿。后一类今天就存在：它写的是每次一换的mkdtemp暂存目录（`cli.py:213,258`、`snippets.py:352`），与别人不撞；仓库根的`.pytest_cache`虽是共享写入，但写入良性，且这类腿今天本就串行编排。
6. 构建树根被所有配置共用：错误日志点名的正是树根的`build-dev/CPackConfig.cmake.tmp`（`CPackSourceConfig.cmake`同理，另有`CMakeCache.txt`），不是每配置子目录各一份。这就是「同一棵树两个配置并发」会撞的物理原因。构建腿的POST_BUILD拷贝都落在`$<TARGET_FILE_DIR:…>`里（`CMakeLists.txt:151-167,182-193`），即各自树内，不跨树。
7. 路径归一化实测：`cygpath -m build-dev`原样吐回相对路径，要`cygpath -ma build-dev`才得`E:/cases/nlang/dev/build-dev`；`realpath -m build-dev`得`/e/cases/nlang/dev/build-dev`。
8. 全仓按行号引用`gate.sh`的地方，勘察那条`git grep -n 'gate\.sh:[0-9]'`命中**七处三个文件**：`docs/dev/http_perf_baseline.md:710、798`与`tools/http_perf/doc_template.md:637、725`是消费方引用（后者是基线页再生成的模板，漏改就会把旧行号再灌回前者），另外三处在本文档里（v4的`:35`、`:55`、`:87`，按v4的行文数）。本文是提交进仓的文档，自己就在grep的命中面里，引用`gate.sh`同样不能写行号——否则九那条「改完复核为空」的自查根本达不到，实施者会撞在一面清不掉的命中上。本文这三处已在v5按九的同一写法改成按函数引用。

## 四、调研结论与出处

- shell级互斥的两种标准做法是`flock(1)`与原子`mkdir`。POSIX文件系统上`mkdir()`是原子的，认领必须用不带`-p`的单次`mkdir`（`mkdir -p`不保证「已存在即失败」），释放用`rmdir`；网络文件系统上`mkdir()`可能不原子（unix/SE答复，镜像`cloud.tencent.com/developer/ask/sof/116584365`、`cloud.tencent.com/developer/ask/sof/105941096`）。本机锁根在`%TEMP%`本地盘，不在网络盘上。既有机器锁已经是这个形状，目录锁沿用同一机制，一个脚本里只有一种锁法。
- 「一棵构建树同一时刻只有一个构建」是CMake社区的常规前提：多配置的正路是多棵构建树，同一文件系统位置并发构建会撞（Xcode生成器的`build.db: database is locked — Possibly there are two concurrent builds running in the same filesystem location`，`cloud.tencent.com/developer/ask/sof/107865466`；多配置构建问答`cloud.tencent.cn/developer/ask/sof/102367408`）。本仓库选了多配置共用一棵树（省磁盘、省配置时间），代价就是要由门禁保证同树串行——这正是本次要做的事。

## 五、方案比较

- **A 按写目录互斥（选定）**：目录从命令行导出，目录级互斥，跨树并行度完整保留。代价：目录得从argv导出，导不出时退回现状（且日志可见）。
- **B 构建腿一律串行**：零新机制，但把三棵独立树的并行重建也交出去了——机器锁当初正是为这个并行度设计的（`tools/gate.sh`头部注释讲机器锁并行度的那一段，今天落在`:19-26`）。收缩功能需要独立理由，这里没有。
- **C 每个配置一棵树**：能根治「共用树根CPack文件」，但要改构建树布局、门禁编排、e2e的二进制路径与全盘脚本，影响面远大于本次。门禁之外的入口这一项是C的真实优势：手工跑的构建与IDE后台构建根本不经过`gate.sh`，目录锁拦不到它们，而C的「每配置一棵树」在文件系统层面就消除了跨配置并发（各配置写各自目录），只有同配置并发两案相同。本方案不掩饰这个缺口，选A的理由与之无关——天天相撞的场景发生在门禁批里（本次事故就是），而`gate.sh`的职责范围也正是门禁批；门禁之外怎么摆构建树属于贡献者约定，不该由脚本代管，代价只是手工/IDE的跨配置并发仍靠习惯避免。
- **D 只加一个必填旗标让作者声明写目录**：实现最省，但失败模式恰恰是「人忘了声明」，本次要修的正是这个。导出为主、环境变量可覆盖（D-3）比「必须记得」稳。

## 六、架构裁定

### D-1 互斥资源＝命令自己声明的目录，读写一视同仁

docs的`check --site-dir`是读者、`build --site-dir`是写者，同目录并发同样会读到半成品站点。区分读写要两套锁语义，换来的只有「两个check可并行」，而docs腿本来就串行编排（计时帽是机器级的）。故一把锁，读写都算。

### D-2 只有`--shared`腿取目录锁

独占腿起跑前要等`shared/`清空、起跑中独占整机，因此任何不是「shared对shared」的配对都已被机器锁全序化，再加目录锁是空转。此裁定有独立理由，不是「现状如此」：目录锁要防的是两本脚本各自合法（都带`--shared`）却写同一目录。

### D-3 目录集合的导出规则

按argv顺序扫描目录旗标，两种拼法都认：长旗标的空格式与`=`连接式（`--build DIR`/`--build=DIR`、`--test-dir DIR`/`--test-dir=DIR`、`--site-dir DIR`/`--site-dir=DIR`、`--workdir DIR`/`--workdir=DIR`），短旗标`-B DIR`与`-B<DIR>`。环境变量`NLANG_GATE_WRITE_DIR`指定的目录并入集合（为argv看不见的工具预备，如手工跑的msbuild/ninja）。两个入口的值都是**单个目录**，不引入分隔符语法：多目录本来就有argv那条通道，env只是给argv看不见的工具兜底，为它再造一套分隔符只是多一处要记的约定。旗标后面缺值（它是argv末项）或值为空串（`--build=`）时跳过该旗标、不记任何目录：实测空串在两条归一化路上都给不出结果（`cygpath -ma ''`与`realpath -m ''`都报错），硬走下去会得到一个按空串算出的锁键，把彼此无关的坏调用互相串起来；缺值的旗标本来就没说出要写哪个目录，拦一个猜出来的目录不如不拦。

为什么`=`连接必须支持：对cmake/ctest它本来就是坏调用（三.4：cmake直接拒绝、ctest静默改用CWD），拦下总比漏过强；对`nlang_docs`它是argparse认的合法拼法，若不支持，`--site-dir=temp/en`这条腿跑得好好儿的却一把锁都不取，与同目录的另一半并不串行——正是方案D被否决的那个失败模式。多一个分支，不多一处坑。

`NLANG_GATE_WRITE_DIR`的使用纪律：只用逐次前缀形式（`NLANG_GATE_WRITE_DIR=<dir> tools/gate.sh …`），**不得export**。批脚本里的export会随环境继承给后面每条腿，让写别的树的腿也白等一把无关的锁；获锁行会把取到的每个目录都打出来，这种白等看得见，但仍要避免。

### D-4 路径规范化

Windows下用`cygpath -ma`（实测`-m`不做绝对化，`-ma`才得`E:/…`正斜杠绝对形）再转小写——Windows大小写不敏感，`build-dev`与`BUILD-DEV`是同一棵树。无`cygpath`时（Linux移植预备）用`realpath -m`：`-m`不要求路径存在（`cmake -B`正是要新建目录），且**不转小写**——POSIX大小写敏感，`/Build-Dev`与`/build-dev`是两棵树，折叠成一把键就是假串行。相对路径按gate.sh的CWD解析——gate.sh不chdir，其CWD就是调用者的CWD。

### D-5 一把腿可持多把目录锁，全局同序获取

对集合内去重后的每个目录都上锁，按锁键字典序依次获取（全局同序是无死锁的充分条件；这个次序一律按字节比，即排序加`LC_ALL=C`——默认排序跟着locale走，「全局同序」就会退化成「只在这台机器的locale下成立」，读侧配对键次序时同样要加），释放逆序。获取次序全脚本一致：机器锁在先、目录锁在后。于是一条腿同时写两棵树（例如`cmake --build A`后再`ctest --test-dir B`）也被完整覆盖，无需「只认第一个旗标」这种隐性收缩。今天的腿还没有这种形状，故这条机制的覆盖面必须由八.2的两树断言与突变核查兜住，不能只靠论述。

### D-6 锁文件布局与陈旧接管

`$lock_dir/wdir/`为根（随`NLANG_GATE_LOCK_DIR`一起改址，自测因此可以整体搬进私有目录）；每个目录一把锁＝原子`mkdir "$lock_dir/wdir/<key>"`（不带`-p`，理由见四），其内`holder.info`沿用`write_holder`的六行格式并多写一行`path=<真实目录>`。每轮认领前先`mkdir -p "$lock_dir/wdir"`——与`tools/gate.sh`的`acquire()`每轮认领前重建锁根那段（今天落在`:148-151`）同一个理由：临时清理器可能在等待期间把父目录删掉，缺这一步，原子认领会永久停在ENOENT上，正是那段注释防的挂死。陈旧判定与接管复用`holder_age_s`与`LOCK_STALE_S`，但目录锁还要给「holder文件根本没写成」的残骸补一条龄源：旗标目录是在写holder之前建立的，进程死在这两步之间就没有`started=`可读，`holder_age_s`对缺失文件回0，等待者会守着一个永不变老的旗标——所以holder缺失时改用旗标目录自身的mtime判龄。这个两步窗口不是目录锁独有的：机器锁的独占分支同样先`mkdir`后`write_holder`（今天落在`:167-168`），死在这两步之间的`exclusive/`里没有`holder.info`，`sweep_stale`只能经`holder_age_s`取龄而它对缺失文件回0，于是那份残骸连`LOCK_STALE_S`都等不到、等待者永久等下去——`sweep_stale`自己那段注释（就挂在函数上方：「持有锁的进程随shell关闭而死，不能把机器冻到有人来发现」）要防的正是这种情形。故龄源抽成一个共用函数：`holder.info`在且读得出`started=`就用`started=`，否则用旗标对象自身的mtime；兜底参数是「创建时刻写在哪个对象上」，先`mkdir`后写holder的两处传旗标目录，共享腿那种holder文件本身就是旗标的地方传文件自身（写坏的半个holder文件同样读不出`started=`，今天恒0，会把后面的测试腿永久挡在外面）。机器锁的`sweep_stale`、独占等待行里的`held <n>s`与目录锁的`sweep_stale_wdir`一律用它，四个既有调用点（`sweep_stale`的独占接管分支与共享清扫分支各一处、独占等待行里取`held <n>s`的两处）一个不留，龄源全脚本只此一处；独占分支就此一并修好。这不是改机器锁的语义（2.2那条禁的是互斥含义与`--shared`含义）：认领、互斥、释放、接管行与等待行的文案一概不动，动的只是「一份读不出`started=`的残骸要永远等下去」这条与本函数意图相悖的行为。它的测试口径与八.4同款，残骸换成没有holder文件的`exclusive/`。

接管的判据只有龄这一条，`write_holder`写的`pid=`全脚本没有读者（实测只有写它那一行）：进程被kill或机器重启留下的残骸，也要守到`LOCK_STALE_S`才被发现。这是机器锁今天的行为，目录锁照搬，本次不改。不做pid存活检查是裁定的结果而非疏漏：`pid=`记的是bash自己的进程号，实测Git Bash的`kill -0`看不见非MSYS进程（对Windows的System进程pid 4回`No such process`、rc=1），而进程号每次开机重新分配——重启前那份残骸的pid很可能撞上一个正在跑的无关进程，「它还活着」判成假、于是永久等待；拿有界的`LOCK_STALE_S`等待换这种无界的错误占有不划算。真撞上的出路写在头部注释里：等待行每`LOCK_REPORT_EVERY_S`就报一次holder，照它的`path=`核对之后手工删掉那个锁目录即可，`NLANG_GATE_STALE_S`也能把阈值调小（八.4的探针正是用它做反向对照的）。

### D-7 无目录可导出的`--shared`腿：警告并继续

打印一行说明「未从命令行导出写目录、未取目录锁」后照常执行。错误化会打断今天就合法的腿（三.5），而那类腿根本没有跨腿冲突可防（各自的mkdtemp暂存不共享；仓库根的pytest缓存写入良性，且这类腿今天串行）。

### D-8 锁键＝规范化路径的sha256前16位十六进制

键要进文件系统当目录名：Windows有路径长度上限，路径里还有空格与`:`。日志与holder一律打真实路径，人读得懂；哈希只当目录名用。

### D-9 不做前缀包含判定，也不锁跨目录的文件读

`build-dev`与`build-dev/src`互不排除，因为没有腿把写目录指进另一棵写树里面（今天全部形态里，docs两站是`temp/en`与`temp/zh`这样的兄弟目录）；做包含判定要在多种拼法间比父链，复杂度换不到现实收益。holder已记`path=`，日后真要加规则不必改格式。同理，「docs腿读build-dev里的`ncc.exe`」这类跨目录读写竞态不在本次范围：它是文件级的，且`--ncc`是文件不是目录——锁它的父目录也与`--build build-dev`的锁键不同，锁了也拦不住。

### D-10 自测只断言事件先后，不断言时长

按确定性测试设计裁定（2026-11-14）：不给时间赌局加时间护栏。自测用私有`NLANG_GATE_LOCK_DIR`（绝不排在真门禁后面排队）、`NLANG_GATE_POLL_S=1`；驱动一开跑就`cd`进本次专用的临时工作区，测试目录、事件文件、GO文件与腿的日志产物全放在里面——腿的CWD就是驱动的CWD（D-4），用例里的相对写法由此才有唯一确定的含义，脚本产物也不会落到仓库根那种不被忽略的位置；被测脚本一律按绝对路径调用，不随`cd`失效。哨兵预算在驱动起跑时一次算定，各次轮询都取同一个截止时刻的余量：每用例各配120s的话，七条串起来会先撞上D-11那个180s的ctest超时，哨兵反倒没机会报出holder——那正是它存在的意义；桩命令是一个只认`--build DIR`与`--site-dir DIR`两式并记录事件的shell脚本，由`bash`直接调用，起跑时在事件文件记一行、直到GO文件出现才收工——不篡改PATH也不假冒cmake可执行文件（Windows下PATH桩受PATHEXT与无扩展名执行限制，代价不可控）。桩与被测的导出逻辑共用同一套旗标拼法，所以**桩用到的那两式**导出规则确被检验，其余旗标由八.3的突变核查兜底。驱动脚本一律条件轮询（等期望日志行、等holder文件），断言取自日志事实与事件文件里的先后次序。整体挂120s哨兵（常量命名，一次算定的全局预算，即上面对各次轮询取余量的那条），哨兵触发即判失败并报出当时的holder。

### D-11 注册进ctest：bash要实跑出目录键才注册，否则响亮跳过

`tests/CMakeLists.txt`里`find_program(BASH_PROGRAM bash)`，命中之后还要用这条bash实跑一次`gate.sh --print-write-dirs --build <项目根>`：只有退出码为0**且**输出一行`key <非空十六进制锁键> path <目录>`，才注册`add_test(NAME nlang_gate_selftest COMMAND ${BASH_PROGRAM} ${PROJECT_SOURCE_DIR}/tools/gate_selftest.sh)`，配`WORKING_DIRECTORY ${PROJECT_SOURCE_DIR}`与`TIMEOUT 180`；没找到bash、或找到了却跑不出这行，各打一条`message(STATUS "… skipped: …")`说明是哪一种。加这道冒烟而不是只信`find_program`，是因为后者只保证PATH里有个叫`bash`的东西，不保证它跑得通本脚本：实测本机PATH里就有`C:\Windows\System32\bash.exe`（WSL启动器），拿它读`E:/cases/…`这种写法的路径直接`No such file or directory`、rc=1（那棵树在WSL里是`/mnt/e/…`）；coreutils不全的bash同样命中却算不出锁键（D-8）。把「能不能跑」留到ctest运行时才暴露，等于注册一条当场必红的条目，比少一条门禁条目更糟。两个条件用`且`连着，不是为了保险好看：注入一个能起、却不输出目录键的程序名（如实测的`cmd.exe`）时，它的退出码在0与1之间漂过，只有输出形状那条能稳定判下跳过。锁键那一半只要求「非空」而不是精确16位（D-8定的是16位，这里放行得宽一档），理由是CMake的`MATCHES`不支持界定重复次数：实测3.25.2上`[0-9a-f]{16}`形态永不命中，能落地的只有`[0-9a-f]+`这一种形状。放宽一处不等于少判一种坏情形——`sha256sum`缺失时锁键算成空串、那行打成`key  path <目录>`（`key`与`path`之间两个空格），非空这一条正好把它筛掉；精确16位仍由自测的打印用例断言（八.2），两处合起来覆盖不变。配置期这次探测不取锁也不落文件——打印分支在`mkdir -p "$lock_dir"`与`acquire`之前就返回（这两行今天落在`:194`、`:195`）。这与`nlang_docs_pytest`缺依赖时的处理同形（`tests/CMakeLists.txt:2796`注册、`:2805`的`TIMEOUT 180`、`:2807`的skipped消息），只是把「依赖齐全」的判据从「程序存在」换成「脚本真跑得出结果」。180s是仓内同类脚本条目的既有取值（`nlang_docs_pytest`就用它，见`:2805`），也是AGENTS「测试超时设短（最长3min）」的上限本身；超过它的少数条目（`:669`的900s、`:2763`的300s、`:2778-2779`的420s）都是经用户裁定确立的例外，那几处上方的注释记着裁定与实测数据，本条目不属于例外，故取180s。这是第一条以bash注册的ctest条目；缺席只是少一条门禁条目，不是构建失败。两条skipped消息各要在实施计划里当场注入触发一次（一条注`NOTFOUND`，一条注一个跑不出目录键的程序名），跑一遍配置再核跳过消息与条目数：没实跑过的跳过分支不算被覆盖，等一台恰好没装bash的机器更不是办法。

### D-12 判决行一字不改

`GATE <name>: PASS|FAIL rc=`原样保留，目录锁的所有行都用`LOCK `前缀，「只认判决行」的纪律不受影响。

## 七、行为面

新增/改变的只有日志行，格式为：

- `LOCK <name>: write-directory lock acquired after <n>s (<dir>)`
- `LOCK <name>: waiting for the write-directory lock on <dir> (<holder>)`（首轮），其后每`LOCK_REPORT_EVERY_S`一行`LOCK <name>: still waiting <n>s (<holder>)`
- `LOCK <name>: taking over the write-directory lock on <dir> held <age>s by <holder>`
- `LOCK <name>: no write directory derived from the command line, no directory lock taken`

四条行里的`<dir>`一律是D-4规范化之后的路径，也就是holder`path=`行的那个值，不是命令行的原样拼法。理由：同一把锁的等待行、获锁行、接管行与holder必须写同一个目录串，否则同一条腿换一种拼法（相对对绝对、绝对对大小写）之后日志行互相对不上，读日志的人只能猜是不是同一棵树；钉成规范化形，`wdir/<锁键>/holder.info`的`path=`与日志行可以直接对读，锁键目录名是谁也有据可查。这同时定了测试的断法：断言目录串的用例去读holder的`path=`或另一条腿的日志行做相等比较，不在驱动里重算一遍规范化配方（与「锁键不复制哈希配方」同一个道理，见八.2）。

另两个占位符同样只有一种算法：`<holder>`是`holder_text`对holder文件各字段压成一行的输出，holder文件不存在时是该函数的既有定值`unknown holder`（机器锁的等待行今天就用这句，两把锁共用一套措辞，不另造）；`<age>`按D-6的口径算，holder在则取`started=`到接管时刻的秒数（即`holder_age_s`的返回值），holder缺失则取旗标目录mtime起算的秒数。八.4的陈旧探针正是拿注入的老龄与接管行打出的`<age>`对账，这两个占位符若各按各的理解实现，那条断言就失去意义。同一个龄源也管既有机器锁的独占等待行与`sweep_stale`的独占接管分支里的龄（这两处今天就只调`holder_age_s`）：换成D-6的共用龄源之后，缺holder文件的独占残骸同样会变老、会被接管，两行的文案一字不改。

退出码语义不变（仍是被包命令的rc），`GATE`判决行不变，既有`LOCK`机器锁行不变。用法行与`--shared`的说明随之更新。

## 八、测试策略

1. **TDD顺序**：先写`tools/gate_selftest.sh`，在当前`tools/gate.sh`上跑到RED（缺等待行、事件文件显示重叠），再实现目录锁转GREEN。
2. **自测的断言面**：
   - 同树两拼法（`--build <abs>`对`--build <rel>`）→ 第二条腿必出现等待行，事件文件里第二条的起跑晚于第一条的收工；
   - 同树大小写差（仅Windows生效；Linux大小写敏感，这条在POSIX下自动跳过，见D-4）→ 同上；
   - 异树（T1对T2）→ 第二条腿无等待行，事件文件里两条起跑重叠；
   - 两树对单树（一条腿同时写T1与T2，另一条只写T2）→ 必串行，且获锁行里两把锁的先后严格按锁键字典序——这一条是D-5的覆盖面。为使该断言能区分「按锁键排序获锁」与「按argv顺序获锁」，驱动先把两目录按锁键排序、再以**逆序**写进argv（argv顺序正是全局排序要防的那种交叉形态）；锁键次序从holder文件配对读出，不复制哈希配方（目录名即锁键、`path=`行即目录，见D-6），但映射必须在上一条异树用例的重叠窗口里建立——那时T1与T2两个holder同时在场，列一次`wdir/*/holder.info`就够了；不能改用两树腿自己持锁期间的那次listing，因为argv在起跑前就得定，那次listing只能用来核对获锁行的先后。两树腿写作`--build <目录> --site-dir <目录>`：真实命令里一条腿涉及两类目录旗标就是这一种形态，重复两次`--build`不是合法的cmake命令。启动顺序固定为先起两树腿（它的起跑事件在两把锁都持住之后才落，见D-10）、再起单树腿并断言其等待行、最后放GO；反序启动会让两树腿被单树腿挡在T2上，获锁行根本打不出来；
   - `NLANG_GATE_WRITE_DIR`覆盖 → 与命令行目录同键时照样串行；
   - 无目录可导出的`--shared`腿 → 必出现「no write directory derived」行且腿照常PASS。
3. **突变核查（temp/探针，不入仓）**：从旗标集合里删掉`--build`、再删`--site-dir`，两轮自测都必须转红（证明旗标集合每个成员都真被检验）；把`cygpath -ma`退回`-m`（绝对化失效），同树两拼法那条必须转红。「每个成员都真被检验」不是靠这三次突变独立达成的：旗标集合有`--build`、`--test-dir`、`--site-dir`、`--workdir`四个长旗标加`-B`短旗标，只删两条臂的话，其余三条臂即便写坏了也无人报警。补齐的办法不是再加三次突变（每轮突变都是一次全局截止时刻烧到底的慢轮），而是让打印用例把全部拼法各喂一遍同一目录：断言每次输出**同一个键**，删掉任何一条臂那次就一个键都打不出来。突变核查因此只保留spec规定的三次，其余臂的活性归那条常态断言。三次突变的归因还依赖跑序：打印用例与「无目录」那条不涉锁、任何旗标改动都会先把它们打红，故它们必须跑在序列末尾，否则首条FAIL永远是打印用例，说不出是哪条臂坏了；承载机制的用例在前，首条FAIL才指向真凶。
4. **陈旧接管**：把`wdir/<key>/holder.info`的`started=`改老再起跑，必出现接管行——由temp/探针验证并记台账，不进自测（它会额外等一轮）。探针的两条口径是实质问题不是细节：①**不降`NLANG_GATE_STALE_S`，改造残骸老龄**（默认10800、注入10801）。把阈值降到几秒看着省时间，实际是替实现圆场——一个无视`LOCK_STALE_S`、见残骸就抢的实现照样全绿，而这条探针防的正是「阈值到底有没有被读」。老龄写在`started=`里，不在真实时间里等，不花时间。②**配一轮反向对照**：同一份老龄残骸，把阈值抬到高于龄（如20000）再跑一轮，必须没有接管行、只有等待行——只有正反两面都成立，「接管是因为过了阈值」才成立。这一轮顺手钉住另一个形态：进程已被kill、残骸还没过阈值。接管判据只看龄、不看pid（D-6），所以「pid已死」与「阈值在龄之上」走的是同一条代码路径，不必再造一轮——代价是这条用例说不出「死进程」与「活进程」的区别，而那正是D-6裁定不做存活检查的结果。接管行里的龄要能与注入值核对，才证明读的是注入的那份残骸；holder按`write_holder`的字段写（含`name=`），否则接管行「点名被替换者」那条断言无从点起。③**共用龄源在机器锁那一侧也要验一遍**：造一份没有`holder.info`的`exclusive/`残骸（`mkdir`之后不写holder，再给目录本身打老龄），跑一条`--shared`腿，必须打出既有的独占接管行、且行里的龄与注入值对得上。这一轮防的是「共用龄源只落在目录锁一侧、独占分支仍只调`holder_age_s`」——那样那个永久等待的洞照旧在，D-6末尾那句「独占分支就此一并修好」就成了没有对证的空话。同形的一小轮给共享holder：写一个只有`name=`/`pid=`、没有`started=`的半截`.info`文件（给文件自身打老龄），跑一条独占腿，必出既有的`dropping a shared lock`行且龄与注入值对得上——共享侧的兜底参数是文件自身而非旗标目录，是唯一一处形状不同的地方，不验就等于没写。
5. **门禁口径**：`tests/CMakeLists.txt`变了，三树都要重新configure。Debug（断言）树与IDE树各跑全量ctest（含新条目）：改动落在测试注册本身，只有全量跑才能证明它没碰坏同一棵树里其他条目的注册与超时属性。ASan树按例行口径重建并跑全量`ctest_asan`（含新条目）——它是例行门禁三树之一，跑全量本就是这棵树的例行默认，省掉才是要另加理由的偏离；而「CMake文件变更」正是已获认可的窄复扫先例（`.superpowers/sdd/2026-11-15-json-library/progress.md:132-134`）明列的ctest腿失效条件：那批省掉ctest腿是因为它没动CMake文件，这批动了，不能照抄那份省略。e2e不跑：本批无`.n`、二进制或产物变更，按用户裁定（2026-11-08）e2e只在发布时点执行一次。门禁范围属于用户口径，已随本spec请用户确认：用户2026-11-15裁定**保留全量`ctest_asan`**（本批最贵的一条腿照跑），「省掉它、只留新条目单跑」的方案连同「注册改动碰坏ASan树其他条目」这个信号一并作废。
