# v0.13.1 运行时泛型类型参数信息——概要设计

- **文档定位**：v0.13.1的概要设计（Spec）。目标与范围界定部分自roadmap条目拆出
  （用户指示2026-11-01原排0.12.8，网络库占用0.12.8后于2026-11-07改排0.13.1）；
  本文在其基础上给出经独立裁决的设计方案。用户指示（2026-11-08）：既有设计文档
  仅作参考，合理性优先，不向下兼容——本文§三对各旧决策逐项重审，偏离处附证据。
- **设计原则**（用户指示2026-11-01）：设计此功能时，应全面考虑基本的运行时类型
  信息和辅助设施的支持。

## 一、现状（取证2026-11-08，master树a71f47e4）

- 语言面：仅类模板（`class Box<T>`）；无游离泛型函数、无方法级类型参数。泛型类
  禁止静态字段（无每实例化状态位）；静态方法引用T的声明合法，但跨类限定调用
  无法绑定（探针：`S.f(5)`报Incompatible type、`S<int>.f(5)`语法错），仅类内
  裸调用可达（探针证实可编译运行）。
- 编译期铸造与去重：实例缓存键=（模板节点，类型实参节点）指针恒等
  （ExprResolverGenericMint.cpp两阶段构造）；全部实例化共用模板的一条类行与一份
  编译记录（Register.cpp:116跳过实例化登记）。
- T槽：声明类型为T的槽一律`RTK_TypeParam`，GC保守双域扫描（ESC_Dual）。
- 描述符设施：`GenericInstDescriptor`（规范拼写+进程级驻留池，拼写相等即描述符
  相等）已在树，仅单元测试引用，无生产调用方。
- 缺口（沿用2026-11-07取证）：对象无实例化标识（对象头首格仅类行索引）；
  `OP_CheckCast`仅类行恒等+超类链行走，`Box<int>`与`Box<string>`运行时不可区分；
  catch类型位接受泛型实例化；`.ncu`零泛型信息（`CompiledClass`无模板标记与类型
  参数名，桩签名重建T叶降int32占位）。
- 探针钉死的三项边缘（2026-11-08，本机Release构建）：
  1. 体内以T实参构造用户模板**合法**（`Hold<T>`体内`Box<T> b = Box(x);`编译运行
     通过）——运行时描述符合成是必答题，不是可选项。
  2. `o as T`（模板体内T作转型目标）**当前崩溃编译器**（backend: own class
     missing from the unit table: T）——现存bug，本版必须处置。
  3. 预置容器`List<T>`体内构造现状可用（元素种类降级路径，另行议题，本版不动）。

## 二、主流方案对照（联网取证2026-11-08）

- **Go 1.18+**：gcshape印制+调用点字典——泛型函数共享体，每次调用静态携带一个
  字典（含类型描述符），AMD64上经AX寄存器传递。载体=调用点，因为Go泛型函数是
  自由函数、无接收者对象。
- **.NET（具体化泛型）**：每个实例化在运行时拥有独立TypeHandle，对象头携带其
  MethodTable，`typeof(T)`直接读运行时类型；`Type.MakeGenericType`可从元数据在
  运行时铸新实例化（`.ncu`模板表的直接先例）。静态字段每实例化一份（NLang明确
  不取——模板行共享是NLang既定模型）。
- **JVM/Kotlin**：擦除+inline reified（靠体复制还原类型信息）——与字典模型
  （一份共享体）不相容，仅作反例参考。
- **结论**：NLang泛型是类形态，实例即堆对象——**对象自身是描述符的自然载体**
  （.NET路线）；调用点字典（Go路线）只对无接收者上下文必要。经§三D1取证，当前
  语言面不存在必须调用点载体的消费者，本版单载体。

## 三、关键设计决策

### D1 描述符载体：对象侧单载体，不引入帧隐藏槽

- **决定**：实例化描述符只随**对象**携带；运行时类型信息操作（typeName(T)、T上
  判等、T上转型）在实例方法/构造器体内一律经`this`对象读取。**不实现**旧设计的
  帧隐藏描述符槽与调用点隐藏实参通道。
- **理由**：载体必须跟上语言面，而非预支语言面。当前语言面的泛型上下文全部有
  接收者（实例方法、构造器——`this`恒在）；无接收者上下文只有"静态成员引用T"
  一个半残面（跨类调用本就无法绑定，仅类内可达）与不存在的游离泛型函数。为它们
  预铺帧槽要改动全部调用形态的参数装配（直调、按名、委托、out变体），是零现值
  的行道工程（YAGNI）。.NET对象头单载体先例；Go调用点字典的适用前提（自由函数）
  在NLang不成立。
- **预留**：将来静态引用T全面化或游离泛型函数落地时，按Go字典先例引入调用点
  通道——描述符经进程级驻留池指针恒等（D2），两种载体互通无重造代价。
- **存储**：并行数组`m_classInstDesc`（元素=驻留描述符指针或nullptr），与
  `m_slotKinds`/`m_slotStructIdx`同 resizing 纪律。不动物理记录布局、不动字段
  偏移（字段在cell 1+2i不变）、不进GC扫描（宿主内存）。改对象记录布局的替代案
  （头/尾加格）被否：字段偏移是编译进字节码的立即数，模板行对象与普通对象混行
  会使偏移计算分叉。同一并行数组兼作**数组记录的元素描述符位**（D5数组元素位
  比较）。
- **写头规则**：构造类型本身是实例化→写该实例化的描述符；构造非实例化→nullptr。
  继承实例化作基类（`class Sub : Box<int>`或模板继承实例化）今日语法即不接受
  （探针钉死），维持不可用——将来引入时必须同时裁决"定义模板参数→对象描述符
  实参位"的映射规则（参数错序与具体实参会破坏按位读取）。

### D2 描述符表示：链接身份规范拼写＋进程级驻留（沿用既有设施）

- `GenericInstDescriptor`+`InternDescriptor`照用，补齐**规范拼写的构造规则**：
  模板名=包限定链接身份（根包类型即裸名）；类型实参拼写——标量用规范名
  （int/long/float/double/byte/short/uint/ulong/ushort/bool/char/string）、
  枚举/类/接口/结构体用限定链接名、数组`E[]`（逗号表多秩）、嵌套实例化递归。
- **实参携带种类与载荷**：`TypeArgDesc`在拼写之外携带种类字节（标量族/宽度、
  string、struct、class/interface、enum、array含秩）与解析载荷（结构限定名、
  类行）——T判等与`as T`的种类分派（D6）读它，不再从拼写反解。驻留键仍为拼写
  （种类是拼写的函数，规范拼写下无歧义）。
- 拼写恒等⟺描述符恒等（驻留池保证）⟺**实例化恒等**。因此转型所需的"递归描述符
  比较"坍缩为一次指针比较；跨模块、跨包的描述符经同一驻留池自动归一。
- 用户可见的`typeName`返回同一规范拼写（与intern键共用一个串，不再造显示形态）；
  限定拼写天然防跨包歧义（静态字段补偿模式按键区分度刚好）。

### D3 构造点写头：描述符常量＋运行时合成配方

- `OP_New`追加`u16 descIdx`操作数（0xFFFF=无描述符）。模块级新增**描述符表**，
  条目二形态：
  - **静态拼写**：完整规范拼写串（构造点实参全部具体）。执行期查驻留池（加载时
    预驻留）直接写头。
  - **合成配方**：`(模板链接名, 实参源表)`，实参源=静态拼写｜`THIS_ARG(i)`
    （取`this`对象描述符第i实参的完整TypeArgDesc）｜数组包装（元素配方+秩，
    `Vec<T[]>`形）｜递归配方（嵌套`Box<Box<T>>`形）。体内以T实参构造（§一探针1）
    走此臂：执行器按配方组装TypeArgDesc表→InternDescriptor→写头。
- 配方随函数体所属单元序列化（同函数字节码一样是逐单元数据）。
- 静态成员体内构造带T实参的模板：具名拒绝（无`this`可读，同D4裁定）。
- 数组创建`new T[n]`维持拒绝（不变）。
- **序列化位**：模板行对象经WriteObject/ReadObject往返时，对象图携带其描述符
  规范拼写（读侧驻留后写回并行数组）——不携带则`Box<int>`往返后`typeName`/转型
  失明。T槽字段的序列化路由按既有保守规则，不因本版改动。

### D4 `typeName(类型表达式)`语言表达式

- 新初等表达式，接受类型位语法。三形态：
  1. **具体类型**：编译期折叠为字符串字面量（含嵌套实例化、数组、限定类名）。
  2. **裸T（实例方法/构造器体内）**：发射读`this`描述符第i实参拼写的操作码，
     结果为string（拼写随描述符常驻，操作码侧重字符串存储分配）。
  3. **T嵌在实参内**（`typeName(List<T>)`）：发射逐段合成拼写（读`this`描述符
     拼段+常量拼段）。
- 静态成员体内引用T：**具名拒绝**（运行时实例化信息经实例携带；改用实例成员或
  补偿模式）。静态成员声明本身与T值的存取传递不受影响（维持现状语义）。
- 用途锚点：泛型类禁静态字段（每模板一份实现无每实例化状态位），用户层补偿
  模式=非泛型辅助类`static Dict<string,...>`按`typeName(T)`分键。补偿模式随本版
  写入语言规格与用户手册（用户指示2026-11-01）。

### D5 转型区分实例化（运行时与编译期对齐）

- `OP_CheckCast`追加`u16 descIdx`（0xFFFF=无）：行匹配（现超类链行走）通过后，
  目标带描述符则比对对象并行数组描述符（指针恒等）；不匹配抛内建
  `InvalidCastException`（消息含两侧规范拼写）。`Box<int>`经`Object`中介转
  `Box<string>`自此运行时失败。
- 编译期转型表（CastInfo）对实例化目标：同模板不同实参仍编译期拒绝（静态可知，
  不留到运行时）；仅静态不可知的形态（经`Object`/超类下行）落到运行时描述符
  比较。
- catch类型位的泛型实例化（含T）：**编译期具名拒绝**（异常分派按行匹配，擦除下
  无法区分实例化，拒绝比默许诚实）。
- **数组元素位**：数组cast目标的比较键扩为（元素种类，元素类型下标，秩）＋
  元素级描述符——元素类型为模板行时经D1并行数组的元素描述符位比较。这同时修复
  预置容器的同族既有洞（`Object o = int数组; o as Array<string>`今日运行时静默
  通过）。数组创建操作码同`OP_New`规则携带descIdx（元素为实例化时写元素描述符
  位；体内以T为元素的数组创建维持拒绝，实例化元素走配方）。

### D6 T操作面恢复（判等、拼接、打印、`as T`）

- `==`/`!=`（T与T、T与null）：新操作码读`this`描述符该实参位种类分派——标量按
  各自宽度/语义内联比较；string按内容；struct按字段深值（复用
  `StructValuesEqual`，struct身份经实参拼写在链接模块解析）；class/interface按
  句柄恒等；enum按内联值；array按句柄恒等（与容器`indexOf`既定语义一致）；
  T与null：句柄种类比0，标量种类恒false。0.13.0的具名拒绝（裸T操作数）对
  `==`/`!=`解除，其余运算符维持拒绝（等约束机制）。
- T值与string拼接、`io.print`/toString：种类分派的通用toString操作码（复用
  0.13.0值语义批的分派例程）。
- `x as T`（§一探针2，现状崩溃）：实现按描述符实参种类分派到既有各`as`运行时
  路径（标量拆箱、string种类检查、struct身份、类行行走+描述符、数组比较）；
  失败抛`InvalidCastException`。修复崩溃并给出正确语义。
- 静态成员体内上述全部具名拒绝（同D4裁定）。

### D7 `.ncu`模板表（格式v2.15）

- `CompiledClass`追加`isTemplate`标记与`typeParamNames`；TypeDesc文法追加
  `RTK_TypeParam`叶（携带参数序号）；模板成员函数的`paramTypeDescs`携带T叶随
  模板行序列化。描述符表（拼写串+配方）随模块序列化。
- 桩重建：模板类桩=带`SetTypeParamNames`+泛型声明的SnClassDecl，成员签名经
  `SynthTypeExprFromDesc`新增的`RTK_TypeParam`臂合成标识符，由既有占位符绑定
  通道（BindTypeParamPlaceholderIfAny按父链）绑到参数占位符；消费方对无源码
  预编译包铸新实例化——铸造克隆签名面，编译记录经导入槽引用模板行（.NET
  `MakeGenericType`先例；Rust元数据分发泛型同路）。
- 链接合并：描述符表按拼写去重合并、操作数重映射（与字符串常量合并同形）。
- 版本：`NCU_FORMAT_MINOR` 14→15，loader拒绝≤14（描述符表使记录布局位移；
  既有惯例全部`.ncu`随版本重编）。

### D8 原生宿主接口ABI v12

- `NLANG_HOST_ABI_VERSION` 11→12，`NativeHost`新增类型实参回调：
  `typeArgCount()`、`typeArgKind(i)`（标量RTK族/结构/类/数组…）、
  `typeArgName(i)`（规范拼写）。实例native成员的调用经**接收者对象**的描述符
  回答（native路径`args[0]`即this，无帧、无需调用点通道）。在树无消费者——
  以测试native模块（若测试设施无generic native fixture则单元级覆盖回调契约）
  与文档契约钉死；stdlib既有native零改动。

### D9 版本与文档

- VERSION→0.13.1；CHANGELOG中英成对；语言规格：§4.12补`typeName`与判等解除、
  转型区分、catch拒绝、体内构造语义；§5运算符页、§8异常页同步；补偿模式写入
  用户手册；`tools/manual_sync_check.py`核销漂移；README/公共头随接口变更同步。

## 四、非目标

- 反射API（描述符为其地基，本版不交付反射面）；`typeName`的值形态（
  `typeName(expr)`读值的运行时类型——对象头描述符已就绪，有消费者时小步补）；
  类型参数约束、模板特化、方法级类型参数、游离泛型函数、静态引用T的调用点载体
  （D1预留路径）。
- `new T[n]`、表达式位显式泛型实参语法、预置容器实现改动（含`List<T>`体内构造
  的元素种类降级——另行议题）。
- struct/func类型实参的描述符多槽演进（v0.13.2值类型引用线；描述符拼写规则已
  天然容纳，无需现在改）。
- 静态字段解禁（补偿模式即官方答案，模型上模板行共享一份实现）。

## 五、实施顺序与验收

- 顺序（依赖排序，小件先行）：
  1. catch泛型拒绝（独立）＋`as T`崩溃的临时具名拒绝占位（先止血，D6实现时
     翻正为分派）。
  2. 描述符基础：规范拼写构造器（编译期）＋模块描述符表＋序列化＋链接合并＋
     `NCU_FORMAT_MINOR`=15。
  3. 对象载体：并行数组＋`OP_New`/数组创建写头（常量+配方）。
  4. `typeName`（折叠＋运行时读＋静态拒绝）。
  5. 转型区分（OP_CheckCast扩展＋CastInfo对齐＋数组元素位与预置洞修复）。
  6. T操作面（==/!=/拼接/toString/`as T`分派）。
  7. `.ncu`模板表＋桩重建＋无源码铸造。
  8. ABI v12回调。
  9. 文档/版本/门禁收尾。
- e2e钉：`typeName(T)`各实例化返回规范拼写；`typeName`具体类型折叠（嵌套/数组/
  限定名）；`Box<int>`经`Object`转`Box<string>`运行时失败（反向同）；数组元素位
  `Box<int>[]`与`Array<int>`/`Array<string>`的实例化区分；体内`Box(x)`构造后
  `typeName`/转型正确；`catch (Box<int> e)`与`catch (T e)`编译期诊断；T判等
  各实例化语义（int/string/struct/class/enum/array）＋T与null；T拼接/打印；
  `as T`分派（含拆箱与失败路径）；无源码`.npkg`铸新实例化运行；T槽GC回归族
  （generic_gc_tslot_survives）；模板行对象序列化往返保描述符；跨单元描述符
  合并（proj_generic_cross_unit扩展）；ABI v12握手。
- 门禁：Debug断言＋ASan＋IDE树全量；e2e串行；语言规格与手册同步为完成定义。
