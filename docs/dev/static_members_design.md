# 静态局部变量与静态成员设计

日期：2026-11-01
状态：已定稿（概要设计，随0.12.6实施）
修订记录：初推荐「加载期求值＋初始化表达式仅限编译期可折叠」；用户裁定改Java式懒惰初始化；随后重审「启动期按依赖序积极初始化」（Go式），论证后维持懒惰；终审期用户提出interface也应支持非折叠静态常量，核实const语义一致性后裁定三处统一开放`static const`运行时常量；防坑加固轮（实现坑调研K1-K7，零功能取消＋四项加固）新增D12静默零值消灭、K7上下文终止状态回收，递归初始化改判显式报错；跨模块轮新增D13循环import禁令＋懒惰触发序；泛型补偿轮将运行时类型参数信息（`typeName`→string）排期独立版本0.13.1并记入§1.1与D8补偿路径。

## 1 背景与目标

NLang静态面此前不完整：class静态方法完整可用，静态字段与函数内静态局部变量是语法错误，interface静态常量被限制为编译期可折叠字面量。0.12.6补齐三块语言能力（用户2026-10-31立项）：

1. **class静态字段**：跨实例共享的可变存储，任意类型、任意初始化表达式；
2. **静态局部变量**：跨调用共享、词法作用域局限于声明处的可变存储，任意初始化表达式；
3. **运行时静态常量**：`static const`非折叠初始化器在class、interface、局部三处统一——求值恰好一次后不可变。

可变静态字段与运行时常量统一采用Java式懒惰初始化：首次主动使用时恰好执行一次、线程安全。不向下兼容，合理性优先（用户2026-11-01裁定，亦为全局原则）。

### 1.1 范围边界（本轮不做）

- 模块级全局变量（类与函数之外的顶层变量）——语言现状即拒绝，维持非目标
- 泛型类静态字段（含`static const`形态）与泛型类方法体内静态局部——字典模型一份实现被全部实例化共享，状态共享违反C#/Java使用直觉，给明确诊断，待真实需求再设计按实例化存储；用户层补偿已排期独立版本0.13.1（用户裁定2026-11-01）：运行时泛型类型参数信息`typeName(类型表达式)`返回规范拼写string（需先接通0.12.3遗留的描述符携带路径：对象头部＋调用点隐藏实参），非泛型类`static Dict<string,...>`按`typeName(T)`分键实现按实例化状态（C#`typeof`＋`Dictionary<Type,...>`同款配套），模式随0.13.1写入语言规范与用户手册
- 静态构造器语法（`static {}`块）——隐藏初始化器函数由编译器生成，语法面不新增
- struct/enum静态字段——静态字段声明面为class与interface
- 按实例化的静态存储

### 2.1 关键论证：为何不取Go式启动期积极初始化

1. NLang没有包级变量，静态只能挂在类与函数上，Go「升包级＋启动期初始化」路线没有落点；
2. 静态局部变量无论如何需要「首次执行到声明处＋线程安全」守卫（从未调用的函数，其初始化器不能在启动期执行副作用）——守卫机制反正要建，类静态复用同一套是单机制；积极路线反而两套机制（启动期排序执行＋静态局部守卫）；
3. 积极路线需要编译期依赖序分析（传递、跨模块、环诊断），且初始化异常发生在`main`之前不可捕获、从未使用的类也在启动期执行副作用——对嵌入场景不友好；
4. 懒惰恰好一次已由`sync.Once`验证为成熟语义；NLang内建进语言，因为静态字段访问形式`ClassName.field`没有「导出函数替代变量」的出口。

### 2.2 NLang侧代码事实（2026-11-01实测核验）

- 静态方法编译运行全通（探针`Util.twice(21)`返回42）；静态字段与静态局部是语法错误（ClassMember字段产生式不接受NodeFlags；LocalDeclStmt只有`KT_Const`前缀分支）；
- interface`static const`＝编译期折叠字面量、无运行时存储；静态方法＝共享实现须带方法体；
- 静态与虚方法冲突规则已存在（`CheckStaticNameRules`）；
- 模块级变量被拒绝，无包级变量；
- 值表示为统一8字节值单元（标量内联低半，字符串/对象/数组/容器为堆句柄），局部与字段一律零初始化；
- `.ncu`格式版本单一来源`include/nlang/vm/CompiledModule.h`（当前v2.12）；
- 阻塞式原生调用（互斥锁、join等）已有「释放全局解释器锁并阻塞载体线程、完成时唤醒」机制；
- **const局部变量已允许任意运行时初始化表达式**（探针`const int x = side();`求值返回7）——const在局部与聚合处语义均为「初始化后不可变」，interface的「必须可折叠」是全语言唯一异类（D11动因）；
- 标准库预置包`stdlib/*.n`无任何`static const`使用，放开非折叠初始化器零迁移影响。
- import为编译期合并模型（编译a时加载b.ncu、符号并入a的产物，运行时自包含）；现有循环检查只覆盖struct引用与类继承，import依赖图无环检测——环只能靠旧镜像自举，环上的类在两个模块各存一份拷贝。

## 3 设计决策

每条含裁定、理由与被否方案。

- **D1存储表示**：每模块一张静态槽位表（static slot table，由统一8字节值单元组成的平坦数组，槽位编号编译期分配、模块内唯一），class可变静态字段、interface运行时常量、静态局部（含`static const`局部）共用；编译期折叠的常量不占槽位。垃圾回收把整张表纳入根扫描。理由：单张表＝单机制＋单根扫描面；被否：按类挂存储（静态局部仍需第二套机制）、伴生对象（引入对象语义）。
- **D2初始化语义**：Java式懒惰初始化器——任意初始化表达式，首次主动使用时恰好执行一次、线程安全。裁定过程：初推荐「加载期求值＋仅常量可折叠」（对齐跨模块默认参数先例）；用户裁定Java式；后经「启动期积极初始化」重审（§2.1四点论证）维持懒惰。
- **D3访问形式**：类内方法体裸名；类外`ClassName.field`限定；静态局部限于声明词法作用域；**实例表达式访问静态成员（`obj.staticField`）为编译错误**（用户裁定，Java先例：静态成员属于类不属于实例，且避免null实例语义争议）。
- **D4继承可见性**：静态字段沿父类链查找可见；初始化顺序父类先于子类；静态不可virtual/override（沿用既有冲突规则）。
- **D5并发语义**：初始化由状态机保证恰好一次，无初始化竞态；初始化后访问的原子性与可见性同现有共享堆字段访问；本版不新增同步语义（需要同步由用户用concurrent.n原语自行保证）。
- **D6 interface静态面**：静态方法维持共享实现；静态常量放开非折叠初始化器（运行时常量，见D11）；可变静态字段仍仅class——接口是契约，不承载可变状态。
- **D7序列化**：`.ncu`新增静态槽位表节（槽数量、类型描述符、槽位名、所属与拥有者类别）；NCU格式v2.12→v2.13，旧虚拟机拒载。
- **D8非目标**：见§1.1。
- **D9统一懒惰（可变字段）**：可变静态字段的初始化表达式一律懒惰执行（包括字面量），槽位启动时为零值——可变字段不做双轨时序（C#教训）。`static const`不在此列，按D11二分。
- **D10异常策略**：初始化器抛出→状态回退为未初始化、异常传播到使用点（可捕获）；下次使用重试。类与静态局部统一（比Java「类永久失败态」简，单一心智模型）。保持重试的裁定理由（用户2026-11-01）：重试能发生本身说明异常已被用户代码捕获、执行流在用户控制之下；已知代价（手册明示）：初始化器已执行的副作用会在重试时重复执行（C++同款语义）。
- **D11运行时静态常量**（三处统一开放）：
  - 可折叠初始化器→编译期折叠（interface现状推广到三处；不占槽、不触发初始化、恒读折叠值）；
  - 不可折叠初始化器→运行时常量：占槽位，懒惰恰好一次求值（class/interface＝首次主动使用，与D2同一状态机；局部＝首次执行到声明处），此后不可变；初始化前读为显式异常（D12，不静默）；
  - 写保护：作赋值目标或`out`实参→编译错误；
  - 动因：const语义唯一异类（§2.2）＋Java接口字段先例＋class此前无任何常量手段；只读性作用于槽位绑定本身，引用对象自身状态仍可变（同Java`final`），深层不可变组合const聚合；
  - 讨论记录：Go模型无法一等表达「对外只读静态」——反向佐证。
- **D12静默零值消灭**（防坑加固轮裁定，2026-11-01）：「静态初始化时引用未初始化的静态变量都报错，包括递归初始化」，双层实现（用户确认「编译＋运行」）：
  - 编译层：静态字段初始化表达式内直接引用同类中文本位置更晚声明的静态字段（裸名或`ClassName.field`限定名）→编译错误（Java JLS §8.3.3规则的限定名扩展）；
  - 运行层：每个**带初始化表达式**的静态槽配一个初始化位（模块槽位表配套位图；无初始化表达式的字段恒为零值，不适用）。隐藏初始化器执行到该槽赋值时置位；读静态槽时：所属类/接口已完成初始化→照常（零额外开销）；正被本上下文初始化→查该槽初始化位，未置位即抛异常（进入D10重试循环）；正被其他上下文初始化→照常阻塞等待（等完成后再读，不读半初始化）；
  - 覆盖面：经函数调用的传递引用、跨类循环初始化、递归初始化、跨模块引用全部在真实发生时精确报错——不依赖保守过程间分析，零误报；比Java更严（Java这些位置静默读零值），有意分歧（坑调研结论：窗口内读零值没有安全形态）；
  - 静态局部同规：守卫照旧管理「谁来执行初始化器」；递归重入放行执行，真正读取该槽时由初始化位检查拦截（没读该槽的递归无害放行）。
- **D13跨模块依赖**（用户提出2026-11-01，核实后裁定）：
  - 循环import编译期禁止：import依赖图必须是有向无环图；编译a时从b.ncu的import节（SymbolImport模块路径）取依赖边做深度优先环检测，不经过本模块的预存环（b↔c）同样报出，诊断给出环路径。理由：import是编译期合并模型，造环只能靠旧镜像自举，环上的类两个模块各一份拷贝——静态字段出现后是两份独立槽位表、两次独立「恰好一次」初始化，跨模块共享静默失效；先例：Go编译期拒绝包循环导入、Java模块系统（JPMS）解析期拒绝`requires`环。类级初始化环不受此禁令管辖，归D12运行期报错——模块依赖图归编译期，类级环归运行期；
  - 跨模块初始化次序＝懒惰触发序（用户确认）：a的初始化器实际引用b中类的静态时，先完成b该类初始化再读（D2触发点跨模块同一机制，依赖先于使用方天然成立）；未引用的模块不初始化、不执行副作用（拒绝「import即预初始化」——那是启动期积极初始化的后门，§2.1已否）。

## 4 语言面

- 文法：ClassMember字段产生式接受NodeFlags（复用`KT_Static`→`NF_Static`）；LocalDeclStmt新增`KT_Static`与`KT_Static KT_Const`前缀分支（固定顺序，`const static`不接受）。
- 成员契约：类字段合法组合为`static`与`static const`；裸`const`字段仍拒绝（类型级const聚合是既有机制，不与字段级混同）。
- 每个静态局部声明点对应一个独立槽位；循环体内声明首次执行到时初始化，后续迭代读已初始化值。
- 静态字段初始化表达式内直接引用同类中更晚声明的静态字段（裸名或限定名）→编译错误（D12编译层，Java「非法前向引用」的限定名扩展）；经函数调用、跨类引用等间接形态由运行层初始化位检查拦截（读到未初始化槽抛异常，D12运行层）。无初始化表达式的静态字段恒为零值，读取不受限。
- 诊断：泛型类静态字段（含const）拒绝；实例式访问拒绝；struct/enum静态字段拒绝；静态常量赋值/`out`拒绝；泛型类方法体内静态局部拒绝；循环import（直接环或预存环）编译错误并给出环路径（D13）。

## 5 运行时与字节码机制

- **触发点**（首次主动使用，Java同款）：静态字段读/写、静态方法调用（触发声明该方法的类的初始化）、`new`创建实例（触发所构造的类）；interface侧读运行时常量、调用接口静态方法触发该接口初始化（仅当该接口存在运行时常量；类实现接口不触发）。命中→先确保目标类/接口完成初始化（父类链先于子类）。跨模块同机制：`import b;`后访问b中类的静态→先完成b该类初始化再读（懒惰触发序，依赖先于使用方；未引用的模块不初始化——D13）。
- **隐藏初始化器**：编译器为「含至少一个带初始化表达式的静态槽」的类或接口生成隐藏函数（内部命名带`$staticInit`标记，不参与名称解析），按文本声明顺序求值并写入槽位。全部静态槽均无初始化表达式的类/接口不生成、不守卫。
- **状态机**（每类/接口与每静态局部槽各一套，三态：未初始化/初始化中（记录发起上下文）/已完成）：本上下文递归进入→放行执行（初始化器自身须在该状态下运行），期间读取未置位的带初始化槽→抛异常（D12运行层，递归初始化与传递引用在此显式报错）；其他上下文→阻塞等待（释放全局解释器锁，复用既有阻塞机制），等待期间不读半初始化状态；已完成→零开销放行；失败→回退未初始化并唤醒全部等待者（重试）；发起初始化的上下文中途终止（任务失败/取消）→运行时回收其全部「初始化中」状态：回退为未初始化并唤醒等待者（Java无此坑因其线程不会异步死亡，NLang上下文会）。
- **已知边界**：初始化器内派生任务并等待其完成、而任务又触发同一类初始化→相互等待死锁（Java类初始化锁同款风险），属用户可避免的编程错误，手册提示，不做检测。
- **静态局部守卫**：声明点发射守卫序列（状态迁移操作码→条件跳转→初始化表达式→写槽→完成迁移）；递归重入放行执行，真正读取该槽时由D12初始化位检查拦截（未初始化即抛异常，未读该槽的递归无害放行）。
- **字节码面**：静态槽位读写新操作码（模块内槽位编号，跨模块访问连同目标模块定位）；守卫序列是普通字节码（条件跳转＋调用隐藏初始化函数），状态迁移是少量本地操作码——虚拟机无需在操作码内重入执行NLang代码，初始化器经既有函数调用机制执行。
- **垃圾回收**：槽位表整体纳入根扫描；初始化器执行期间堆对象经帧根（既有）与已写槽位（新增）可见。

## 6 序列化与ABI

- 静态槽位表节只含元数据（初始值不序列化：可变字段统一懒惰、运行时常量懒惰求值）；隐藏初始化器函数随函数表序列化（附隐藏标记）。
- NCU v2.12→v2.13，读写原子递增。
- 调试器最小面＝模块信息列出静态槽与当前值＋类/接口初始化状态（未初始化/初始化中/已完成——排查初始化死锁与D12异常的最低工具）；断点/监视静态变量为进阶项非验收必需。

## 7 与0.12.7的衔接

槽位为统一8字节值单元，`Array<T>`统一与数组进Object不改变槽表结构；数组字面量初始化器（堆构造）与其他表达式同走懒惰初始化。

## 8 测试与验收（要点）

- e2e：跨实例共享计数器；触发点全覆盖；父类先于子类；静态局部跨调用保持、循环内只初始化一次；初始化异常传播可捕获＋重试；并发首次使用恰好一次；各类拒绝诊断；静态槽跨垃圾回收存活（`--gc-stress`）；跨模块静态（导入`.ncu`后初始化器照常懒惰执行）；interface运行时常量（触发、恰好一次、赋值与`out`拒绝、实现接口不触发）；class`static const`两形态；`static const`局部；const局部现状回归；直接前向引用编译诊断（裸名＋限定名）；读未初始化静态的运行时异常（传递引用、递归初始化、跨类循环三形态，可捕获且捕获后重试成功）；初始化发起上下文中途终止后其他上下文可正常使用该类；循环import拒绝（直接环＋预存环）；跨模块懒惰触发序（引用方初始化器依赖的类先完成初始化、未引用模块不执行副作用）。
- ctest：逐槽初始化位（带初始化器的槽才参与、置位时机）；状态机单元含发起上下文终止后的状态回收；import依赖图环检测。
