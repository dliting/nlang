# Phase 6 运行期包加载与链接设计（加载器＝nloader，链接器＝nlink）

组件命名（2026-10-01 用户裁定）：**nloader**＝运行期包加载器；**nlink**＝
符号链接器。二者是加载流水线的先后两段：nloader 把包与模块装进内存，
nlink 解析跨模块符号引用并合并运行期表。

状态：**设计稿 v2.1（2026-10-02，接手审核修订）**，取代 v1/v2 的过渡性表述。
用户裁定（2026-10-01/02）：第三方独立扩展是硬需求；热加载是未来可能项；
**不做向下兼容**；易用性与可扩展性并重；**系统性解决，不做表面补丁**。
本稿据此把 v1 中残留的「编译期合并＋stub 双重真相」过渡模型整体退役，
确立单一链接模型。v2.1 修订（接手 Task 3 时审核发现）：符号引用采用
**占位槽模型**（跨单元引用是单元表尾部的占位记录，操作数与自有引用同一
局部下标空间，无需新操作码）；nlink 保持**纯内存**（闭包装载归还 nloader）；
§9 实施顺序改为切换战役（单一全绿边界）。

## 0. 架构裁定：链接只有一个模型，发生在加载期（v2 核心修订）

v1 稿遗留的过渡模型有三个结构性纠缠（2026-10-02 对树核实的架构事实）：

1. **Phase A/B（`src/vm/backend/Import.cpp`）是伪装成编译期步骤的链接器**：
   它按限定名去重合并类型表、搬运并重映射导入函数字节码、回填方法索引
   （`PerModuleRemap`）——这套机制把库代码烤进消费方产物，是第三方包
   无法独立升级的根因，也使 `Import.cpp` 的重映射器无法成为真正的链接器。
2. **stub 双重真相**：导入类型在消费方存在两份记录（空壳 AST stub 注册的
   CompiledClass＋导入的完整 CompiledClass），靠 Phase A 按限定名去重统一；
   身份有两个来源。
3. **字节码操作数双轨**：自有函数走直接下标、导入函数经
   `m_funcIndexMap` 也落成直接下标——链接信息在编译期被抹掉，运行期
   无从重建。

**裁定**：链接只有一个模型——**加载期**。编译期只做签名解析与产码；
`Import.cpp` 的 Phase A/B 机制**整体搬迁**为 nlink 的内核（去重合并、
字节码重映射、方法索引回填正是链接器的本职，放错层的东西归位）；
stub 机制保留但只承担**签名解析**职责，不再参与运行期表构建。
操作数双轨的解法是**占位槽模型**：跨单元引用在编译期落为本单元表
尾部的占位记录（最小信息：目标模块路径＋限定名；函数槽另加名、
形参数与属主类键，见 §2），
操作数＝单元局部槽位下标，与自有引用同一下标空间——nlink 对全部
操作数统一重映射，**不引入新操作码**（执行器与 ndisasm 零改动）。

## 1. 总体架构

| 组件 | 职责 |
| --- | --- |
| ncc（编译＋打包） | 解析（合并 AST＋stub 签名，现状不变）；**逐单元产码**：每个单元输出自己的 `.ncu`（自有类型/函数/字符串常量＋符号导入槽）；项目模式打包 `.npkg`；单文件模式输出入口单元的 `.ncu`（stdlib 来自 stdlib 包，见 §6） |
| `.npkg`（包归档） | 头部（包名、格式版本、标志位、签名块描述符；程序包多入口点记录）＋成员表（模块路径 → 偏移/长度/校验和）＋若干 `.ncu` 成员 |
| nloader（加载器，nvm/ncc run 内） | 定位并加载闭包内全部单元：从入口单元的符号导入槽收集目标模块路径，在包搜索路径逐个定位 `.ncu`/`.npkg` 成员，递归装载＋校验（版本/校验和）。**纯 I/O＋发现，不做表合并** |
| nlink（链接器，nvm/ncc run 内） | **纯内存变换，零 I/O**：输入 N 份单元映像（产码直出或 nloader 装载），按限定名对等合并进运行期唯一 `CompiledModule`（Phase A/B 机制搬迁至此），把每个单元的表槽位（自有条目＋跨单元占位槽）统一重映射为全局下标；**所有未解析项一次报清** |

核心原则：**自研模块、第三方包、stdlib 走同一条加载链接路径**。
任何产物都不内嵌其它包的代码；每个包可独立升级；热加载的使能结构
（重载包＋失效引用槽）由该模型直接提供。

## 2. `.ncu` 格式 2.0（不向下兼容；2.0 未发布，布局随本设计定稿）

- 模块头：魔数 `NLANGCU\0`、版本 2.0、**模块点分路径**（Task 1 已落地）。
- 单元自有表：函数（限定键＋字节码＋tryBlocks）、类型
  （class/struct/enum/interface，限定键）、字符串常量、数组类型——
  自有条目占表下标 `0..n-1`；**跨单元占位槽从 n 起追加**（同表同构，
  最小信息记录于导入槽）；字节码操作数统一引用本单元局部槽位。
  枚举表以 `enumKeys`（与 `enumNames` 平行）携带限定键——nlink 按键
  解析枚举占位槽并跨单元去重（v2.0 定稿时补入；旧布局枚举无键，
  运行期不可名寻址）。
- **符号导入槽**（占位槽模型）：四张分表
  `functionImports/classImports/structImports/enumImports`；类型槽每条
  记录 `(目标模块路径, 目标限定名)`，函数槽每条
  `(目标模块路径, 名, 形参数 u32, 属主类限定键)`（字段序即结构体与
  序列化序）。**属主类键**
  （2026-10-02 D 裁定，取代 §4.4 旧「已知限制」）：空＝命名空间级
  函数，`名` 为限定键；非空＝该类的方法或构造器，`名` 为裸名（构造器
  ＝裸类名）。类/接口方法的**表键**保持裸名不变（运行期
  `FindMethodByName` 按裸名派发），属主键只进槽记录——nlink 借它把
  槽定址到类，再在类内按名消歧（类内无重载：仅名查找
  `FindMethodByName` 即返回唯一下标；名＝裸类名即构造器，走
  `constructorIdx`）。**枚举方法的表键例外为封装链限定键**
  （如 `lib.Color.rank`，类嵌套枚举 `lib.Outer.Inner.rank`；同日 D
  裁定）：枚举方法永不按名派发（帧内直调用函数下标），裸键无法区分
  同单元两枚举的同名方法——限定键使跨单元枚举方法导入走命名空间
  分支构造性解析。槽位与表尾部占位记录
  按序对应。闭包发现直接依据＝各导入槽的目标模块路径
  （无独立导入节）。
- `entryKey`：入口函数的限定名（空＝无入口）。**不序列化下标**——
  表布局相关的下标不可序列化，加载期按名重解析。`.npkg` 头部入口点
  记录可覆写它。

## 3. 产码（ncc）

- 解析阶段不变：项目单元＋stdlib 源内联单元合并成一个 AST（owner 标签
  决定归属），外部导入以 stub 参与签名解析——**可见性/裸池/重复检查
  语义 100% 保留**。
- 产码阶段：`GenerateCodes` 按单元循环——对每个非外部单元
  （项目 TU＋stdlib 内联 TU），以 `OwnerOf == u` 过滤合并树的成员，
  各自跑一遍 VmBackend 的注册＋产码，得到该单元的表；跨单元引用落
  占位槽：
  - 自有函数调用：直接下标（现状）；
  - 其它单元/外部 stub 的函数调用：函数表占位槽下标（去重键＝
    目标模块路径＋名＋形参数＋属主类键；命名空间级函数与枚举方法的
    名即限定键，类方法为裸名）；
  - 其它单元的类型引用（`new`/cast/字段访问/方法表）：class/struct/
    enum 表的占位槽下标；类型内部的字段下标随类型定义走（布局自包含）；
  - 字符串常量：单元自洽（各自 codegen 各自 intern），链接器无 stringMap。
- 外部导入（`.ncu`/`.npkg`）**不再合并**：stub 只供签名；Phase A/B 从
  VmBackend 删除。
- `.ncu` 序列化 `entryKey`（入口函数限定名，空＝无入口），不序列化
  下标；ncc 把「哪个单元拥有 main」写进 `.npkg` 入口记录（可覆写
  entryKey 的解析结果）。（单文件模式同样 pack：入口单元＋0 个其它
  成员时也走 `.npkg`？——**不**：单文件模式输出入口单元 `.ncu`，
  stdlib 符号引用由 nloader 从 stdlib 包解析；`.npkg` 打包仅在项目模式。）

## 4. nloader＋nlink（加载与链接流程）

1. **装入口**：`.npkg` → 入口记录选成员；`.ncu` → 直接装载。
2. **闭包加载（急切，nloader）**：对每个已装单元，取其符号导入槽的
   目标模块路径，在包搜索路径定位（`<path>.ncu` 文件，或 `.npkg` 成员——
   含本包自身成员表）→ 递归装载＋校验（版本/校验和）。stdlib 包在
   stdlib 目录（系统层）。
3. **合并（nlink 内核＝Phase A/B 搬迁）**：以限定名为键把各单元的类型/
   函数/枚举表合并进运行期唯一 `CompiledModule`；每单元建
   `PerModuleRemap`；类型描述符/方法索引/构造器下标随合并重映射。
   循环依赖天然支持（先全量装载、后统一合并）。
   合并去重规则：类型/枚举按限定键去重（跨单元同名只有各单元恒等
   注册的内建类）；函数只有纯内建桩（`intrinsicId` 非空、无字节码）
   按（名，形参数，intrinsicId）去重——用户函数永不按名去重，裸
   方法键（"add"/"toString"）跨类同名同参合法并存；字符串按内容
   驻留；数组类型在元素下标重映射后按（元素 kind，元素下标）去重。
   `defaultValues.stringIdx` 等生产者侧下标随单元映射统一换算。
4. **符号解析（急切，一次报清）**：遍历各单元的表槽位，自有条目按
   限定名、占位槽按槽记录定址——类型/枚举按（目标模块路径，限定键）
   直接查合并表（限定键全局唯一）；函数按**属主类键**两分（§2 D 裁定）：
   空键＝命名空间级函数，`名` 为限定键，定址到**目标单元的自有条目区**
   （目标单元内多重同名同参记录即拒绝，不猜）；非空键＝按限定键先解析
   属主类，再在类内消歧——`名`＝裸类名走 `constructorIdx`，否则在
   `methodIndices` 中按裸名（形参数为校验）取唯一下标（类内无重载，
   见 §2）。全部操作数统一重映射为全局下标（原地改写，宽度不变）。
   未解析项全部收集后一次诊断（缺包/缺符号/版本不符各自成行）。
5. 执行入口（`.npkg` 入口记录的模块＋`main`）。

运行期开销：链接后调用与现状完全同价（直接下标）；间接层只存在于
链接瞬间。热加载（远期）：重载包＋重跑步骤 3–4＋失效旧槽。

## 5. 与既有机制的衔接

- **native DLL**：维持首次调用懒加载；「native 限单段包」诊断随包→库
  映射确立而解除（DLL 按顶层包段命名）。
- **`_package.n` 可见性**：双重执行（编译期只对导出面做类型检查；
  nlink 合并时校验被引用符号确属导出面）。
- **确定性**：单元 `.ncu` 与 `.npkg` 均字节确定（成员/表排序）；
  `check_ncu_determinism` 扩展 `.npkg`。
- **`Import.cpp` 的归宿**：Phase A/B 核心搬入 nlink；`RemapBytecode`/
  `InstructionStride`/`RemapTypeDesc` 随迁；VmBackend 的
  `SetImportedModules`/`m_importedModules`/`m_funcIndexMap` 的 stub 条目
  全部删除。
- **stdlib 成为普通包**：CMake 新目标用 bootstrap ncc 把
  `stdlib/{io,math,fs}.n` 编成单元并打包 `stdlib.npkg`，落在构建树的
  stdlib 目录（`FindStdLibDir` 已覆盖）；nvm/ncc run 从该目录解析
  stdlib 符号引用。stdlib 源仍是权威签名面（符号索引照旧）。

## 6. 错误处理（全部在任何用户字节码执行之前；一次报清）

| 错误 | 诊断 |
| --- | --- |
| 缺包/缺单元 | 指名目标模块路径＋已搜索目录列表 |
| 格式版本不符 | 指名包/单元与两方版本号 |
| 成员校验和不符 | 指名包与模块 |
| 符号未解析 | 指名目标模块、限定名、形参数＋引用方单元 |
| 可见性违规 | 指名引用方与被引用的非导出符号 |
| 入口缺失 | 程序包无入口记录或记录的函数不存在 |
