# 泛型模型总体设计（字典模型：每模板一份实现＋运行时类型实参）

- **文档定位**：用户定义泛型（v0.12.3起）的模型选型与决策依据；预置容器、
  宿主native方法、用户声明模板三类泛型统一机制的权威参考。实施细节见各版
  概要设计与实施计划。
- **裁定原则**：用户指示（2026-10-29）——不需要向下兼容，合理性优先；机制
  尽量统一，不搞多套特殊处理；接受运行时性能损失，避免过早优化；**语言
  设计遵循最小惊异原则，避免用户记住很多特例**（泛型的用户可见规则最大
  程度与普通类/函数一致，例外仅存在于类型参数本身缺乏具体种类的场合，且
  每个例外都有可推导的语义原因）。
- **状态**：v0.12.3用户定义泛型落地中。

## 一、模型选型：字典模型，否定模板印制与两形态互斥

选型经过三个阶段，前两个被否决，理由留档：

1. **两形态互斥契约**（宿主绑定模板／编译模板，禁止混合）——**否决**。从
   使用者角度看接口不好用：含native方法的类不必所有方法都是native的
   （参考C#；C#泛型类中托管方法与运行时内实现的方法自由混存）。
2. **按实例化印制**（每实例化独立类行＋方法体克隆后逐实例化编译）——
   **否决**。三条：代码量随实例化组合膨胀；跨package消费方必须重编译模板
   代码；与既有架构逆行——勘察发现NLang的实例化节点本就共享模板裸名落在
   擦除单行（`ExprResolverGenericMint.cpp`的`MintInstanceOf`注释），方法
   分派本就按名经接收者行动态进行（`VmExecutor::FindMethodByName`），
   "印制"从未是现状。
3. **字典模型**（采纳）：每个泛型模板只生成一行类记录、方法体只编译一次，
   签名与字段中类型参数保留参数化形态；实例化在解析阶段做签名替换供类型
   检查；运行时由**实例化描述符**（类型实参拼写＋解析后种类＋嵌套递归）
   携带类型信息——泛型实例对象头部存一份、静态可知的调用点作为隐藏实参
   传一份（Go字典路线：共享代码按调用收到类型字典）。

采纳的直接理由（用户裁定）：跨package不需要链接后再编译；避免代码膨胀；
描述符提供额外的运行时类型信息（兼为将来反射的基础）。运行时性能损失
（T上操作按描述符种类分派）可接受——过早优化往往带来坏处。

**架构事实支撑**（字典模型在NLang是顺架构而非逆架构）：

- 值表示统一8字节槽（`NLANG_VALUE_SIZE 8`：标量内联低半、堆类型为句柄）
  → `T`类型字段恒为一槽、`T[]`恒为句柄，**单行布局对所有实例化成立**，
  擦除无需装箱（Java擦除被迫装箱的痛点在NLang不成立）；
- 方法按名经接收者行动态分派 → T上的成员调用零新机制；
- `.ncu`工件本就序列化类行＋函数字节码 → 跨package直接分发"一行＋一份
  字节码"，消费方免重编译。

## 二、主流方案对照（联网取证，2026-10-29）

| 语言 | 泛型策略 | 与本设计的关系 |
|------|----------|----------------|
| Go | 形状模板＋字典：共享代码，调用点传类型描述符字典 | **同构采纳**。以避免全印制代码膨胀为目标（[实现设计](https://github.com/golang/proposal/blob/master/design/generics-implementation-dictionaries-gcshape.md)、[提案](https://github.com/golang/proposal/blob/master/design/15292-generics.md)） |
| Swift | 每实例化元数据记录；泛型函数运行时收见证表；`any P`值＋双表容器 | 对象携带实例化元数据的先例；判别值形态承载variant语义（[TypeMetadata.rst](https://github.com/apple/swift/blob/main/docs/ABI/TypeMetadata.rst)） |
| C#/.NET | 运行时实例化；泛型上下文禁止P/Invoke/InternalCall | **反证**：原生入口点唯一而C无泛型概念，无描述符时只能禁止（[dotnet/runtime #46204](https://github.com/dotnet/runtime/discussions/46204)）；本设计用描述符解开该限制 |
| Rust | 单态化；泛型不能直接跨FFI导出 | 全印制的膨胀与跨语言边界问题是要避开的（[FFI讨论](https://users.rust-lang.org/t/rust-ffi-crates/20218)、[对象安全限制](https://stackoverflow.com/questions/67767207/why-are-trait-methods-with-generic-type-parameters-object-unsafe)）；其实例化名可逆编码原则被借鉴用于描述符拼写 |
| Java | 类型擦除＋装箱 | 擦除的两条痛点（装箱、运行时丢失实参）在NLang分别被统一值槽与描述符化解（[langdev选型框架](https://langdev.stackexchange.com/questions/902/how-to-choose-between-monomorphisation-and-type-erasure-for-generics)） |

## 三、关键决策记录

- **成员自由混合，规则对齐普通类（最小惊异原则）**：带方法体成员、字段、
  native方法（签名可提类型参数）三类共存，无形态二选一；契约删除"全体成
  员必须native"限制。**具体类型字段初始化器与参数默认值在泛型上照常工
  作**（普通类怎么写泛型就怎么写）；只有T本身的初值被拒绝（无约束下不存
  在有意义的T初值——T类型字段初始化器、T类型形参默认值；C#同类场景也仅
  允许`default(T)`，将来随约束机制演进）；成员名与类型参数名冲突维持拒
  绝；无体非native成员诊断。例外清单收敛为一条推导线：**T没有具体种类的
  场合**（T初值、T算术、`new T[n]`、裸T基类）。
- **实例化描述符双载体，各司其职**：**对象头部**＝对象身份——`new
    Box<int>`构造点写入，转型、instanceof与将来反射都问对象自身；
    **调用点隐藏实参**＝代码绑定——游离泛型函数与泛型类static成员没有接
    收者对象，调用点静态可知类型实参，按Go字典方式传入。泛型函数帧统一增
    加一个隐藏描述符槽（实例方法、static成员、游离函数同规），体内通用操
    作码一律读该槽——单一代码生成路径；非泛型函数帧不变。T槽传值不装箱，
    读描述符判别表示形态与种类——"类any/variant"的判别语义由此产生；
    **不引入语言级`any`/`variant`类型**（那是独立特性，判别需求在边界处
    已满足）。**语言面裁定（用户，2026-10-29）：机制不得限制语言面——
    static成员引用T与游离泛型函数都要支持**（曾拟"无接收者则拒绝static引
    用T"，被用户否决——载体必须跟上语言面，而非语言面迁就载体）。
- **游离泛型函数**：`T first(List<T> xs)`——类型参数写在声明名字后（声
    明位置无表达式歧义）；一份函数记录、体一次编译、签名参数化；调用点从
    实参静态类型推断类型实参（T直接出现、`T[]`、嵌套实例化逐层合一；仅返
    回位置出现时从赋值目标推断）。不做表达式位置的显式实参调用语法（文法
    歧义治理成本远超收益，与构造语法裁定一致）。类成员方法级自有类型参数
    非目标（方法已乘类级T）。
- **三类泛型统一**：预置容器（List/Dict/Channel/Future/Promise）已是字典
  模型形态（擦除单行＋运行时种类信息），零改动；用户模板对齐到同一模型；
  native成员（引擎实现与宿主实现）经同一注册表绑定、模板路径键、一份实现
  服务全部实例化；intrinsic（内建快速路径操作码）降级为**发射优化**——
  绑定表命中发操作码、未命中走CallNative，是逐成员优化而非独立泛型机制。
- **原生宿主接口ABI版本10**：新增`typeArgCount`/`typeArgName`回调，调用时
  携带类型实参描述符。Go/Swift为直接先例；C#的限制是反证。
- **跨package**：工件新增泛型模板表（模板行＋成员函数记录＋类型参数名表
  ＋占位符类型RTK标签），消费方直接导入链接，**不重新解析模板源、不重新
  编译**。Rust以元数据分发泛型定义是先例；早先"需源片段重解析"的方案
  （类比C++头文件分发）被否决——其对".ncu无序列化层"的前提判断有误，
  行＋字节码分发不需要AST序列化。
- **T上的操作面**：允许存取/传参/返回/字段存储、判等与toString（按描述符
  种类的通用操作码）、T绑定为类或接口时的成员调用（既有按名分派）、模板
  体内`x as T`（目标为类型参数本身，按描述符该参数位的解析后种类分派，
  与判等/toString同族）、对`List<T>`/`T[]`/`Dict<K,T>`源的foreach遍历；拒
  绝算术等需具体种类的运算符（含`+`拼接的T操作数，无约束机制时不成立）、
  方法体内`new T[n]`（数组按元素种类定型，种类编译期未知）、基类为裸T、
  null进入T类型位置（T可能是标量实例化）。类型实参限定为单槽可表示类型：
  全部12个标量基本类型、string、枚举、数组、接口（接口值为单槽对象句
  柄）、List/Dict、类；用户struct与func暂缓——两者都是多槽值类型（struct
  多槽、func三槽：目标/接收者/形态），破坏单槽布局不变量（内建容器经装
  箱可存func，差异可从"装箱存储对裸槽字段"推导）。
- **不变型＋转型描述符比对**：泛型保持不变（`Box<Derived>`不可赋
  `Box<Base>`，与主流类泛型缺省一致）；擦除单行下，`as`与向上转型到
  泛型目标须在行身份匹配后**递归比对描述符**——这是擦除模型相对印制模型
  必须显式补上的检查。比对位点清单：直接`as`与向上转型＝行身份＋递
  归描述符比对；占位符目标（模板体内`x as T`）＝按描述符种类分派（标量
  实例化下值形态必不匹配，与其他`as`失败一致抛内建`InvalidCastException`）；
  数组元素位置（如`Box<int>[]`与`Box<string>[]`）＝运行时
  数组类型按（元素种类、元素类型下标、秩）驻留后逐元素描述符比对；
  `catch`泛型实例化类型**拒绝**（异常分派按行匹配，擦除下无法区分实例
  化，编译期诊断而非运行时漏接）。
- **T槽的垃圾回收安全**：精确GC按声明种类扫描，占位符种类未知——T槽在
  字节码与`.ncu`中以新标签`RTK_TypeParam`序列化。GC共三条扫描路径，各接
  一臂：参数扫描（`MarkFrameLocals`——自K2切片5起只扫参数，具名局部已迁
  入帧带位图）、具名局部/临时槽的帧带位图（其2位种类分类在编译期由
  `EvalSlotClassOfKind`决定，`RTK_TypeParam`须映射为保守双域类别，否则落
  入默认类别即静默跳过）、类字段扫描（`MarkClassFields`）。T槽改用**保守
  双域值测试**（值既可能是字符串存储域句柄也可能是对象表句柄，两个域都
  测试、宁可多标不可漏标，沿用既有TestRootValue的双域先例）。多标只浪费
  一次标记，漏标产生悬挂指针——方向必须保守。
- **注册拓扑翻转**：现状是模板自身跳过类行登记、由首个实例化代登（行以
  裸名共享的由来）；字典模型改为**模板自身登记为行**，实例化不再触发登
  记。翻转涉及四个消费位点（行登记、方法表回填、单元生成、实例化枚举）
  与三处模板跳过判定；预置容器登记路径同步迁移，容器运行时行为零变化。
  方法调用分派管道：隐藏描述符槽为**形参区之后的首个固定槽**（帧布局
  `__this｜形参…｜描述符槽｜帧带区`，槽的帧带种类为不扫描——槽值是驻
  留表的C++指针而非VM堆值），实参个数与out参数掩码、默认参数机制都按
  形参下标编址、原样不动。填充按调用编译期的两臂分派：**按名臂**（virtual
  方法、接口类型接收者、内建调用、委托路径——运行时按名解析）由分派桥
  在帧压入后从接收者对象的头部描述符补填该槽；**直调臂**（非虚成员方法、
  构造器、游离泛型函数、泛型类static成员——编译期已知被调记录）由调用
  方把描述符常量作为形参区之后的追加装配值连续装配，帧参数拷贝的单一咽
  喉点按被调记录的泛型标志扩展一次拷贝长度（非泛型记录零变化）。native
  记录豁免帧槽——native路径直接消费实参装配区不经VM帧，泛型native成员
  的类型实参经原生宿主接口ABI装配传递。
- **实例化深度守护**：`class A<T> { A<A<T>> x; }`使签名替换无限重入铸造，
  与代码膨胀无关，是类型检查期的结构增长；铸造入口设深度上限（C++同类
  "template instantiation depth exceeds maximum"先例）。
- **泛型特性面范围裁定**（详细矩阵见各版概要设计）：模板特化拒绝（主流
  共识不做＋Rust可靠性前车之鉴）；类型参数约束非目标但保留演进口（按名
  动态分派使无约束的T成员调用可行，约束的价值是把报错提前到声明点并放开
  T算术）；型变显式裁定不变；编译期计算实参、泛型方法、泛型接口/结构体、
  变长类型参数均非目标。

## 四、v0.12.3范围

**做**：用户声明模板的成员混合（方法体/构造器体/T字段/native方法，含
static成员引用T）、游离泛型函数（声明语法＋调用点类型推断）、字典模型
落地（描述符双载体、通用判等与toString、转型比对、深度守护、T槽保守
垃圾回收扫描、模板行注册拓扑翻转）、原生宿主接口ABI版本10、跨package
模板表与免重编译链接、诊断改写、文档与版本。

**不做（非目标）**：预置容器实现改动（行为零变化）；类成员方法级自有类
型参数（非类级T）；类型参数约束；模板特化；struct与func类型实参；方法体
内`new T[n]`；表达式位置的显式泛型实参调用语法。
